## 4. わかっている宿題（`docs/06_タスクリスト.md` の各段の「残り」と同じ）

2. **満足度が上機嫌に寄っている**：上機嫌65%・ふつう33%・不満2%・限界1%。出来事はプラス年27・マイナス年2。不満・限界が少ないので事故がほとんど起きない
3. **敗北の重なり**：前線のボスで止まった時期に、依頼の期限切れ（−10×2）・スポンサー契約の未達（−12）・年末の退職金の不足（払えない1人ごとに−15、3人なら−45）が重なり、成果なしの退屈減衰（毎週−5）が続いて機嫌0（解雇）や破産になる。スポンサー契約の期限（24週）が撃破の依頼の期限と同じ週に重なりやすい

6. **⚠（危険の表示）を隠すか**はテストプレイのあとで決める（§0.102）

## 5. 計測の基準（段5のあと。同じ設定なら同じ値が出る）

`dotnet run --project tools/balance_sim -c Release -- audit 30 1440 L3 simple`（→ `tools/balance_sim/README.md`）。CSV を直したら `dotnet build tools/balance_sim -c Release` を先に（古い CSV のまま回ることがある）。

| 設定 | 結果 |
|---|---|
| `audit 30 1440 L3 simple` | 28/30・11年目〔9〜14〕（破産2） |
| 同 ＋ `randhire randtourney randcomm randequip randbuild randtrain randsquad`（全部くじ引き） | 25/30・12年目〔10〜18〕 |
| `campaign 10 1440` | 10/10・12年目〔11〜14〕 |
| `audit 30 1440 L0`（放置） | 0/30（全回解雇） |
| L3 simple ＋ `hardtrain`／`gentletrain`／`prizeshare`／`noinvest` | 25/30・11年目／29/30・12年目／27/30・11年目／23/30・12年目 |

L3 simple のほかの値：所持金1万G以上の週 38%（4年目以降 49%）、年のはじめの所持金の中央値は2年目 4,900G・4年目 3,300G（底）・7年目 14,700G、維持費 年約12,400G・手当 年約1,600G、スポンサー契約 達成480・未達130（全回の合計）。
1回足すだけでも乱数がずれて、30回の結果は ±1〜2年・敗北 ±2〜3回 揺れる。比べるときは同じ設定で対照（オプションを外した回）も流す。

## 6. 画面の確かめ方（ユーザーの実セーブを守る）

CLAUDE.md の「動作確認」の手順どおり。要点：

- 実セーブは `%APPDATA%\Godot\app_userdata\GuildManager.Godot\savegame.json`。プロジェクトをそのまま起動しない
- scratchpad に `GuildManager.Core`（bin・obj を除く）・`docs/04_バランス表`・`guild-manager.godot`（`.godot` と `addons/.godot_ai_update` を除く）を写し、`project.godot` の `config/name` を**毎回**変える
- 検証用の C# を autoload で差し込む。写しは `docs/検証レポート/2026-10-11_単調さと判断の手応え/計測の道具/VerifyShots.cs.txt`（`SHOT_DIR` の環境変数に画像を書き出す。撮影は `--headless` を付けずに窓で動かす）
- 途中のセーブで見たいときは、検証用の `config/name` のフォルダ（`%APPDATA%\Godot\app_userdata\<config/name>\`）に `savegame.json` を置くと「続きから」で読まれる
- サンドボックスへ写すとき、`main` で消したファイル（例：`scripts/CommissionPopup.cs`）が写し先に残っているとビルドが壊れる。消えたファイルは写し先からも消す
- 新しい .cs を作ったら、Godot が作る `.cs.uid` を写し先から持ち帰って一緒にコミットする

## 7. 気をつけること（このシリーズで効いたもの）

- `dotnet format` は使わない。テストとビルドの数（件数・警告）を毎回報告する
- `python3` はこの機械では何もしない（Windows Store の空のもの）。`python -` は入力待ちで止まる。ファイルの編集は Edit・Write か perl で
- 改行：作業ツリーには CRLF と LF のファイルが混ざっている（git は autocrlf で吸収する）。perl や sed で `\r\n` を足すと混ざるので、足したら CR の数（`tr -cd '\r' < f | wc -c`）と行数を比べる
- Bash で変数を使った `rm` は `"${VAR:?}/..."` の形にする（素の `rm -f "$SP/..."` は止められた）
- 新しい Core のファイル名は、既存と重ならないか先に確かめる（`AppraisalSystem.cs` を上書きしかけたことがある）
- `DungeonMissionType.Scouting` は「潜行」（名前が古い）、`Survey` が「迷宮調査」
- 物語・台詞の正本はアーティファクト「ギルド物語帳」のデータベース。`docs` の md は凍結した写し
