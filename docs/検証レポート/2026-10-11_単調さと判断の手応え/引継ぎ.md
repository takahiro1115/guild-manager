## 6. 環境の作り方（クラウドのコンテナは毎回まっさら）

- ローカル（Windows）で動かすときは CLAUDE.md の「動作確認」の手順（Godot は `D:\Godot_v4.7.2-stable_mono_win64\`、保存先は `%APPDATA%\Godot\app_userdata\<config/name>\`）。画面は `--headless` を付けずに窓で動かして撮る
- .NET：`apt-get install -y dotnet-sdk-8.0`（`builds.dotnet.microsoft.com` は通らない。apt は通る）
- Godot（Linux 版）：`https://github.com/godotengine/godot/releases/download/4.7.2-stable/Godot_v4.7.2-stable_mono_linux_x86_64.zip` を scratchpad に落として展開。画面は `xvfb-run -a -s "-screen 0 1920x1080x24"` で
- rsync は無いので `tar` のパイプで写す
- **実セーブを守る**：プロジェクトをそのまま起動しない。scratchpad に写し、`project.godot` の `config/name` を `GuildManager.Sandbox` にする（保存先 `~/.local/share/godot/app_userdata/GuildManager.Sandbox/`）

画面を撮る手順（段1・段2で使ったもの）：
1. scratchpad に `sandbox/` を作り、`GuildManager.Core`（bin・obj を除く）・`docs/04_バランス表`・`guild-manager.godot`（`.godot` と `addons/.godot_ai_update` を除く）を同じ相対配置で写す
2. `sandbox/guild-manager.godot/_verify/VerifyShots.cs` に `計測の道具/VerifyShots.cs.txt` を置き、`project.godot` の `[autoload]` に `VerifyShots="*res://_verify/VerifyShots.cs"` を足す（リポジトリには入れない）
3. 中盤のセーブを作る：`dotnet run --project tools/balance_sim -c Release -- audit 1 1440 L3 simple notutorial dump=241 dumpdir=<scratchpad>/saves/w241`（241週＝6年目のはじめ）
4. 保存先に `savegame.json` を置き、`cd sandbox/guild-manager.godot && dotnet build && "$G" --headless --import`（初回だけ）
5. `SHOT_DIR=<出力先> SHOT_SCENARIO=stage2 xvfb-run -a -s "-screen 0 1920x1080x24" "$G" --path .`（シナリオは `midgame`・`newgame`・`stage1`・`stage2`）

## 7. 守ること（CLAUDE.md より、このシリーズで特に効いたもの）

- Core を変えたらテストを足す。変えたら両方（テスト・Godot ビルド）を通し、件数と警告数を報告する
- CSV にキーを足したら CSV にも（フォールバック無し）。`dotnet format` は使わない。新しい依存は事前に提案
- 仕様を変えたら docs/03 に §0.xx の章と冒頭の改訂履歴の行（段3で §0.99 を使った。次の番号は `main` の最新と照らして決める）、バランス値なら docs/04 README、終わった・残った作業は docs/06
- セーブに項目を足したら旧セーブで既定値のまま読めるようにし、テストを足す
- ユーザーへの質問は日本語。コミットとプッシュは頼まれたときだけ（このシリーズでは段の終わりにコミット・プッシュしてきた）
