## 1. システム全体構想

- **タイトル:** 冒険者ギルドマネージャー（仮称）
- **エンジン:** Godot **4.2 以降**（C# / .NET 8）※ .NET 8 対応は 4.2 から。対象は PC（Win/Mac/Linux）。C# は Web 書き出し非対応のため Web 版は想定しない（→ 05）
- **解像度:** 論理 1920×1080 を基準。ウィンドウ拡縮は Godot の content scale で対応（→ §9・05）
- **設計方針:** モデル層（Godot 非依存の純 C# ライブラリ）とビュー層（Godot Node/UI）を完全分離。

### 1.2 時間モデル
- 1ターン ＝ 1週。1ヶ月 ＝ 4週。1年 ＝ 12ヶ月 ＝ 48週。
- **第960ターン（20年目）到達による勝敗判定は行わない（v1.10改訂で撤廃）。**
  「20年でSランク到達＝勝利」という当初案は撤回済みで、この20年という
  数字は、期限でも勝敗条件でもなく、下記「期間設計の意図」（世代交代を
  構造的に強制するための目安の年数）を説明するための**参考値**として
  残す。勝利条件そのものは引き続き未定（→ §8.2）。
- 検算：20年 × 48週 = 960ターン。✓（あくまで参考値としての検算であり、
  この週数に到達しても勝敗のいずれも発生しない）
- 期間設計の意図：初期メンバー1世代の稼働年数（稼働の中核は §3.0 の22〜34歳）では
  20年を走り切れず、必ず新人採用と世代交代が要る。「初期メンバーだけでは
  クリアできない」を加齢・強制引退（§3.7）だけで構造的に保証するための年数。

### 1.3 自動スキップ（早送り）機能（新規、v1.10改訂）

- 「次週へ進める」を毎週手動で押す代わりに、複数週を連続して自動処理
  できる機能。`AutoSkipService.AutoSkip` が `WeekProcessingSystem.ProcessWeek`
  を繰り返し呼び出す（手動の「次週へ」と全く同じ週次決算処理を経由する
  ため、挙動が食い違うことはない）。
- 自動スキップ中、受注可能クエスト一覧への操作は一切行わない（新しい
  クエストを自動受注させない）。既に派遣済みの複数週クエストは
  そのまま進行する。
- 無限ループ防止のため、1回の自動スキップで進める週数に上限
  （暫定1000週、`AutoSkipService.DefaultMaxWeeks`）を設ける。
- **以下のいずれかが発生した週で自動的に停止し、プレイヤーに操作を
  戻す**（→ `WeekResult.ShouldStopAutoSkip`）：
  1. 新春採用試験の週
  2. 満足度警告（契約交渉）が新たに発生した週
  3. 施設の建設完了
  4. 複数週クエストの帰還（結果判明）
  5. 戦死・古傷（不可逆障害）の発生
  6. 脅威度が75%・100%を**新たに**跨いだ週（既に閾値を超えた状態が
     継続しているだけでは停止しない）
  7. Aランク到達（`FinalQuestUnlocked` が新たに立った週、→ §8.2）
  8. 討伐クエストの期限切れ「1週前」の週（事前に警告して停止する）
  9. 敗北（破産・治安崩壊）の発生（指示書の8条件には無いが、自動
     スキップがゲームオーバーを検知せず素通りしてしまうのを防ぐため
     追加した第9の停止条件。`WeekResult.DefeatOccurred`）

## 2. 冒険者データモデル

### 2.1 静的・基本属性

- **ID:** GUID
- **氏名:** 文字列（新人応募者は氏名ジェネレーター(NameGenerator)で自動生成、
  → §2.4。初期メンバー4名は引き続き固定名）
- **性別（Gender）:** **女性のみ（v2.0改訂：構造的に保証）。** `Models.Gender` 列挙型は
  `Female` しか持たず、`Male` は削除済み。氏名ジェネレーターからも男性名プール・
  性別抽選そのものを撤去しており、バランス値の書き換えだけでは男性が復活しない
  （経緯・詳細は §11「確定済みの世界観連動仕様」）。氏名生成と、将来の立ち絵
  システム連携（次フェーズ、post-MVP）のための土台という位置づけは変わらない。
- **年齢:** 整数 18〜26（v2.0改訂：8年稼働モデル、→ §3）。加入は18歳固定、
  26歳の年度末で満期引退するため、現役として取りうる年齢の範囲はこの8年間のみ。
- **職業（JobClass）:** 7職業（v2.0改訂：Knight・Thief・Scholar を追加、→ growth_job_weights.csv）。
  配置（前衛/後衛）は職業から一意に決まる（→ §4.2・`PlacementRules.GetDefault`）。
  - 前衛：
    - 重戦士（**Warrior**）：耐久（VIT）・筋力（STR）特化、ヘイト集中
    - 騎士（**Knight**）：VIT特化の重装・統率、部隊の盾役（新職）
    - 斥候（**Ranger**）：俊敏（AGI）・探索（DEX）特化、不意打ち防止 ※旧 Scout をリネーム
    - 盗賊（**Thief**）：AGI特化の俊敏・器用、罠解除・隠密に長ける（新職）
  - 後衛：
    - 魔導士（**Mage**）：精神力（MND）・知力（INT）特化、範囲殲滅
    - 神官（**Cleric**）：精神力（MND）・統率（LDR）特化、致死回避・負傷軽減
    - 学者（**Scholar**）：INT特化の解析役、ボスギミックの生体解析に長ける（新職、→ §4.5）
  - 成長重み（→ BAL: growth_job_weights.csv）：全7職業で7ステータスの重み合計が
    **9に統一**されている（例：Warrior=STR3/VIT3/AGI1/DEX1/LDR1、Scholar=INT4/MND2/AGI1/DEX1/LDR1）。
    特定職だけが総合的に育ちやすい・育ちにくいという不公平が出ないようにする設計。
  - 装備制限（→ §4.2.2）：大剣・重装鎧はWarrior/Knight系、魔導士の杖・ローブは
    Mage/Scholar系、というように7職業に対応する形で拡張済み。
- **性格（Personality）:** 質実剛健 / 合理主義 / 好漢 / 慎重派（効果は §5・§3 に接続。MVP では未使用でよい）

### 2.2 能力値（実効値 1〜100）

STR / VIT / AGI / DEX / MND / LDR / INT の7種。INTは今回から個人CP・成長・
総合PAに参加する活性ステータスとなった（v1.2改訂：旧仕様の予約フィールドを
昇格）。各ステータスの役割は §4・§10 のとおり。

- **潜在能力 PA：ステータス毎に `PA_STR`, `PA_VIT`, `PA_AGI`, `PA_DEX`, `PA_MND`, `PA_LDR`,
  `PA_INT` の7値を持つ（各 1〜100）。** 実効値は対応する PA を上限に成長する。
- **総合PA** ＝ 上記7つの PA の平均（v1.2改訂：旧6値平均からINTを追加）（採用試験・
  スカウト評価など「素質の高さ」を1数値で見たい箇所で使用）。
- 生成時の関係：新人はステータス実効値 < PA。序盤は伸びしろがあり、経験（出撃・訓練）で
  実効値がPAに近づいていく。**加齢による衰微はv2.0で完全廃止**（§3）。実効値はPAへ向かって
  伸びるのみで、下がる経路は古傷（Trait、§4.3）のみになった。
- **生涯ピーク値（新規・v1.3改訂）：** ステータス毎に `PeakSTR`, `PeakVIT`, `PeakAGI`,
  `PeakDEX`, `PeakMND`, `PeakINT`, `PeakLDR` の7値を持つ。成長ロール（経路1・経路2、
  §3.1〜3.4）で実効値が上昇した時にのみ更新され、古傷（Trait）による実効値低下では
  変更されない（＝現役時代に到達した最高値を記録し続ける）。衰微処理自体がv2.0で廃止
  されたため、現在この2つ（成長ロールでの更新／古傷での非更新）が唯一の変動要因。
  引退後、顧問（教官・参謀・スカウト、§7）の効果算出の基準として使う。

### 2.3 動的・コンディション属性

- **現在HP / 最大HP：** `最大HP = VIT×2 + 50`（VIT 1〜100 → 52〜250）
- **満足度（Satisfaction）:** 0〜100。50未満でサボタージュ傾向、20未満で移籍・退団検討（§5）
  - ※ v1.0 の「Morale」を改名。戦闘中の一時的な士気（Morale）は post-MVP の別フィールドとして予約
- **負傷状態（InjurySeverity）:** なし / 軽傷（全治1〜2週・該当能力-10%）/ 重傷（全治3〜8週・出撃不可・-30%）/ 不可逆障害（完治不能・恒久低下）
- **契約週給（WeeklyWage）:** 毎週引落しの基本給（→ BAL: 経済/週給基準）

### 2.4 採用（新規：新春採用試験）
- タイミング：毎年 新年（第1週）の新春採用試験のみ。年1回。途中採用なし。
  **ただし1年目（ゲーム開始時点の第1週）は対象外。** 初期メンバーが既に配備されているため、
  最初の採用試験は2年目の新年（第49週）から（→ プレイテストで発覚。1年目に既に応募が
  来ると初期配備との整合性が悪いため）。
- 選抜：応募者数名（→ BAL: 採用/応募者数）から、宿舎の空き枠の範囲で
  プレイヤーが選ぶ。採用人数に固定上限なし（枠が許す限り複数可）。
- 契約年齢：**18歳固定**（v2.0改訂：8年稼働モデル、→ §3・`MinCandidateAge` = `MaxCandidateAge` = 18）。
  全員が加入から満期（26歳）まで、ちょうど8年間（384週）稼働できるよう年齢を統一した。
  年齢による能力差別化は無くなったため、最年少ボーナス（`YoungestAgePaBonus`）は0。
  PA自体は年齢に依存せず、通常応募者（PA 40〜80）と、一定確率（`HighPotentialBaseChance`）で
  出現する有望新人（PA 70〜100）の2段構えで生成される（→ BAL: recruitment.csv）。
- 雇用枠：現役枠は宿舎Lvに連動。宿舎Lv1で8枠、拡張で解放（§6）。
  顧問は現役枠を占有しない（§7）。
- 契約金：契約時に一時金。総合PA×年齢で変動、即戦力(高PA・年長)ほど高額（→ BAL: 採用/契約金）。
- 維持コスト：契約中は毎週の週給が継続（§2.3・§5.1）。頭数×週給が経営を圧迫し、
  宿舎・医務室・訓練場との投資競合を生む。
- 応募の質：格付けが高いほど有望新人(高PA)の応募率↑（§8.1）＋スカウト顧問+25%（§7）。
- 初期メンバー：採用システム対象外（開始時に別枠配備。将来キャラエディットで選択実装）。
- 冒険者支援室がLv0（未建設）の間も、新春採用試験自体は例年どおり
  発生する。ただしスカウト（§7.3）による応募率バフは、この施設が
  Lv1以上でスカウトが配置されている場合のみ発生する。
- 応募者の氏名は、氏名ジェネレーター（NameGenerator）により生成される。
  文化圏（洋名80%・和名20%、→ BAL: 採用/文化圏比率）をランダムに決定し、
  対応する名前プールからファーストネームを選ぶ。性別は前述のとおり女性で固定のため、
  性別の抽選自体を行わない（v2.0改訂：`RollGenderAndCulture` → `RollCulture`、→ §11）。
  現役ロースターと重複する名前は避ける（最大50回リトライ）。
  姓・二つ名の付与はpost-MVP（→ §11）。

## 3. 加齢・成長モデル（v2.0改訂：8年稼働・26歳満期引退モデル）

> **v2.0での全面改訂：** 加齢による能力低下（衰微）は完全に廃止した。冒険者は
> 「衰えない」代わりに「短い期間で必ずギルドを去る」。世界観上の根拠は
> ギルドマスター・アルベールの信念（「危険な冒険者は若く美しい全盛期のうちに
> 引退させ、十分な退職金を持たせて安全に自立させるべき」→ 01_コンセプト.md）。
> 旧モデル（15〜40歳・円熟期/限界期のフィジカル衰微・40歳強制引退）は本節の
> 改訂により丸ごと置き換わった（詳細な経緯は §11「確定済みの世界観連動仕様」）。

### 3.0 年齢帯の定義（成長ロール確率の区分として存続）

年齢帯そのもの（境界・呼称）はv1.1から変更していない。ただし**現役として
到達しうるのは成長期の一部と全盛期のみ**（後述のとおり18歳加入・26歳満期引退の
ため、円熟期・限界期に到達する前に必ず引退する）。円熟期・限界期の区分は、
成長ロール確率のテーブル（→ BAL: aging.csv `GrowthProbability_*`）としては
コード上に残っているが、通常プレイでは実質的に参照されない。

| 年齢帯 | 範囲 | 8年稼働モデルでの実際の到達年齢 | 成長ロール基礎確率 |
|---|---|---|---|
| 成長期 | 15〜21 | 18〜21歳（加入直後〜） | 0.30（→ BAL: aging.csv） |
| 全盛期 | 22〜27 | 22〜26歳（満期引退まで） | 0.12 |
| 円熟期 | 28〜34 | **到達しない**（26歳で満期引退） | 0.05（参照されない） |
| 限界期 | 35〜40 | **到達しない** | 0.02（参照されない） |

> §5.1 の出場機会ペナルティ対象年齢は **22〜27歳**のまま（実質的には22〜26歳が対象）。→ BAL: 満足度/出場機会

### 3.1〜3.4 成長の数値、および成長トリガー（新規定義。v2.0改訂：衰微は完全廃止のため節タイトルから除去）

**成長トリガーは2経路のみ。それ以外（単純待機）では実効値は変化しない。**
EXP・Lvのような中間概念は導入しない。実効値が直接、週ごとの成長ロールで増減する
（v1.1初出のレベルアップ制度は本改訂で廃止。理由は下記）。

#### 経路1：出撃による成長（実戦経験）
- その週クエストに出撃したパーティの全員が対象（成否は問わない）。
- 成長ロール確率 = 年齢帯別基礎確率（成長期は1.5倍、以降の年齢帯で逓減。
  → BAL: 加齢/成長率）× クエスト難易度による係数（→ BAL: 加齢/難易度成長係数）。
- ロール対象ステータスは、職業に応じた簡易重み付けに従って抽選する
  （前衛職はSTR/AGI/VIT寄り、魔導士はMND/INT寄り、神官はMND/LDR寄り、等。
  → BAL: 加齢/職業別成長重み。
  §4.2の列システム（前衛/後衛）は未実装のため、現時点では職業のみに基づく重み）。
- 成長ロール成功時、対象ステータスの実効値を+1〜数点で上昇させる
  （→ BAL: 加齢/成長量）。上限は対応する PA_xxx（クランプ、超過しない）。

#### 経路2：訓練施設配置による成長（座学・鍛錬）
- 出撃せず、かついずれかの訓練施設（戦士訓練所・教会・魔法研究所・斥候所）に
  配置されている冒険者が対象（出撃した週はこちらのロールは行わない＝二重成長なし）。
- 成長ロール確率 = 年齢帯別基礎確率 ×（訓練施設倍率（現状1.0倍固定）＋教官ボーナス）。
  教官（Trainer、§7.1）が配置先施設に配置されていれば、教官の対象ステータス
  生涯ピーク値に比例したボーナスが加算される（→ BAL: 顧問/教官伝授）。
- ロール対象ステータスは、配置先施設が扱うステータスに限定される（v1.3改訂。
  戦士訓練所→STR・VIT、教会→MND、魔法研究所→INT、斥候所→AGI・DEX。→ §6）。
- 成長ロール成功時の処理は経路1と同じ（+1〜数点、PA_xxxでクランプ）。実効値が
  上昇した場合、対応する生涯ピーク値（§2.2）も更新する。

##### 経路2：運用ルール確定
- 訓練枠は各施設Lv1で1名まで。Lv上昇で枠数を開放する（→ §6・BAL: 施設/訓練場）。
- 配置には毎週の利用費用が発生する（→ BAL: 訓練/週次費用）。宿舎枠のような
  「保有しているだけで無料」ではなく、都度払いのランニングコストとして
  資金処理に組み込む。
- 配置された冒険者は、成長ロール（既存記述のとおり）に加えて、
  §3.5の訓練固有HP処理（微減・回復なし・下限1）を受ける。
- 上記により「訓練場は無制限に使える安全策」ではなく、
  「1名だけ選んで・費用を払って・少しずつHPを削りながら鍛える」
  という毎週の投資判断になる。

#### 経路なし：単純待機
- 出撃もせず訓練場配置もされていない冒険者は、当該週のステータス成長ロールを
  行わない。HPの自然回復（§3.5改）のみ発生する（成長とHP回復は独立した軸）。

#### 成長打ち止めの表現
- 実効値がPA_xxxに到達したステータスはロールしても変化しない
  （自然に成長が止まる。上限到達の明示的な処理は不要、クランプのみで表現できる）。
- 年齢帯が進むほど成長ロール基礎確率は下がる設計とし、育成の主な窓は
  成長期(18〜21、8年稼働モデルでの実際の到達範囲)に集中させる（→ BAL: 加齢/年齢帯別基礎確率）。

#### 衰微処理（v2.0で完全廃止）
- **加齢によるステータス低下（衰微）は一切発生しない。** 旧モデルにあった
  「円熟期・限界期にSTR/AGI/VITを確率で恒久的に低下させる」処理（`ApplyDecline`）と、
  対応するバランス値（`MatureDecline*` / `LimitDecline*`）はコードごと削除済み。
- 実効値が下がる経路は、本モデルでは古傷（Trait、§4.3）のみになった。
- 育成不足は意図的に残す：8年（384週）という短い1世代の稼働期間では、
  実効値をPAまで伸ばし切れない（＝一代では「強すぎるキャラ」を作れない）成長速度に
  BAL: aging.csv の成長率を設定している。
- 世代間増幅で埋める：不足分は 教官伝授(§7)＋訓練場(§6)＋格付け上昇に伴う高PA新人の
  流入(§8.1)で世代をまたいで埋める。成長率(絞る)と伝授効果(伸ばす)は常に一対で
  釣り合わせる＝本作の中心的バランス方程式（この設計方針自体はv1.1から変更なし。
  「20年でSランク到達」という当初の勝敗条件は§1.2のとおり既に撤廃済みのため、
  「間に合わせるべき期限」としての20年という数字はもう存在しない。8年ごとに
  世代交代が必ず起きる、という**構造**だけが目的である）。

### 3.5 静養・HP自然回復（疲労Fatigueを廃止し、回復をHPに一本化）
- 疲労度（Fatigue）パラメータは廃止。持久・消耗の軸はHP（VIT由来）に統合する。
- 出撃した週：戦闘結果に応じて CurrentHP が減少（§4.2 表）。
- 非出撃（待機・静養）の週：CurrentHP を一定量回復（→ BAL: 静養/待機回復）。上限は MaxHP。
- 施設補正：宿舎・医務室 Lv により回復量に倍率（→ §6）。
- 対象範囲：本処理は重傷以外（無傷・軽傷）のHP回復を担う。重傷は §3.6 が別管理
  （InjuryWeeksRemaining をカウントし、全治時に HP を満タン復帰）。
- 「過労」フラグは廃止。連続出撃の抑制は、低HP→個人CP低下（§4.2）による
  戦闘結果の悪化で軟らかく働く（ハードな出撃不可ゲートは重傷のみ）。

### 3.5 静養・HP自然回復（つづき：訓練場配置の扱い）

- 訓練場に配置され、かつ出撃していない週は、§3.5前段のHP自然回復を**適用しない**。
  代わりに以下の訓練固有のHP処理を行う：
  - CurrentHP を一定量減少させる（→ BAL: 訓練/HP消費）。
  - ただし CurrentHP は 1 未満にはならない（下限クランプ）。
  - この減少は負傷（InjurySeverity）を発生させず、致死・不可逆障害の判定
    （§4.3）には一切接続しない。訓練は「回復しない・地味に削れる」だけの
    低リスクな経路として扱う。
- 出撃も訓練場配置もしていない（単純待機の）週のみ、前段のHP自然回復が適用される。
- 3つの状態（出撃／訓練場配置／単純待機）は互いに排他。同じ週に重複しない。

### 3.6 負傷回復処理（v1.1で欠落判明・新規追加）

**発覚の経緯:** Phase 2 のMVPを実際にプレイしたところ、重傷になった冒険者が一度も回復せず、詰み状態のまま出撃させ続けられることが判明した。§2.3で負傷の全治週数（軽傷1〜2週／重傷3〜8週）をデータとして定義していたにもかかわらず、それを消化して治す処理がv1.0・v1.1のどちらにも存在していなかった。

- 負傷した週に、その負傷の全治週数を `InjuryWeeksRemaining` としてランダムに決定し保持する（軽傷1〜2週、重傷3〜8週の範囲で）。
- 毎週の決算処理で、負傷している全冒険者の `InjuryWeeksRemaining` を1減らす。
- 0に達したら `Injury = None` に戻し、`CurrentHP = MaxHP` として全快させる。
- **出撃制限:** `Injury == Severe` の間は編成画面で選択できないようにする（MVPのUIには未実装だったため、Phase 2の修正で追加）。
- 不可逆障害（Permanent）はこの処理の対象外（そもそも完治しない。仕様書 §2.3・§4.3参照）。

### 3.7 満期引退（v2.0改訂：26歳・8年稼働モデル）

- **26歳になった年度末（第48週決算）に満期引退**（`RetirementAge` = 26、
  `AgingSystem.ProcessWeeklyAging`）。18歳で加入した場合、年度末を8回迎えて
  26歳になるため、稼働期間はちょうど8年＝384週（`MaxActiveWeeks`）になる。
  この計算が成立する順序が重要：**先に加齢し、その結果が満期年齢に達していれば
  引退**という順序で処理する（逆にすると9年稼働になってしまう）。
- 加入から満期までの週数は `Adventurer.ActiveWeeks` に毎週記録される
  （UI表示・退職金の算定根拠に使う想定）。
- **早期引退（`AgingSystem.RetireVoluntarily`）：** プレイヤーは満期を待たず、
  任意のタイミングで現役冒険者を早期引退させ、顧問候補にすることもできる
  （→ MainDashboardの「引退させる」ボタン）。退職金支給等の処理は満期引退と共通。
- **退職金＝週給×12週（`SeveranceWeeks`）＋累積功績（`TotalContributionScore`）×
  係数（`SeveranceContributionCoefficient`）。** 危険な任務を多く引き受けた
  冒険者ほど手厚く送り出される。累積功績はクエスト解決のたびに
  `QuestDispatchSystem` が難易度に応じて加算する（達成時はさらに倍加）。
- 退職金を払いきれない場合も引退自体は成立させる（冒険者を人質に取らない）が、
  「約束した退職金を用意できないギルド」として名声が下がる
  （`SeveranceShortfallReputationPenalty`）。
- 引退した冒険者は現役ロースターから除外され、`RetiredAdventurers`（引退済み・
  顧問候補一覧）へ移る。§7の顧問制度（教官・参謀・スカウト）は既に本実装済みで、
  ここに保持された冒険者から任命できる（旧v1.1時点の「顧問制度は未実装のため
  効果を付与しない」という制約は解消済み）。
- 「引退勧告（肩たたき）」の受諾判定は任意項目のまま未実装（→ §11）。8年稼働
  モデルでは満期が明確な区切りとして機能するため、優先度は当初より下がっている。

## 4. クエスト・遠征解決エンジン

「次週へ」実行時、派遣中の各パーティに対して以下の順で解決する。

### 4.0 クエストの定義（スケール確定）

各クエストは以下を持つ。**難易度・索敵要求・報酬はランクに紐づく**（→ BAL: クエスト）。

- **ランク:** E / D / C / B / A / S（ギルド格付けと同じ体系）
- **QuestDifficulty:** 1〜100 の整数（ランク帯ごとの範囲は → BAL: クエスト/難易度レンジ）
- **QuestScoutRequirement:** 1〜100（DEX と同スケール。→ BAL: クエスト/索敵要求）
- **探索規模（Scale）:** 難易度とは独立した属性。クエストの拘束期間（週数）を
  決める（→ BAL: クエスト/探索規模。例：小=1週、中=2〜3週、大=4週以上）。
  同じ難易度でも、探索規模によって「短期決戦」と「長期の調査任務」の
  バリエーションが生まれる。
- **報酬（ゴールド）／期限（週）／放置危険度**
- **QuestType（新規）:** 討伐（Subjugation）／調査・探索（Exploration）／
  護衛（Escort）の3区分。脅威度（§4.4）への影響は討伐のみが対象。
  調査・探索・護衛の固有ギミックは今後実装（post-MVP、→ §11）。
- **期限（DeadlineWeeks、v1.10改訂）:** 暫定 **5〜8週程度**に延長
  （→ BAL: クエスト）。
- **長期遠征クエストの解禁条件（新規、v1.10改訂）:** 現役ロースター
  （現在の冒険者数、引退・戦死を除く）が **6名未満**の間、探索規模
  （Scale）が**中・大**のクエストは受注可能リストに生成・補充されない。
  6名以上になって初めて出現し始める。探索規模が**小**のクエストは、
  人数に関わらず常に出現する。

### 4.0.1 複数週クエストの解決タイミング（新規定義）

- 拘束期間が2週以上のクエストは、派遣した週から拘束期間が満了する週まで
  「派遣中」状態になる。索敵〜治安の解決（§4.1〜4.4）は**満了週にまとめて
  1回だけ**行う。
- 派遣中は何も起きない：HP自然回復（§3.5）・訓練場配置による成長
  （§3.1〜3.4経路2）は適用されない。成長ロール（経路1・出撃による成長）は
  満了週の解決時に1回だけ発生させる。
- 週給は派遣中も毎週通常どおり発生する。
- 派遣中のパーティ・メンバーは、他クエストへの再編成・訓練場への配置が
  できない（拘束される）。
- 一度派遣したパーティを、拘束期間の途中で呼び戻す（中断する）ことは
  できない。結果が出るまで待つ以外の選択肢は無い。

## 4.0.2 パーティー編成（永続化、新規）

- パーティーは編成時に保存される永続的な単位になった（クエストごとに
  毎回4人を選び直す必要はない）。名前を付けられる。
- 1人は同時に1つのパーティーにしか所属できない。
- どのパーティーにも属さない冒険者は「未編成」として扱われる。
- 前衛/後衛の配置（§4.2、Placement）は既存どおり冒険者個人に紐づく
  永続状態のまま。**プレイヤーによる配置の選択操作は廃止した
  （v1.10再改訂）**：パーティー編成画面にあった配置切り替えボタンを削除し、
  配置は職業から自動決定された初期値（§4.2）のまま固定で運用する。内部の
  個人CP計算・不意打ち時の被弾ウェイト差は従来どおり配置に応じて機能し
  続けるが、プレイヤーには前衛/後衛の表示自体を行わない（→ 情報公開の
  原則、§4.2.3）。
- 派遣時、編成メンバーのうち出撃可能（重傷でない・他クエスト派遣中で
  ない・訓練所配置中でない）な者だけで自動的に出撃する。出撃可能な
  人数が0人の場合のみ派遣不可とする。
- 派遣直前に、その場限りの一時的な入れ替え（保存されている編成自体は
  変更しない）ができる。
- 編成画面で、メンバー間の相性（→ §5.3.1）を確認できる。相性30未満
  （険悪）のペアがいる場合は警告表示するが、編成自体は妨げない
  （険悪なペアを含めて編成することも可能）。

### 4.1 フェーズ1：索敵・遭遇判定

```
PartyScout = max(DEX) + 平均DEX×0.3 + 隊長LDR×0.2
ΔS = PartyScout − QuestScoutRequirement
Roll = Random(1,100)
```

- `Roll ≤ clamp(15+ΔS, 1, 99)` → 奇襲成功：パーティ戦闘力 +30%
- 上記超〜`clamp(80+ΔS, 1, 99)` → 通常交戦：補正なし
- それ超 → 不意打ち：敵戦力 +30%、後衛の被弾ウェイト上昇（§4.3）

> v1.1 で **境界を 1〜99 にクランプ**（ΔS が極端でも帯が消えない・逆転しないように）。

### 4.2 前衛/後衛の列システム（新規定義）

- 各冒険者は「配置（Placement）」＝前衛/後衛の属性を持つ。これはパーティの
  スロットではなく冒険者自身に紐づく永続的な状態で、クエストをまたいで
  保持される。
- 配置は職業から自動決定される（§2.1の適性表に基づく、v2.0改訂：7職業分に拡張）：
  - 前衛：重戦士（Warrior）・騎士（Knight）・斥候（Ranger）・盗賊（Thief）
  - 後衛：魔導士（Mage）・神官（Cleric）・学者（Scholar）
- 配置補正（個人CP計算式の「職業配置補正(職業, 配置)」）も7職業分を定義済み
  （→ BAL: combat.csv `PlacementCorrection_*`）。新3職も既存職と同じ考え方：
  騎士＝前衛1.2倍/後衛0.8倍（重戦士と同型）、学者＝前衛0.8倍/後衛1.2倍（魔導士と
  同型）、盗賊＝前衛/後衛とも1.0倍（斥候と同型）。同じ役割の職業間に戦闘格差が
  出ないようにしている。
- **プレイヤーによる配置の選択操作は廃止した（v1.10再改訂）。** 以前は
  パーティー編成画面に配置切り替えボタンがあったが、「現状は職業でほぼ
  配置が固定され、選択の幅を生んでいない」という判断（→ §11）から削除した。
  UI上に前衛/後衛の表示自体も行わない（→ 情報公開の原則、§4.2.3）。
  個人CP計算・不意打ち時の被弾ウェイト差といった内部の配置補正ロジックは
  自動決定された配置のまま従来どおり機能し続ける。将来、特性やクエスト
  種別と絡めた再設計を行う際に選択操作を復活させる可能性がある（→ §11）。
- 役割から外れた配置（例：魔導士を前衛に置く）は、個人CP計算式の職業配置補正で
  ペナルティが掛かる（→ BAL: 戦闘/配置補正）。ただし配置が職業で自動固定される
  ため、現状この分岐が実際に発生することはない。
- 個人CP計算式（既存）の「職業配置補正(職業, 配置)」は、この配置属性を
  参照する（→ BAL: 戦闘/配置補正）。

### 4.2 フェーズ2：戦闘比率と個別ダウン判定

**個人CP（v1.0 で未定義 → 新規定義）:**

```
個人CP = ( STR×wSTR + AGI×wAGI + VIT×wVIT + DEX×wDEX + MND×wMND
           + INT×wINT + LDR×wLDR )
         × 職業配置補正(職業, 配置)
         × (現在HP / 最大HP)
```

- v1.2改訂：DEXは索敵フェーズ専任の役割に加え、個人CPにも参加する（二重役割）。
  INTも今回から個人CPに参加する（旧仕様では未接続の予約フィールドだったが、
  成長ステータスとして活性化）。
- 重み `wXXX` は → BAL: 戦闘/CP重み。DEX・INTの重みは新規に定義する
  （既存の他ステータスの重みバランスを崩さない範囲で暫定値を置く）。

```
PartyCP = Σ個人CP × 索敵補正
EnemyCP = QuestDifficulty × 3.0        （→ BAL: 戦闘/敵CP係数）
Ratio   = PartyCP / EnemyCP
```

※ HPの影響は個人CPの ×(現在HP/最大HP) で保持。疲労項は廃止。

**勝敗と基本損耗（HP消費%）:**

| 結果 | 条件 | 任務 | HP消費 | 個別ダウン判定 |
|---|---|---|---|---|
| 完全勝利 | Ratio ≥ 1.8 | 達成 | 5〜15% | 無し |
| 辛勝 | 1.0 ≤ Ratio < 1.8 | 達成 | 20〜45% | 無し |
| 苦戦敗退 | 0.6 ≤ Ratio < 1.0 | 失敗 | 40〜70% | 各員が確率でダウン → §4.3 |
| 戦線崩壊 | Ratio < 0.6 | 壊滅 | — | 各員が高確率でダウン → §4.3 |

- 損耗の方針：campaign長期化(20年)に伴い HP消費%(上表) は重めに置き、
  静養→ローテーションを頻発させてテンポを作る。重くするのは主に勝利行
  (完全勝利・辛勝)であり、敗北率そのものは上げない——ロストの希少さは
  「敗北時のみダウン判定」で担保する既存方針(§4.3)を維持（→ BAL: 戦闘/HP消費）。
- 被弾配分：不意打ち発生時（§4.1）のみ、後衛メンバーのHP消費%を前衛より
  重く適用する（→ BAL: 戦闘/被弾ウェイト）。奇襲成功・通常交戦では
  前衛/後衛による差はつけない。

**個別ダウン判定（v1.0 の「HP≤0 経路」欠落を解消）:**

- 損耗%を各員の現在HPに適用したうえで、苦戦敗退・戦線崩壊では各員が「ダウン」ロールを行う。ダウン確率は結果ランクで変わる（→ BAL: 戦闘/ダウン確率）。
- **AGI が高い者はダウン確率が下がる**（＝逃走成功の表現。v1.0 の「AGI 逃走成功率」をここで接続）。
- ダウンした者だけがフェーズ3（致死判定）へ進む。ダウンしなければ重傷止まり。

### 4.2.3 クエスト種別ごとの統一点数計算式（新規、項目63）

討伐・探索・護衛は、以下の共通式の「対象ステータス・重み」違いとして統一する。

```
点数 = Σ(各メンバーの対象ステータス合計 × HP比率) + 装備ボーナス（討伐のみ） × 配置補正（討伐のみ）
要求値 = クエストDifficulty × 種別ごとの要求係数（→ BAL: クエスト/種別要求係数）
Ratio  = 点数 ÷ 要求値
```

対象ステータス・重みは → BAL: クエスト/種別スコアリング（種別ごとのテーブル）。

**討伐**：既存の個人CP・Ratio区分（完全勝利/辛勝/苦戦敗退/戦線崩壊）・致死判定・
古傷・戦死のフローを完全に維持する（変更なし）。

**探索・護衛**：3区分（大成功/成功/失敗）。致死判定・古傷・戦死は発生しない。
HP消費は軽量（→ BAL: クエスト/軽量HP消費）。大成功・成功は達成、失敗は未達成として扱う。

索敵フェーズの隊長LDR補正は討伐のみ適用する（探索・護衛は点数式側でLDRを
直接評価するため、二重評価を避けて適用しない）。

旧・クエスト適性ボーナス（1.0〜1.3倍のCP補正倍率）は本項目により廃止した。

**個人特性ボーナス・ペア特性シナジー（項目64で追加）：**

点数計算式に、以下を加算項として追加する：

- 個人特性ボーナス：特性ごとに対応するクエスト種別のスコアへ加算（例：
  「田舎育ち」は探索クエストのスコアに加算）
- ペア特性シナジー：パーティ内の異なる2名が特定の特性の組み合わせを
  満たす場合、符号付きでパーティ全体のスコアに加算（→ BAL: 特性/ペアシナジー）。
  同じ組み合わせが複数ペア成立する場合は合算する。1名が両方の特性を
  兼ねる場合はペアとして成立しない。
  合計がマイナスの場合のみ、隊長のLDRに応じて絶対値を圧縮する
  （プラスの合計には影響しない）。

**ランダムイベント（項目65で追加）：**

探索・護衛クエストの解決時、低確率で以下のイベントが発生しうる。プレイヤーには
選択肢を見せず、能力値・特性の組み合わせによる内部判定の結果のみが週報に
報告される（→ 情報公開の原則）。

- **強敵との遭遇**（探索・護衛のみ）：押し切り／退避／苦戦の3値判定。押し切り・
  苦戦時は、既存の討伐フロー（辛勝・苦戦敗退相当のHP消費・致死判定）を
  その場で流用する。
- **宝物庫の発見**（探索のみ）：DEX/INT中心の判定で追加報酬の大小・罠を判定する。
- **深追い**（探索・護衛）：VIT/MND中心の判定で、粘った場合の追加報酬と
  引き換えのHP消費を判定する。

いずれも仮値（→ BAL: クエストイベント）。

**週報表示（項目66で対応）：** 索敵結果・判定区分は日本語ラベルで表示する。
ランダムイベントは、発生した場合のみ結果を文章で報告する（内部の判定スコア・
閾値は表示しない）。これにより「情報公開の原則」（結果は全て報告するが、
数値そのものは隠す）を実現する。

情報公開の原則の適用範囲（項目67で追加徹底）：週報のRatio数値、クエスト一覧の
ランク・難易度数値、パーティー編成画面の相性数値は表示しない。能力値そのもの
（実効値・PA・総合PA）は判定数値ではなく能力値として扱い、表示を継続する。

### 4.3 フェーズ3：負傷・致死判定（低確率ロスト仕様）

ダウンした冒険者に対して判定する。

```
SurvivalThreshold = clamp( VIT + 神官MND×0.4 + 隊長LDR×0.2 , 5 , 90 )   ← v1.1 でクランプ追加
PermanentBand     = 20   （→ BAL: 戦闘/不可逆帯幅。調整可）
Roll = Random(1,100)
```

- `Roll ≤ SurvivalThreshold` → **生存**：HP1で踏みとどまり重傷（全治3〜6週）
- `SurvivalThreshold < Roll ≤ SurvivalThreshold + PermanentBand` → **不可逆障害**：永続デバフ（詳細は下記つづき参照。v1.2改訂：システムとして引退・顧問化を強制するものではない）
- `Roll > SurvivalThreshold + PermanentBand` → **強制除籍（恒久ロスト）**：現役ロースターから
  完全に除外される（詳細・世界観上の表現は §4.3.1）

> **修正の要点:** (1) 閾値を最大90にクランプしたので、どんなに硬い前衛でもロストは 0% にならない。(2) 範囲方式に一本化し、v1.0 の「70%/30%の割り当て」注記は廃止（範囲と矛盾していたため）。ロストの希少さは「フェーズ2でそもそもダウンしにくい」ことで担保する設計に変更。

### 4.3 フェーズ3：負傷・致死判定（つづき：不可逆障害＝「古傷」の実装詳細）

- 不可逆障害は、汎用の特性(Trait)エンジン上の「古傷」特性として実装する
  （→ §5.3 特性システムの最初の実装例）。付与されるとMND・INT・LDR以外
  （STR/VIT/AGI/DEX）を割合で恒久的に低下させる（→ BAL: 戦闘/古傷減少率）。
- 出撃制限は課さない。古傷を負った冒険者も現役を続けられる
  （弱くなった熟練者が現役に居続けることで、プレイヤーに新人育成の
  必要性を早期に意識させる設計）。
- 特性は同じ種類を重複して持てない。既に「古傷」特性を持つ冒険者が
  再び不可逆障害の判定域に入った場合は、新たな古傷を付与せず、
  代わりに「生存（重傷）」として扱う（致死判定の結果を1段階軽く丸める）。
  将来、部位の異なる古傷（別の特性ID）が追加されれば、この丸め処理は
  解消される（→ §11）。
- **強制除籍（恒久ロスト）**：キャラクターは完全にロストする。記録として
  「〇週目に強制除籍」を保持し、ロースターから除外する（詳細・表現は §4.3.1）。

### 4.3.1 強制除籍の記録（v2.0改訂：「戦死」表現の撤廃）

> **世界観上の扱い（→ 01_コンセプト.md）：** 本作の冒険者は「戦死」しない。
> HPが0に達しても、アルベールの秘薬によって必ず一命は取り留める。ただし、
> 危険な目に遭わせたことに激怒したマスターがギルド登録を即座に強制抹消するため、
> 二度と戻らない。**システム上の扱いは恒久的なロストであり、以前の「戦死」と
> 何一つ変わらない。** 変更したのはプレイヤーへの提示文言のみ（内部の識別子
> `FallenAdventurers` 等はセーブデータ互換のため据え置き）。この表現は、通常
> クエスト（`QuestResolver`）と大迷宮の階層ボス（`DungeonResolver`、§4.5）の
> 両方で統一している。

- 強制除籍となった冒険者は、氏名・除籍された週番号・除籍時の年齢・職業を
  記録として保持する（内部呼称は据え置きで `FallenAdventurers`、顧問候補の
  引退済み一覧とは別枠）。
- 現役ロースター・パーティ編成・訓練場配置からは完全に除外する。
- §5.1「仲間ロストの余波（-30、同パーティ全員の満足度）」は、
  この強制除籍の判定と同時に実行する。

### 4.4 フェーズ4：治安連動処理

- **対象は討伐（Subjugation）クエストのみ。** 調査・探索、護衛は
  脅威度に影響しない。
- 討伐クエストが以下のいずれかに該当すると、街の**脅威度 +2〜5%**
  （→ BAL: 治安）：
  - 受注されないまま期限切れになった（放置）
  - 受注はしたが苦戦敗退・戦線崩壊で失敗した（§4.2の任務=失敗/壊滅）

  市場システム未実装のため今回は扱わない。post-MVP、→ §11）。
- **地域モデル:** MVP は単一の街（脅威度1値）。複数地域は post-MVP。

## 4.5 大迷宮（ダンジョン攻略システム、v2.0新規・5フィールド拡張／3大任務）

通常クエスト（§4.0〜§4.4）とは別枠の攻略対象。「調査任務で階層を進み、情報を集める →
判明したギミックへ対策を組んだ編成で討伐する」という2段構えを軸に、随時出撃できる
第3の任務「探索（採取）」（§4.5.5）が並走する。**無調査での突撃は未対策ペナルティに
より壊滅する**設計（→ §4.5.4）。

同時出撃枠（`GameState.UnlockedSquadSlots`）は通常クエストの派遣と共有する
（`QuestDispatchSystem.CanDispatch` が両方の出撃数を合算して判定）。出撃操作
自体は即座に解決せず、次の週次決算でまとめて解決する（通常クエストと同じ流れ）。

### 4.5.1 5フィールド構造と開放条件（`DungeonField`）

- 大迷宮は単一のダンジョンではなく、**全5フィールド**で構成される
  （→ BAL: 構造値のためCSV化せず`Data.SampleData.CreateDefaultFields`にハードコード。
  §10.1の方針どおり）：

  | 攻略順（Order） | フィールドId | 名称 |
  |---|---|---|
  | 1 | forest | 翠緑の原生林 |
  | 2 | cave | 嘆きの鍾乳洞 |
  | 3 | ruins | 忘却の古代廃墟 |
  | 4 | canyon | 焦熱の峡谷 |
  | 5 | abyss | 深淵の特異点 |

- 各フィールドは**100階層**（`DungeonField.MaxFloor`）を持ち、**5階ごと**
  （`DungeonField.BossInterval`）に階層ボスを配置する（5・10・…・100Fの
  **計20体**）。ボスのギミック種別は4種を周期的に循環させ、階層が深く・
  フィールドの攻略順が進むほどHP・危険度・報酬が滑らかに増える。
- **開放条件：** 初期状態で開放済みなのは第1フィールド（森）のみ。
  - フィールドOrder 1〜3（森・洞窟・廃墟）は、そのフィールドの**10Fボス撃破**で
    次順（Order+1）のフィールドが開放される（森10F撃破→洞窟、洞窟10F→廃墟、
    廃墟10F→峡谷）。
  - 第5フィールド（深淵）だけは通常の10F連鎖では開放されない。**Order 1〜4
    （森・洞窟・廃墟・峡谷）の全フィールドで20Fボスが撃破済み**になった時点で
    開放される（`DungeonExpeditionSystem.ApplyFieldProgression`）。
  - 最終フィールド（深淵）の100Fボス撃破は、通常クエストのAランク到達
    （§8.2）と同じ `FinalQuestUnlocked` フラグを共有して立てる（＝終盤
    コンテンツ解禁の合図として扱う）。
- 各フィールドは**最高到達階層**（`ReachedFloor`）を持ち、ボス撃破のたびに
  `max(現在値, 撃破階層+1)` で更新される（§4.5.3の道中進軍の起点にもなる）。
- 攻略対象は各フィールドごとに「未撃破のうち最も浅い階層のボス」
  （`DungeonField.GetNextActiveBoss`）。全ボス撃破済みのフィールドは制覇済み
  （攻略対象なし。探索（採取）は制覇後も継続可能、→ §4.5.5）。

### 4.5.2 階層ボスと情報解析率（IntelTier）

- 各ボスは階層（`Floor`）・最大HP・複数の**ギミック**（`BossGimmick`、後述）を持つ。
- 各ボスは**情報解析率**（`IntelRate`、0.0〜1.0）を持ち、調査任務（§4.5.3）の成果で
  上昇する。解析率に応じて段階的に情報が開示される（`IntelTier`、→ BAL: scouting.csv）：

  | 解析率 | 段階（IntelTier） | 開示される情報 |
  |---|---|---|
  | 〜25%未満 | 未調査（Unknown） | 名前と階層のみ。ボス概要は「？？？」 |
  | 25%〜 | 基本情報（Basic） | 最大HPなど、おおよその規模が判明 |
  | 50%〜 | 危険情報（Hazards） | どのギミック（猛毒・重装甲など）を持つかが判明 |
  | 75%〜 | 対策情報（Countermeasures） | 各ギミックへの対策ロール・必要アイテムが判明 |
  | 100% | 完全解析（Complete） | 弱点看破。討伐時の与ダメージに+20%ボーナス（→ BAL: dungeon.csv `FullIntelDamageBonus`） |

- 情報公開の原則（§4.2.3）に従い、判定用の内部数値（要求値・Ratio・閾値）は
  UIに一切表示しない。開示されるのは「何が起きるか」という定性的な事実のみ。

### 4.5.3 調査任務（Scouting）：道中進軍と隠密・解析の2分岐

低リスク経路として設計する。**HP下限1で止まり、致死判定には一切接続しない**
（探索・護衛クエストと同じ考え方。調査で人を失うと「調べてから挑む」という
本システムの導線自体が破綻するため）。解決時の状況で以下の2分岐がある：

**分岐A：走破力による道中進軍（`DungeonTraversalResolver`、v2.0内追加）**

- 現在の最高到達階層（`DungeonField.ReachedFloor`）が次の未撃破ボスより浅い場合に
  発生する。一度倒したボス階層は素通りできる（＝再度足止めにならない）。
- **走破力** ＝ Σ(AGI+DEX)×係数 ＋ 部隊長LDR×係数（＋研究「軽装の踏破術」ボーナス、
  → §4.6）vs 現在到達階層×係数（→ BAL: dungeon_traversal.csv）。
- Ratioに応じて4区分（電撃／迅速／通常／苦戦）に分類し、区分ごとに定められた
  階層数だけ一気に進軍する。**走破力が不足していても必ず1階層は進む**
  （完全な足止めにはしない設計）。
- **ストッパー：** 次の未撃破ボス階層を超えて進むことはない。進軍先が
  ボス階層に達した（または超えた）場合はボス階層で止まる
  （`TraversalResult.StopperTriggered`）。
- HP消費は区分ごとに軽重が付く（電撃が最も軽く、苦戦が最も重い）。

**分岐B：隠密・解析（`ScoutingResolver`、既存）**

現在到達階層が既にボス階層に達している場合に発生する。判定は2つ：

1. **隠密・生還：** Σ(AGI+DEX)×係数 ＋ 部隊長LDR×係数 vs 階層×要求値
   （→ BAL: scouting.csv）。失敗すると見つかり、HP消費が重くなり（10〜25%、
   成功時は0〜8%）、解析の成果も1段階下がる（大成功→成功→失敗）。
2. **解析・情報収集：** Σ(INT)×係数 vs 階層×要求値（＋研究「秘薬の斥候試薬」
   ボーナス、→ §4.6）。Ratioに応じて大成功／成功／失敗の3区分（閾値は探索・
   護衛と同じ1.5倍/1.0倍、§4.2.3）。解析率の上昇量は大成功0.50・成功0.25・
   失敗でも断片情報として0.10（調査が完全な無駄骨にはならないようにする）。

- 解析率100%（完全解析済み）のボスへの調査は、UI側で出撃ボタンを無効化する
  （それ以上解析率が上がらず、部隊のHPと1週を消費するだけのため）。

### 4.5.4 階層ボス討伐（Dungeon Expedition）

直接指揮UIは作らない。編成と（対策次第で）携行品を決めて送り出せば、あとは
完全自動で判定し構造化された結果を返す（既存の`QuestResolver`と同じ方針）。

勝敗を分けるのは「事前にどれだけ調べ、どれだけ対策を積んだか」：

- **ボスのギミック（`BossGimmickType`）：** 猛毒（Poison）・重装甲（HeavyArmor）・
  飛行（Flying）・即死級攻撃（InstantKill）の4種。§4.2.3の環境ギミック
  （`EnvironmentTag`。クエストの「場」に付く属性で、対策達成度を3段階で緩和する
  連続的な仕組み）とは**別体系**。こちらは「対策ロール／対策ステータス合算／
  対策アイテム」の**いずれか1つを満たせば対策成立**という離散判定で、
  未対策なら被害が跳ね上がる（対策口を1つも持たないギミック定義は「対策不能」
  として常に未対策扱いになる＝ボス定義側の設定漏れを黙って握り潰さない）。
- **未対策ペナルティ：** 未対策1件につき危険度（`DangerLevel`）に比例して
  被ダメージ倍率が積み上がる（→ BAL: dungeon.csv
  `UncounteredDamageMultiplierPerDangerLevel`）。**即死級（InstantKill）を
  未対策で踏むとHPを全損する**＝無調査での突撃は壊滅する。
- **完全解析ボーナス：** 解析率100%（→ §4.5.2）で部隊火力（討伐の要求値との
  比較に使う値）に+20%の補正が乗る（`FullIntelDamageBonus`）。
- 討伐の成否は部隊火力（`QuestScoreCalculator.MemberScore`の合計、完全解析
  ボーナス適用後）とボスの要求火力（階層×係数、→ BAL: dungeon.csv
  `PartyPowerRequirementPerFloor`）の比較で決まる。**撃破（Victory）**か
  **撤退（Retreat）**の2択で、撤退時はボスのHPが回復し次回は仕切り直しになる。
- 討伐クエスト（`QuestResolver`）との違い：**こちらはHP下限0**で、0に到達した
  冒険者は強制除籍（恒久ロスト、§4.3.1と同じ表現・扱い）になる。
  即死級ギミックを未対策で踏んだ場合は、乱数レンジを無視して固定でHP全損させる
  （対策の有無がそのまま生死を分ける）。

### 4.5.5 探索（採取）任務（Gathering、v2.0内追加：第3の任務）

特定のボスではなく**フィールドそのもの**を対象にする低リスク経路
（`GatheringResolver`）。調査・道中進軍（隠密・解析、§4.5.3）と並び、
**HP下限1で止まり、致死判定には一切接続しない**。

- **常時出撃可能：** ボスの解析状況・到達階層に関わらず、フィールドが
  開放されてさえいれば出撃できる。フィールドを完全制覇（全20体撃破）した後も
  素材採取だけは継続できる。
- **採取スコア** ＝ (Σ(AGI×係数＋DEX×係数) ＋ 部隊長LDR×係数) × 部隊の平均HP比率
  （→ BAL: gathering.csv）。調査・道中進軍と違い、消耗（HP比率）がスコアに
  直接効く＝弱った部隊は採取の効率も落ちる。
- **獲得素材：** `Max(1, 採取スコア÷係数) ＋ 到達階層÷係数`個の、フィールド
  固有の素材を1種類ランダムに獲得する（＋研究「拡張採取袋」ボーナス、→ §4.6）。
  抽選表はフィールドごとに固定（→ `Models.MaterialCatalog`、下表）。
- **換金ゴールド：** 採取スコア×係数の少量のゴールドも同時に得る。
- HP消費は区分の区別なく一律（→ BAL: gathering.csv）。

**フィールド別・素材抽選表（→ `Models.MaterialCatalog`。構造値のためCSV化せず
コード側に保持、§10.1の方針）：**

| フィールド | 素材（抽選率） |
|---|---|
| 翠緑の原生林（forest） | 月光草70%・変異胞子30% |
| 嘆きの鍾乳洞（cave） | 発光苔70%・黒鉱石30% |
| 忘却の古代廃墟（ruins） | 遺物の欠片60%・ルーン石25%・太古の粉塵15% |
| 焦熱の峡谷（canyon） | 紅玉鉱石65%・火山灰35% |
| 深淵の特異点（abyss） | 虚空の結晶55%・深淵のエッセンス30%・禁忌の欠片15% |

獲得した素材は `GameState.Materials`（素材Id→個数の辞書）に蓄積される。
用途は §4.6「アルベールの研究室」への投資。

### 4.5.6 UI（DungeonPanel、中央ペイン「大迷宮」タブ）

- **フィールドセレクター（OptionButton、v2.0内追加）：** 開放済みの複数
  フィールドを自由に選択できる。未開放のフィールドは選択肢として表示はするが
  選べない（グレーアウト）。選択中フィールドの最高到達階層・攻略対象ボスに
  応じて、以下のボス情報エリア・各ボタンの表示内容が切り替わる。
- ボス情報エリア：名前・階層・最大HP、解析率ゲージ（プログレスバー＋％表示）、
  ギミック開示カード（§4.5.2の段階に応じて内容が変化。完全解析時は
  「与ダメージ+20%ボーナス中」のバッジを表示）。フィールドを完全制覇済みの
  場合は攻略対象ボスが無いため、その旨を表示する。
- 出撃パーティ選択：保存済み編成（§4.0.2）から、現時点で待機中のメンバーが
  いる編成のみを選べる。
- 「調査任務に出撃」ボタン：現在の最高到達階層がボス階層未満なら道中進軍
  （走破力の総合値、§4.5.3分岐A）、ボス階層到達済みなら隠密・解析（§4.5.3
  分岐B）のプレビューをラベル・ツールチップで表示する（ここでも判定用の
  要求値自体は表示しない）。
- 「ボス討伐に出撃」ボタン：解析済みギミックごとに部隊の対策充足状況
  （✔充足／✖未対策）をチェック表示する。未対策ギミックが残っている場合
  （またはギミック自体が未解析の場合）は、強制除籍・壊滅のリスクを赤字で警告する。
- **「探索出撃（素材採取）」ボタン（v2.0内追加）：** 選択中フィールドへ、ボスを
  介さず直接派遣する。採取の総合値（AGI+DEX合計＋部隊長LDR補正、部隊のHP比率で
  減衰）をツールチップに表示する。
- **素材在庫ラベル（v2.0内追加）：** 所持している素材の一覧を表示する。
- 出撃予定一覧（`ActiveDungeonMission`）と取り消しボタン：週次決算の前であれば
  出撃を取り消せる（判定が行われていないため何も失わない）。採取（Gathering）は
  ボスを持たないため、一覧上はフィールド名で表示する。
- 自動スキップは、大迷宮への出撃予定が残っている週は実行しない（UI側の制約。
  討伐の決着・強制除籍がサマリー表示に埋もれてしまうのを避けるため）。
- 週報ログ：調査任務は生還の報告と解析率（または到達階層）の変化を一括表示。
  ボス討伐は昇格試験（§9）と同じくステップ再生で決戦感を出す。探索（採取）は
  獲得素材・ゴールドを報告する。

## 4.6 アルベールの研究室（素材投資システム、v2.0内追加）

探索（採取、§4.5.5）で集めた素材と、通常のゴールドを投じて、恒久的な
インフラバフを獲得するシステム（`Systems.ResearchSystem`）。

- **二軸経済：** ゴールド（副官管轄：給与・雇用・退職金・施設投資）と
  素材（アルベール管轄：研究投資）を分離する。ゴールドは稼ぐほど増え続ける
  一方、素材は探索（採取）に出撃しなければ増えない専用資源として扱う。
- **研究プロジェクト（`ResearchDefinition`、→ BAL: research.csv）：** 各プロジェクトは
  必要素材（複数種・個数）・必要ゴールド・効果種別・効果量を持つ。実行すると
  即座に完了し（乱数・週送りを介さない）、恒久的に効果が有効になる
  （`GameState.CompletedResearchIds`、同じ研究は一度しか実行できない）。

  | 研究 | 効果種別 | 効果 |
  |---|---|---|
  | 秘薬の斥候試薬 | IntelRateBonus | ボス調査時の解析率獲得量に倍率（×1.25、→ §4.5.3分岐B） |
  | 拡張採取袋 | GatheringYieldBonus | 探索（採取）の獲得個数に+1個（→ §4.5.5） |
  | 軽装の踏破術 | TraversalBonus | 道中進軍の走破力スコアに+15加算（→ §4.5.3分岐A） |
  | 医務室特製霊薬 | HpRecoveryBonus | 静養（§3.5）時のHP回復量に+15% |

- **研究実行の判定（`ResearchSystem.CanStartResearch` / `CompleteResearch`）：**
  必要素材・必要ゴールドの両方を満たし、かつ未完了の研究のみ実行できる。
  実行すると素材・ゴールドが減算され、`CompletedResearchIds` に登録される。
  既存セーブとの互換性は、`CompletedResearchIds`（`HashSet<string>`）が
  未定義のセーブでは空集合として補完されることで担保する（新規追加フィールド
  につき、§10.1のCSV欠損時例外とは別枠。JSONデシリアライズのデフォルト値補完）。

### 4.6.1 UI（ResearchPanel、中央ペイン「研究室（Lab）」タブ）

- 上部：現在のギルド所持金と、既知の全素材種の在庫一覧を表示する。
- 研究プロジェクト一覧カード：研究名・説明・必要素材と費用の充足状況
  （「月光草: 3/5」のように現在数/必要数を表示、不足項目は赤字）。
- 「研究実行」ボタン：素材・費用が充足していれば活性化、そうでなければ
  無効化する。完了済みの研究は「研究完了」バッジを表示し、ボタンも無効化する。
- 研究実行はその場（週送りを介さず）で即座に反映され、週報ログにも記録される。

## 5. クラブ運営・人事マネジメント

### 5.1 満足度（Satisfaction）変動ロジック

毎週日曜の決算時に増減（各係数 → BAL: 満足度）。

- 出場機会：22〜27歳が「4週連続で遠征なし」なら毎週 -5
- 賃金妥当性：実力ランクに対し週給が適正値の80%未満なら毎週 -8
- 人間関係：相性「険悪」（→ §5.3.1）のメンバーと同パーティ出撃で -10
  （v1.4改訂で接続済み）
- 勝利・功績：Bランク以上クエスト達成で +10
- 仲間ロストの余波：同パーティの死亡で一律 -30（v1.2改訂で接続済み。→ §4.3.1）
  ＋確率でトラウマ特性付与（v1.4改訂で接続済み。→ §5.3.1・§5.3.2）
- 自然回復：酒場 Lv により毎週 +（→ §6）

### 5.2 契約交渉と退団

- 満足度20未満でインボックスに「昇給要求」または「移籍検討」警告。
- 2週以内に昇給（週給 1.5〜2.0倍提示）またはボーナスを行わなければ自発的に契約解除・他都市へ移籍（消滅）。

### 5.3 相性・特性システム

### 5.3.1 相性（Compatibility）

- 冒険者2人1組ごとに相性値（0〜100）を持つ。初回に同じパーティへ
  編成された時点で初期値50（中立）から開始する。
- 変動（→ BAL: 相性）：
  - 同パーティでクエスト達成（完全勝利・辛勝）→ 小さく上昇
  - 同パーティで苦戦敗退・戦線崩壊 → やや下降
  - 同パーティのメンバーが戦死した場合、居合わせた生存者同士の相性は
    大きく下降（トラウマ的な体験として扱う）
- 相性値が **30未満** で「険悪」と判定し、§5.1の満足度ペナルティ
  （相性険悪のペアと同パーティ出撃で毎週-10）が発動する。
- 「容姿秀麗」特性（§5.3.2）を持つ者が関与するペアは、**上昇量のみ**
  倍率がかかる（下降量には影響しない）。

### 5.3.2 特性（Trait）カタログ（v1.3時点）

| 特性 | 種別 | 付与条件 | 効果 |
|---|---|---|---|
| 古傷 | 後天的 | 致死判定の不可逆障害域（§4.3） | STR/VIT/AGI/DEX割合低下 |
| トラウマ | 後天的 | 戦死現場に居合わせた生存者に確率付与 | MND割合低下 |
| 豪胆 | 先天的 | 採用時に低確率付与 | SurvivalThresholdに固定ボーナス |
| 注意深い | 先天的 | 採用時に低確率付与 | 索敵フェーズのDEX寄与+10% |
| 容姿秀麗 | 先天的 | 採用時に低確率付与 | 関与する相性ペアの上昇量に倍率 |
| 田舎育ち | 先天的 | 採用時に低確率付与 | 探索クエストのスコアに個人ボーナス |
| 知識人 | 先天的 | 採用時に低確率付与 | 単独効果は最小限。豪胆とのペアで護衛に負のシナジー |

- **田舎育ち**：探索クエストのスコアに個人ボーナスを加算する（→ BAL: 特性）。
- **知識人**：単独での効果は最小限。「豪胆」とのペアで護衛クエストに
  負のシナジーを持つ（→ §4.2.3）。

各種確率・効果量は → BAL: 特性 に集約。「頑強」「師匠肌」等は
post-MVP（→ §11）。

## 6. 施設・インフラ拡張（9施設 Lv0〜5 または Lv1〜5）

| 施設 | 初期Lv | 備考 |
|---|---|---|
| 宿舎 | Lv1 | 現役枠に連動（既存どおり） |

訓練枠（Lv0で0名・Lv1で1名、Lv上昇で開放）を持つ。経路2（訓練場配置
による成長、§3.1〜3.4）の対象ステータスは、配置先施設が扱う
ステータスに限定される。

各 Lv の効果・**改築費**は → BAL: 施設。
（v1.0 の Lv1/3/5 の効果値を土台に、Lv2/4 の中間値と全 Lv の費用を BAL 側で補完する。）

### 6.1 建設（Lvアップ）の仕組み（新規定義）

- Lvアップは即時ではなく、**着工→N週間の工事期間→完成**という時間経過を
  要する（Nは施設・対象Lvごとに → BAL: 施設/工事期間）。
- 改築費は着工時に前払い（着工時点で資金から差し引く）。
- **同時着工は1件のみ。** 他の施設（9施設全体）が工事中の間、新たな着工は
  できない（単一の建設キュー）。
- 工事中も、現在のLv（着工前のLv）の効果はそのまま維持される。
- 完成した週の決算処理でLvが+1され、新しいLvの効果が即座に適用される。

## 7. 引退とセカンドキャリア（顧問制度）

- **引退の経路：** 26歳での満期引退（§3.7）に加え、プレイヤーが
  任意のタイミングで満期前の現役冒険者を早期引退させることもできる。
  どちらの場合も退職金（週給×12週＋累積功績×係数）を一括支給する（→ §3.7）。
- 引退した冒険者は「顧問候補」として保持され、以下のいずれかの
  役職に任意で任命できる（任命しなくてもよい）。

### 7.1 教官（Trainer）

- 戦士訓練所・教会・魔法研究所・斥候所、各施設に1名まで配置できる
  （計4名まで）。配置はプレイヤーの手動操作。
- 効果：配置先施設の対象ステータス（1つまたは2つの平均）の
  **生涯ピーク値**に比例して、その施設で訓練中の者への成長ボーナス
  （成長ロール確率または成長量への加算、→ BAL: 顧問/教官伝授）が
  発生する。「得意ステータスの一致判定」は行わない
  （施設の対象ステータスにおけるピーク値の高さがそのままボーナス量になる）。

### 7.2 作戦参謀（Advisor）

- 作戦資料室に1名まで配置できる。
- 効果：**生涯ピーク7能力平均**に比例したボーナスを、
  索敵フェーズのPartyScout（§4.1）と致死判定のSurvivalThreshold
  （§4.3）の両方に加算する（→ BAL: 顧問/参謀補正）。

### 7.3 スカウト（Scout Master）

- **冒険者支援室に1名まで配置できる。** 冒険者支援室がLv0（未建設）の
  間は配置できない。
- 効果：生涯ピークのLDR・DEX平均に比例したボーナスを、新人応募率に
  加算する（既存どおり。能力値そのものへの補正ではない）。既存の
  「総合PA75以上の新人応募率+25%」はスカウト未配置時の基礎値として
  維持し、配置時はここに個人ボーナスが上乗せされる。

### 7.4 保有枠との関係（既存決定を維持）

- 顧問は宿舎の保有枠（現役枠）を占有しない。顧問は各施設の専用スロット
  （教官枠・参謀枠・スカウト枠）にのみ入る。

## 8. 勝敗判定条件

### 8.1 ギルド格付け（v1.0 で未定義 → 新規：勝利条件の根幹）

- ギルドは **名声（Reputation）** 整数を持つ。クエスト達成で加算、
  失敗・ロストで減算（値 → BAL: 格付け/名声増減）。
- ランクは **G → F → E → D → C → B → A → S** の8段階。
- **昇格・降格は別の閾値を持つ（ヒステリシス）。** 各ランクには
  「昇格ライン」（このランクに上がるための最低名声）と「降格ライン」
  （このランクを維持できる最低名声。昇格ラインより低い値）がある
  （→ BAL: 格付け/ランク閾値、昇格・降格それぞれ定義）。
  - 名声が現在ランクの上位ランクの昇格ラインに到達 → 昇格。
  - 名声が現在ランクの降格ラインを割り込む → 降格。
  - 両者の間で名声が上下している限りランクは変化しない
    （閾値付近でのランクのチラつきを防ぐ）。
- ランクは「受注可能クエストの最高ランク」と「助成金額」に影響する
  （既存記述どおり）。

### 8.1.1 名声の自然減衰（新規定義）

- 現在のランクに見合ったクエスト（目安：現ランクと同ランク帯以上の
  クエスト）を、直近N週において1件も達成できていない場合、毎週
  わずかに名声が減少する（→ BAL: 格付け/名声減衰・対象週数N）。
  §5.1「4週連続遠征なしで満足度-5」と同じ発想をギルド全体に適用したもの。
- 直近で該当クエストを1件でも達成すれば、このカウンタはリセットされる。
- この減衰により、Sランクに到達した後も「維持し続けるために相応の
  クエストをこなし続ける」ことが要求される（到達後に安泰化しない）。

### 8.2 勝利条件（未定・構想段階）

- **勝利条件は現時点で未定。** 「20年でSランク到達」「第960ターン到達」
  という当初案はいずれも撤回した（→ §1.2）。**期限による勝敗判定は
  無い。**
- **想定している方向性：** 最終討伐クエスト（魔王戦、仮称）のクリアを
  勝利条件とする。通常のクエスト（§4.0）とは別枠の、一度きりの特別な
  クエストとして構想している（出現条件・難易度・専用の解決ロジック等、
  詳細は未設計）。
- **Aランク到達フラグ（`FinalQuestUnlocked`、v1.10改訂で新設）：**
  ギルド格付けが**初めてAランク以上に到達した時点**で、「最終討伐
  クエストの依頼が持ち込まれるようになった」ことを示すフラグが立ち、
  週報にフレーバーテキストが表示される（→ `GuildRankSystem.UpdateRank`）。
  一度立ったフラグは、その後Aランクを割り込んで降格しても取り消され
  ない。再度A未満からA以上に昇格しても、再度フラグを立てる処理は
  行われない（既にtrueならそのまま）。**最終討伐クエスト自体の中身
  （出現条件・難易度・専用ロジック）は今回実装しない。**
- 詳細設計は、ゲーム全体のバランス・ゲーム性（Phase 3全体の実装・
  実機プレイを経た上での調整方針）が固まってから行う。
- **現時点では勝利判定を一切実装しない。** ギルド格付け・名声システム
  （§8.1）はそのまま維持し、Sランク自体は引き続き「受注可能クエストの
  最高ランク」「助成金額」に影響する指標として機能させるが、
  Sランク到達＝勝利という接続は行わない。

### 8.3 敗北条件（成立した週の終了時に即時敗北）

- **破産:** 週次決算で所持金マイナスが **4週連続**で解消されない
  （4週間の猶予あり）。
- **治安崩壊:** 脅威度が **100%** に到達した週の決算時点で、
  **猶予なく即時敗北**（破産のような連続週数のカウントは行わない）。
- **期限（960ターン到達等）による敗北は無い**（→ §1.2）。敗北条件は
  上記の破産・治安崩壊のみで、既存どおり維持する。

#### 確定済みの世界観連動仕様（実装済み）

以下は構想ではなく、既にコードへ反映済みの確定仕様である。

**1. 女性限定ギルド（構造的に保証）**

コンセプト上の「女性限定」を、設定値ではなく**型の構造**で保証している。

- `Models.Gender` は `Female` のみを持つ（`Male` は削除済み）。
- `NameGenerator` から男性名プール（旧 `WesternMaleNames` / `EasternMaleNames`）と
  性別の抽選（旧 `RollGenderAndCulture`）を撤去し、抽選対象は文化圏のみ（`RollCulture`）。
- バランス値 `MaleGenderChancePercent` は `recruitment.csv` から削除済み。

> 経緯：当初は `MaleGenderChancePercent = 0`（出現率0%）で女性限定を表現していたが、
> それでは**CSVの値を書き換えるだけで男性が復活してしまう**状態だった。
> 「今後も男性冒険者が登場する予定は無い」という決定を受け、復活の余地そのものを
> 構造から取り除いた。この改訂により、既存のセーブデータとの互換性は失われている
> （性別の列挙値が変わったため。互換維持は不要との判断）。

**2. 8年稼働・26歳満期引退モデル（衰微の廃止）**

アルベールの信念（「危険な冒険者は若く美しい全盛期のうちに引退させ、十分な退職金を
持たせて安全に自立させるべき」→ 01_コンセプト.md）をシステム化したもの。

- **加齢による能力低下（衰微）は一切発生しない。** 旧モデルの円熟期・限界期の
  フィジカル衰微と、対応するバランス値（`MatureDecline*` / `LimitDecline*`）は削除した。
- **加入は18歳固定**（`MinCandidateAge` = `MaxCandidateAge` = 18）。
  年齢による能力差別化が無くなったため `YoungestAgePaBonus` は 0 とした。
- **26歳になった年度末で満期引退**（`RetirementAge` = 26）。18歳加入なら稼働期間は
  ちょうど8年＝384週（`MaxActiveWeeks`）になる。時間の刻みは従来どおり**週単位**を維持する。
- 稼働週数は `Adventurer.ActiveWeeks`、累積功績は `Adventurer.TotalContributionScore` に記録する。
- **退職金＝週給×12週＋累積功績×係数**（`SeveranceContributionCoefficient`）。
  支払いきれない場合も引退自体は成立させるが、名声が低下する
  （`SeveranceShortfallReputationPenalty`）。

**3. 冒険者は「戦死」しない（表現の統一）**

HPが0に達した冒険者は、アルベールの秘薬によって必ず一命を取り留める。ただし危険な目に
遭わせたことに激怒したマスターがギルド登録を強制抹消するため、二度と戻らない。

- **システム上の扱いは恒久的なロストであり、従来と変わらない**（現役ロースターから外れる）。
  変更したのはプレイヤーへの提示文言のみで、内部の識別子（`FallenAdventurers` 等）は据え置く。
- 通常クエスト（`QuestResolver` の致死判定）と階層ボス（`DungeonResolver` の
  `ForceRetiredAdventurerIds`）で、この扱いを統一している。

**4. 職業体系の7職拡張**

既存4職（Warrior/Ranger/Mage/Cleric）に、Knight（騎士）・Thief（盗賊）・
Scholar（学者）を追加した。詳細は §2.1・§4.2・§4.2.2。

- 成長重み（`growth_job_weights.csv`）は全7職業で合計9に統一。
- 配置（前衛/後衛）と配置補正倍率は新3職も既存職と同じ考え方で設定
  （騎士＝重戦士型、学者＝魔導士型、盗賊＝斥候型）。
- 装備制限（大剣・魔導士の杖・重装鎧・ローブ）を7職業対応に拡張。
- 学者はギミック解析役として大迷宮システム（下記5）と特に強く結び付く
  （ボスギミックの対策口の1つとして頻出、→ `Data.SampleData.CreateFloorBosses`）。

**5. 大迷宮（ダンジョン攻略システム）**

詳細は新設した §4.5（Core層のエンジン）・§9（UI）を参照。既存の通常クエスト
（討伐/探索/護衛）とは別枠の攻略対象として、全5フィールド（各100階層・
5階ごとに階層ボス計20体）・情報解析率（IntelTier）・走破力による道中進軍・
調査任務（低リスク・致死判定なし）・ギミック対策付きのボス討伐（未対策は
壊滅リスク）・探索（採取、第3の任務）を実装した。中央ペインに専用タブ
（`DungeonPanel.cs`）とフィールドセレクターを追加している。

**6. アルベールの研究室（素材投資システム）**

詳細は新設した §4.6（Core層のエンジン）・§9（UI）を参照。探索（採取）で
集めた素材とゴールドを投じて、恒久的なインフラバフ（HP回復・解析率・
採取数・走破力）を獲得する二軸経済を実装した。中央ペインに専用タブ
（`ResearchPanel.cs`）を追加している。

#### ギルドマスター連動システム構想（将来拡張 / post-MVP）
アルベールのキャラクター性（長命・マッドサイエンティスト・百合趣味）を軸とした、世代交代・育成・経済・演出の深化メカニクス。

1. **【魂魄定着（こんぱくていちゃく）の儀】（顧問制度の不可逆・全盛期固定モデル）**
   - **全盛期スナップショット**: 冒険者が引退・ピークに達した際の最高ステータス・スキルを記録。
   - **施設スロットへのバインド**: 現行の9施設（戦士訓練所・魔法研究所・作戦資料室等）の専用枠に魂を定着させ、永続バフを付与する。施設内には「全盛期の幻影」として常駐する。
   - **不可逆な交代（完全消滅・成仏）**: スロット数は限定的。次世代の魂を新たに定着させるには既存の魂を外す必要があり、外された魂は光となって完全消滅（永久ロスト）する。
   - ※実装時留意: 現行の `AdvisorSystem`（何度でも配置転換可能・消滅なし）からの改修・移行ルールを別途設計すること。

2. **【魂魄融和（こんぱくゆうわ）の秘薬】（女性同士の配合・継承）**
   - **秘薬と誕生**: 相性が最大値に達した女性冒険者ペアに秘薬を処方し、2人の素質・遺伝情報を掛け合わせた子供（新米冒険者）を誕生させる。
   - **培養による高速成長**: エルフの培養技術により短期間で18歳（即戦力、→ §2.4の加入年齢に統一）まで促成成長させる。
   - **百合相性（ニックス）と触媒**: アルベールの琴線に触れる属性・職種ペアほど「感情の爆発力」が高まり、能力限界突破児が生まれやすくなる。採取素材の投入で遺伝安定性・ボーナス値を底上げ可能。

3. **【観測日誌（アルベールズ・ノート）】（関係性可視化と創発ログ）**
   - **関係性タグ**: 同一部隊出撃や同室滞在により、冒険者間に「背中を預ける戦友」「憧れの先輩後輩」等のタグが付与される。
   - **戦闘ログへの割り込み**: 特別な関係にあるペアが出撃時、完全自動の戦闘解決ログ中に確率で特殊連携アクション（庇い・詠唱補助等）が演出として割り込む。

4. **【研究室への素材投資】（二軸経済インフラ）**
   - **ゴールドと素材の分離**: 維持費・装備用の「ゴールド」とは別に、採取任務で得た薬草・魔石・モンスター素材をアルベールへ納品して研究レベルを上げる。
   - **インフラバフ**: 秘薬の純度向上（初期能力上限UP）、医務室設備強化（負傷日数短縮）、試作薬レシピの閃きなど。
   - **基礎版はv2.0内で実装済み（→ §4.6）**：4種の恒久バフ（HP回復・解析率・採取数・走破力）を
     即時実行のシンプルな研究として実装した。上記の「初期能力上限UP」「研究レベル」といった
     より深いインフラ育成要素は引き続きpost-MVPの構想として残る。

5. **【試作薬（ドーピング）の投与】（出撃前のハイリスク・ハイリターン）**
   - ボス戦等において、部隊に副作用付きの未認可薬を投与可能（例：筋力+100%だが帰還後に医務室送り確定、敏捷+50%だが知力激減でスキル使用不可など）。

6. **【ギルドマスター後方支援】（間接介入トリガー）**
   - 緊急退避の煙幕（即時帰還・負傷無効化・報酬破棄）や常備回復薬の投入。
   - ※実装時留意: `GuildManager.Core` は戦闘を一括全自動解決するアーキテクチャであるため、リアルタイム介入ではなく「出撃前の携行品・保険設定」または「UI再生時のイベントフック」としてCore層の純粋性を損なわない形で設計すること。

## 12. セーブ/ロード（新規）

- 保存形式：JSON。
- 保存タイミング：毎週の決算後に自動保存＋プレイヤーの任意操作による
  手動保存。
- セーブスロット：単一（1つのみ、常に上書き）。複数スロットは
  post-MVP（→ §11）。
- ロード失敗時（破損ファイル・バージョン不一致）は新規ゲームの
  みを提示し、既存セーブを保護する（プレイヤーが新規ゲームを
  選ぶまで上書きしない）。
- セーブフォーマットにはバージョン番号を持たせる。現時点では
  マイグレーション処理は未実装（バージョン不一致は単純にロード
  失敗として扱う）。将来的な仕様変更に備え、この番号は仕様変更の
  たびに更新することを検討する。
- 保存対象は、ギルドのスカラー値（週番号・所持金・名声・格付け・
  脅威度・破産カウンタ・敗北理由・名声減衰カウンタ）、冒険者
  （現役・引退済み顧問候補・戦死者の3リスト全体）、相性、訓練施設への
  配置、施設Lv・建設キュー、顧問（教官・参謀・スカウト）の割り当て、
  受注可能クエスト一覧、派遣中（複数週）クエストの全て、永続パーティー
  編成（→ §4.0.2、v1.9改訂で追加）、大迷宮の5フィールド状態（開放状況・
  最高到達階層・各ボスの撃破状況とIntelRate、→ §4.5）、素材インベントリ
  （`GameState.Materials`、→ §4.5.5）、完了済み研究Id一覧
  （`GameState.CompletedResearchIds`、→ §4.6、v2.0内追加）。装備カタログは
  静的コード定義のため保存対象外（冒険者側は装備IDの文字列のみ保持）。
  大迷宮フィールド拡張・素材・研究の3項目はいずれも新規追加フィールドのため、
  それらを持たない旧セーブでもロード自体は失敗しない：素材（`Materials`）・
  完了済み研究Id（`CompletedResearchIds`）は未定義キーがJSONデシリアライズの
  デフォルト値（空辞書／空集合）で自然に補完される一方、大迷宮フィールド
  （`DungeonFields`）は単一ダンジョン時代の旧セーブだと空リストのまま復元される
  ため、`MainDashboard`側に明示的なフォールバック
  （`DungeonFields.Count == 0` なら `SampleData.CreateDefaultFields()` で補う）
  を置いている。
