# 03. システム仕様 v2.0

> v1.0 の詳細仕様を土台に、**矛盾の修正**と**未定義項目の決定**を反映した v1.1 を経て、
> v2.0 では実装済みコード（7職業化・8年稼働モデル・女性限定ギルドの構造化・大迷宮攻略システム
> ＝5フィールド拡張＋3大任務＋素材投資「アルベールの研究室」まで含む）との**内容同期**を行った。
> 数値そのものはこの文書に書かず、`docs/04_バランス表/` 配下の該当CSV・行を参照する
> （`→ BAL: ファイル名/項目`。旧 `04_バランス表.xlsx` は §10.1 のとおり廃止済み）。
> **決定はすべて「暫定」。** 実際に遊んで調整する。ここでは「破綻しない構造」を固めることが目的。

## 0.4 この版での主な変更（v2.0内の追加改訂：候補Aの実装確定＝素材マスターCSV化・研究レシピ刷新）

上記§0.3で「候補A」として保留した探索（採取）・アルベール研究室は、コード側の実装が先行して
完了したため、保留を解除し本文の取り消し線を外した。保留時点（§0.3）からの内容変更点は以下：

| # | 候補A保留時点の叩き台 | 実装確定後 |
|---|---|---|
| 1 | 素材は`Models.MaterialCatalog`にハードコード（5フィールド計12種、抽選率方式） | **`materials.csv`（→ Balance.MaterialBalance）へCSV外部化。現時点は森（forest）フィールドの3種のみ定義**（月光草`mat_forest_herb`・霊樹の枝`mat_forest_wood`・変異胞子`mat_forest_spore`）。**他4フィールド（cave/ruins/canyon/abyss）は未定義のため、それらでの採取は素材が抽選されない**（→ §4.5.5） |
| 2 | 素材抽選はフィールドごとの固定％抽選 | **抽選率ではなく、素材ごとのMinFloor到達判定へ変更。** フィールドの到達階層(`ReachedFloor`)がMinFloor以上の素材だけが対象になり、対象内から等確率で1種を選ぶ（MaxFloorは記録用メタ情報で抽選の上限には使わない、→ §4.5.5） |
| 3 | 研究4種のレシピ・必要素材は旧素材Id（`herb_moonlight`等）ベース | **`research.csv`を新素材Id・新レシピへ全面差し替え。** 「医務室特製霊薬」（`res_infirmary_elixir`）→「薬草湿布の調合」（`res_herb_poultice`）に差し替え、他3種（`res_scout_reagent`・`res_gathering_bag`・`res_light_tread`）はIdを維持しつつレシピを新素材へ更新（→ §4.6） |
| 4 | 採取スコアはAGI・DEX・隊長LDRのみ | **盗賊(Thief)・斥候(Ranger)ボーナスを新設。** 該当職業の部隊員1名につき固定ボーナスをスコアへ加算（→ §4.5.5、`GatheringBalance.ThiefRangerScoreBonus`） |
| 5 | 「生体蛍光試薬」（旧・秘薬の斥候試薬）のEffectValueは解析率上昇量への直接倍率（×1.25） | **(1+EffectValue)倍の「加算率」方式へ統一。** EffectValue=0.25が「+25%」を意味するよう、他3種のバフ（HpRecoveryBonus等）と同じ考え方に揃えた（→ §4.6） |

## 0.6 この版での主な変更（v2.0内の追加改訂：毎回1Fリセット・複数週潜行型への刷新）

| # | 改訂前 | 改訂後 |
|---|---|---|
| 1 | 道中進軍はフィールドの最高到達階層（`ReachedFloor`）から再開し、1週で帰還する | **毎回1階層から潜り直す複数週潜行型へ。** 出撃（`ActiveDungeonMission`）は帰還まで複数週残り続け、`ExpeditionStatus`（Advancing／AwaitingBossDecision／EngagingBoss／Retreating）と現在階層（`CurrentFloor`）を持つ。`ReachedFloor`は最高到達階層の記録（表示・素材抽選範囲用）になった（→ §4.5.1・§4.5.3） |

## 1. システム全体構想

- **タイトル:** 冒険者ギルドマネージャー（仮称）
- **エンジン:** Godot **4.2 以降**（C# / .NET 8）※ .NET 8 対応は 4.2 から。対象は PC（Win/Mac/Linux）。C# は Web 書き出し非対応のため Web 版は想定しない（→ 05）
- **解像度:** 論理 1920×1080 を基準。ウィンドウ拡縮は Godot の content scale で対応（→ §9・05）
- **設計方針:** モデル層（Godot 非依存の純 C# ライブラリ）とビュー層（Godot Node/UI）を完全分離。

### 1.2 時間モデル
- 1ターン ＝ 1週。1ヶ月 ＝ 4週。1年 ＝ 12ヶ月 ＝ 48週。
- **第960ターン（20年目）到達による勝敗判定は行わない（v1.10改訂で撤廃）。**
  「20年でSランク到達＝勝利」という当初案は撤回済みで、この20年という
  数字は、期限でも勝敗条件でもなく、下記「期間設計の意図」（世代交代を
  構造的に強制するための目安の年数）を説明するための**参考値**として
  残す。勝利条件そのものは引き続き未定（→ §8.2）。
- **敗北条件（時間経過ではなく、週次決算の状態で決まる。詳細 → §8.3）：**
  1. **副官解雇** — マスターの機嫌（§8.1）が **0** に到達した週の決算で即時敗北
     （`DefeatReason.DismissedByMaster`、2026年9月新設・§0.20）。成果ゼロの週の退屈減衰（−5）や、
     強制除籍への激怒（1名につき−20）が積み重なると到達する。
  2. **破産** — 所持金マイナスが **4週連続**で解消されない（4週間の猶予あり）。
- 検算：20年 × 48週 = 960ターン。✓（あくまで参考値としての検算であり、
  この週数に到達しても勝敗のいずれも発生しない）
- 期間設計の意図：初期メンバー1世代の稼働年数（稼働の中核は §3.0 の22〜34歳）では
  20年を走り切れず、必ず新人採用と世代交代が要る。「初期メンバーだけでは
  クリアできない」を加齢・強制引退（§3.7）だけで構造的に保証するための年数。

### 1.3 自動スキップ（早送り）機能（新規、v1.10改訂）

- 「次週へ進める」を毎週手動で押す代わりに、複数週を連続して自動処理
  できる機能。`AutoSkipService.AutoSkip` が `WeekProcessingSystem.ProcessWeek`
  を繰り返し呼び出す（手動の「次週へ」と全く同じ週次決算処理を経由する
  ため、挙動が食い違うことはない）。
- 自動スキップ中、受注可能クエスト一覧への操作は一切行わない（新しい
  クエストを自動受注させない）。既に派遣済みの複数週クエストは
  そのまま進行する。
- 無限ループ防止のため、1回の自動スキップで進める週数に上限
  （暫定1000週、`AutoSkipService.DefaultMaxWeeks`）を設ける。
- **以下のいずれかが発生した週で自動的に停止し、プレイヤーに操作を
  戻す**（→ `WeekResult.ShouldStopAutoSkip`）：
  1. 新春採用試験の週
  2. 満足度警告（契約交渉）が新たに発生した週
  3. 施設の建設完了
  4. ~~複数週クエストの帰還（結果判明）~~ **→ 2026年9月、旧通常クエストの撤去に伴い廃止**
  5. 戦死・古傷（不可逆障害）の発生
  6. ~~脅威度が75%を**新たに**跨いだ週~~ **→ 2026年9月、脅威度システムの完全撤去に伴い廃止**（→ §0.10・§4.4）

## 2. 冒険者データモデル

### 2.1 静的・基本属性

- **ID:** GUID
- **氏名:** 文字列（新人応募者は氏名ジェネレーター(NameGenerator)で自動生成、
  → §2.4。初期メンバー4名は引き続き固定名）
- **性別（Gender）:** **女性のみ（v2.0改訂：構造的に保証）。** `Models.Gender` 列挙型は
  `Female` しか持たず、`Male` は削除済み。氏名ジェネレーターからも男性名プール・
  性別抽選そのものを撤去しており、バランス値の書き換えだけでは男性が復活しない
  （経緯・詳細は §11「確定済みの世界観連動仕様」）。氏名生成と、将来の立ち絵
  システム連携（次フェーズ、post-MVP）のための土台という位置づけは変わらない。
- **年齢:** 整数 18〜26（v2.0改訂：8年稼働モデル、→ §3）。加入は18歳固定、
  26歳の年度末で満期引退するため、現役として取りうる年齢の範囲はこの8年間のみ。
- **職業（JobClass）:** 7職業（v2.0改訂：Knight・Thief・Scholar を追加、→ growth_job_weights.csv）。
  配置（前衛/後衛）は職業から一意に決まる（→ §4.2・`PlacementRules.GetDefault`）。
  - 前衛：
    - 重戦士（**Warrior**）：耐久（VIT）・筋力（STR）特化、ヘイト集中
    - 騎士（**Knight**）：VIT特化の重装・統率、部隊の盾役（新職）
    - 斥候（**Ranger**）：俊敏（AGI）・探索（DEX）特化、不意打ち防止 ※旧 Scout をリネーム
    - 盗賊（**Thief**）：AGI特化の俊敏・器用、罠解除・隠密に長ける（新職）
  - 後衛：
    - 魔導士（**Mage**）：精神力（MND）・知力（INT）特化、範囲殲滅
    - 神官（**Cleric**）：精神力（MND）・統率（LDR）特化、致死回避・負傷軽減
    - 学者（**Scholar**）：INT特化の解析役、ボスギミックの生体解析に長ける（新職、→ §4.5）
  - 成長重み（→ BAL: growth_job_weights.csv）：全7職業で7ステータスの重み合計が
    **9に統一**されている（例：Warrior=STR3/VIT3/AGI1/DEX1/LDR1、Scholar=INT4/MND2/AGI1/DEX1/LDR1）。
    特定職だけが総合的に育ちやすい・育ちにくいという不公平が出ないようにする設計。
  - 装備制限（→ §4.2.2）：大剣・重装鎧はWarrior/Knight系、魔導士の杖・ローブは
    Mage/Scholar系、というように7職業に対応する形で拡張済み。
- **性格（Personality）:** 質実剛健 / 合理主義 / 好漢 / 慎重派（効果は §5・§3 に接続。MVP では未使用でよい）

### 2.2 能力値（実効値 1〜100）

STR / VIT / AGI / DEX / MND / LDR / INT の7種。INTは今回から個人CP・成長・
総合PAに参加する活性ステータスとなった（v1.2改訂：旧仕様の予約フィールドを
昇格）。各ステータスの役割は §4・§10 のとおり。

- **潜在能力 PA：ステータス毎に `PA_STR`, `PA_VIT`, `PA_AGI`, `PA_DEX`, `PA_MND`, `PA_LDR`,
  `PA_INT` の7値を持つ（各 1〜100）。** 実効値は対応する PA を上限に成長する。
- **総合PA** ＝ 上記7つの PA の平均（v1.2改訂：旧6値平均からINTを追加）（採用試験・
  スカウト評価など「素質の高さ」を1数値で見たい箇所で使用）。
- 生成時の関係：新人はステータス実効値 < PA。序盤は伸びしろがあり、経験（出撃・訓練）で
  実効値がPAに近づいていく。**加齢による衰微はv2.0で完全廃止**（§3）。実効値はPAへ向かって
  伸びるのみで、下がる経路は古傷（Trait、§4.3）のみになった。
- **生涯ピーク値（v1.3新設 → v2.0で撤廃）：** 加齢衰微廃止（v2.0）に伴い生涯ピーク値
  （旧 `PeakSTR` 等の7値）は撤廃した。顧問効果（教官・参謀・スカウト、§7）は**引退時の
  実効ステータス**（`STR` 等）を直接参照する。旧セーブに残る `Peak*` 項目はロード時に無視される。

### 2.3 動的・コンディション属性

- **現在HP / 最大HP：** `最大HP = VIT×2 + 50`（VIT 1〜100 → 52〜250）
- **満足度（Satisfaction）:** 0〜100。50未満でサボタージュ傾向、20未満で移籍・退団検討（§5）
  - ※ v1.0 の「Morale」を改名。戦闘中の一時的な士気（Morale）は post-MVP の別フィールドとして予約
- **負傷状態（InjurySeverity）:** なし / 軽傷（全治1〜2週・該当能力-10%）/ 重傷（全治3〜8週・出撃不可・-30%）/ 不可逆障害（完治不能・恒久低下）
- **契約週給（WeeklyWage）:** 毎週引落しの基本給（→ BAL: 経済/週給基準）

### 2.4 採用（新規：新春採用試験）
- タイミング：毎年 新年（第1週）の新春採用試験のみ。年1回。途中採用なし。
  **ただし1年目（ゲーム開始時点の第1週）は対象外。** 初期メンバーが既に配備されているため、
  最初の採用試験は2年目の新年（第49週）から（→ プレイテストで発覚。1年目に既に応募が
  来ると初期配備との整合性が悪いため）。
- 選抜：応募者数名（→ BAL: 採用/応募者数）から、宿舎の空き枠の範囲で
  プレイヤーが選ぶ。採用人数に固定上限なし（枠が許す限り複数可）。
- 契約年齢：**18歳固定**（v2.0改訂：8年稼働モデル、→ §3・`MinCandidateAge` = `MaxCandidateAge` = 18）。
  全員が加入から満期（26歳）まで、ちょうど8年間（384週）稼働できるよう年齢を統一した。
  年齢による能力差別化は無くなったため、最年少ボーナス（`YoungestAgePaBonus`）は0。
  PA自体は年齢に依存せず、通常応募者（PA 40〜80）と、一定確率（`HighPotentialBaseChance`）で
  出現する有望新人（PA 70〜100）の2段構えで生成される（→ BAL: recruitment.csv）。
- 雇用枠：現役枠は宿舎Lvに連動。宿舎Lv1で8枠、拡張で解放（§6）。
  顧問は現役枠を占有しない（§7）。
- 契約金：契約時に一時金。総合PA×年齢で変動、即戦力(高PA・年長)ほど高額（→ BAL: 採用/契約金）。
- 維持コスト：契約中は毎週の週給が継続（§2.3・§5.1）。頭数×週給が経営を圧迫し、
  宿舎・医務室・訓練場との投資競合を生む。
- 応募の質：スカウト顧問+25%（§7）。（旧来の「格付けが高いほど有望新人の応募率↑」は、ギルド格付けの廃止（2026年9月、→ §8.1）に伴い削除）
- 初期メンバー：採用システム対象外（開始時に別枠配備。将来キャラエディットで選択実装）。
- 冒険者支援室がLv0（未建設）の間も、新春採用試験自体は例年どおり
  発生する。ただしスカウト（§7.3）による応募率バフは、この施設が
  Lv1以上でスカウトが配置されている場合のみ発生する。
- 応募者の氏名は、氏名ジェネレーター（NameGenerator）により生成される。
  文化圏（洋名80%・和名20%、→ BAL: 採用/文化圏比率）をランダムに決定し、
  対応する名前プールからファーストネームを選ぶ。性別は前述のとおり女性で固定のため、
  性別の抽選自体を行わない（v2.0改訂：`RollGenderAndCulture` → `RollCulture`、→ §11）。
  現役ロースターと重複する名前は避ける（最大50回リトライ）。
  姓・二つ名の付与はpost-MVP（→ §11）。

## 3. 加齢・成長モデル（v2.0改訂：8年稼働・26歳満期引退モデル）

> **v2.0での全面改訂：** 加齢による能力低下（衰微）は完全に廃止した。冒険者は
> 「衰えない」代わりに「短い期間で必ずギルドを去る」。世界観上の根拠は
> ギルドマスター・アルベールの信念（「危険な冒険者は若く美しい全盛期のうちに
> 引退させ、十分な退職金を持たせて安全に自立させるべき」→ 01_コンセプト.md）。
> 旧モデル（15〜40歳・円熟期/限界期のフィジカル衰微・40歳強制引退）は本節の
> 改訂により丸ごと置き換わった（詳細な経緯は §11「確定済みの世界観連動仕様」）。

### 3.0 年齢帯の定義（成長ロール確率の区分。v2.0改訂：実働3区分へ純化）

年齢帯は**18歳加入・26歳満期引退の8年稼働モデルで実際に通過する3区分のみ**とする。
旧モデルの円熟期（28〜34）・限界期（35〜40）は到達経路が存在しないため撤去した
（→ §0.11）。加入初年度（新鋭期）が最も伸び、以降の年齢帯で逓減する設計。

| 年齢帯 | 範囲 | 8年稼働モデルでの実際の到達年齢 | 成長ロール基礎確率 |
|---|---|---|---|
| 新鋭期（`Young`） | 〜18 | 18歳（加入初年度） | 0.35（→ BAL: aging.csv） |
| 成長期（`Growing`） | 19〜22 | 19〜22歳 | 0.30 |
| 全盛期（`Peak`） | 23〜 | 23〜26歳（満期引退まで） | 0.12 |

- 判定は `Adventurer.AgeBand`（年齢からの算出。セーブ対象ではない）。
- 範囲外の年齢は近い側の帯へ丸める：18歳以下（旧モデルの15〜17歳を含む）は新鋭期、
  27歳以上（満期を越えた旧データ・異常値）は全盛期へクランプする。
- 旧セーブに残る `AgeBand`（円熟期・限界期を含む）は読み取り専用プロパティのため
  デシリアライズ時に無視され、年齢から算出し直される（→ §12）。

> §5.1 の出場機会ペナルティ対象年齢は、本改訂の直後（→ §0.12）に新・全盛期の
> **23〜26歳**へ整合させた。22歳（成長期）は育成猶予として対象外。
> → BAL: 満足度/出場機会（`OpportunityPenaltyMinAge`／`MaxAge`）

### 3.1〜3.4 成長の数値、および成長トリガー（新規定義。v2.0改訂：衰微は完全廃止のため節タイトルから除去）

**成長トリガーは2経路のみ。それ以外（単純待機）では実効値は変化しない。**
EXP・Lvのような中間概念は導入しない。実効値が直接、週ごとの成長ロールで増減する
（v1.1初出のレベルアップ制度は本改訂で廃止。理由は下記）。

#### 経路1：出撃による成長（実戦経験）
**2026年9月、大迷宮の任務へ再配線した**（旧通常クエストの撤去で一時停止していたもの。
`GrowthSystem.ApplyExpeditionGrowth`、`DungeonExpeditionSystem` が各任務の週次解決時に呼ぶ）。
大迷宮の各任務（潜行・ボス討伐・迷宮調査・採取）が出撃経験（成長ロール）のトリガーになる。

| 任務（解決のタイミング） | 成長ロールの試行回数 | 対象能力（等確率で1つ） |
|---|---|---|
| 道中進軍（潜行中、1階層以上進んだ週ごと） | `GrowthRolls_Traversal`（2回） | STR・VIT・AGI・DEX |
| 階層ボス撃破（決戦に勝利した週） | `GrowthRolls_BossVictory`（5回） | 全7能力 |
| 迷宮調査（帰還時） | `GrowthRolls_Survey`（2回） | INT・DEX・LDR・AGI |
| 採取（帰還時） | `GrowthRolls_Gathering`（2回） | AGI・DEX・VIT |

- 各試行は `GrowthBaseChancePercent`（35%）で成功し、成功すると対象能力の実効値を **+1** する
  （→ BAL: dungeon.csv）。上限は対応する PA_xxx（クランプ、超過しない。PA到達済みなら変化なし）。
- 対象は部隊の**生存者のみ**（現役ロースターに残り、HPが1以上の者）。強制除籍者には適用しない。
- ボス討伐で撃破できなかった場合（撤退・全滅）は成長しない（決戦の週は進軍もしていないため、
  道中分も発生しない）。扉前での偵察（指令待ちのまま週を越した場合）も成長の対象外。
- 成長した分は週報に「▲ 〇〇 の STR が上昇！」として表示する。
- 旧仕様（年齢帯別基礎確率×クエスト難易度係数×職業別重み、成長量+1〜数点。
  `GrowthSystem.ProcessDeploymentGrowth`）は、旧クエストの撤去以降どこからも呼ばれていない
  （コード・バランス値は残置）。

#### 経路2：訓練施設配置による成長（座学・鍛錬）
- 出撃せず、かついずれかの訓練施設（戦士訓練所・教会・魔法研究所・斥候所）に
  配置されている冒険者が対象（出撃した週はこちらのロールは行わない＝二重成長なし）。
- 成長ロール確率 = 年齢帯別基礎確率 ×（訓練施設倍率（現状1.0倍固定）＋教官ボーナス）。
  教官（Trainer、§7.1）が配置先施設に配置されていれば、教官の対象ステータスの
  引退時の実効値に比例したボーナスが加算される（→ BAL: 顧問/教官伝授）。
- ロール対象ステータスは、配置先施設が扱うステータスに限定される（v1.3改訂。
  戦士訓練所→STR・VIT、教会→MND、魔法研究所→INT、斥候所→AGI・DEX。→ §6）。
- 成長ロール成功時の処理は経路1と同じ（+1〜数点、PA_xxxでクランプ）。更新されるのは
  実効値のみ（生涯ピーク値はv2.0で撤廃、→ §2.2）。

##### 経路2：運用ルール確定
- 訓練枠は各施設Lv1で1名まで。Lv上昇で枠数を開放する（→ §6・BAL: 施設/訓練場）。
- 配置には毎週の利用費用が発生する（→ BAL: 訓練/週次費用）。宿舎枠のような
  「保有しているだけで無料」ではなく、都度払いのランニングコストとして
  資金処理に組み込む。
- 配置された冒険者は、成長ロール（既存記述のとおり）に加えて、
  §3.5の訓練固有HP処理（微減・回復なし・下限1）を受ける。
- 上記により「訓練場は無制限に使える安全策」ではなく、
  「1名だけ選んで・費用を払って・少しずつHPを削りながら鍛える」
  という毎週の投資判断になる。

#### 経路なし：単純待機
- 出撃もせず訓練場配置もされていない冒険者は、当該週のステータス成長ロールを
  行わない。HPの自然回復（§3.5改）のみ発生する（成長とHP回復は独立した軸）。

#### 成長打ち止めの表現
- 実効値がPA_xxxに到達したステータスはロールしても変化しない
  （自然に成長が止まる。上限到達の明示的な処理は不要、クランプのみで表現できる）。
- 年齢帯が進むほど成長ロール基礎確率は下がる設計とし、育成の主な窓は
  新鋭期・成長期(18〜22)に集中させる（→ §3.0、BAL: 加齢/年齢帯別基礎確率）。

#### 衰微処理（v2.0で完全廃止）
- **加齢によるステータス低下（衰微）は一切発生しない。** 旧モデルにあった
  「円熟期・限界期にSTR/AGI/VITを確率で恒久的に低下させる」処理（`ApplyDecline`）と、
  対応するバランス値（`MatureDecline*` / `LimitDecline*`）はコードごと削除済み。
- 実効値が下がる経路は、本モデルでは古傷（Trait、§4.3）のみになった。
- 育成不足は意図的に残す：8年（384週）という短い1世代の稼働期間では、
  実効値をPAまで伸ばし切れない（＝一代では「強すぎるキャラ」を作れない）成長速度に
  BAL: aging.csv の成長率を設定している。
- 世代間増幅で埋める：不足分は 教官伝授(§7)＋訓練場(§6)＋スカウト顧問による高PA新人の
  流入(§8.1)で世代をまたいで埋める。成長率(絞る)と伝授効果(伸ばす)は常に一対で
  釣り合わせる＝本作の中心的バランス方程式（この設計方針自体はv1.1から変更なし。
  「20年でSランク到達」という当初の勝敗条件は§1.2のとおり既に撤廃済みのため、
  「間に合わせるべき期限」としての20年という数字はもう存在しない。8年ごとに
  世代交代が必ず起きる、という**構造**だけが目的である）。

### 3.5 静養・HP自然回復（疲労Fatigueを廃止し、回復をHPに一本化）
- 疲労度（Fatigue）パラメータは廃止。持久・消耗の軸はHP（VIT由来）に統合する。
- 出撃した週：戦闘結果に応じて CurrentHP が減少（§4.2 表）。
- 非出撃（待機・静養）の週：CurrentHP を一定量回復（→ BAL: 静養/待機回復）。上限は MaxHP。
- 施設補正：宿舎・医務室 Lv により回復量に倍率（→ §6）。
- 対象範囲：本処理は重傷以外（無傷・軽傷）のHP回復を担う。重傷は §3.6 が別管理
  （InjuryWeeksRemaining をカウントし、全治時に HP を満タン復帰）。
- 「過労」フラグは廃止。連続出撃の抑制は、低HP→個人CP低下（§4.2）による
  戦闘結果の悪化で軟らかく働く（ハードな出撃不可ゲートは重傷のみ）。

### 3.5 静養・HP自然回復（つづき：訓練場配置の扱い）

- 訓練場に配置され、かつ出撃していない週は、§3.5前段のHP自然回復を**適用しない**。
  代わりに以下の訓練固有のHP処理を行う：
  - CurrentHP を一定量減少させる（→ BAL: 訓練/HP消費）。
  - ただし CurrentHP は 1 未満にはならない（下限クランプ）。
  - この減少は負傷（InjurySeverity）を発生させず、致死・不可逆障害の判定
    （§4.3）には一切接続しない。訓練は「回復しない・地味に削れる」だけの
    低リスクな経路として扱う。
- 出撃も訓練場配置もしていない（単純待機の）週のみ、前段のHP自然回復が適用される。
- 3つの状態（出撃／訓練場配置／単純待機）は互いに排他。同じ週に重複しない。

### 3.6 負傷回復処理（v1.1で欠落判明・新規追加）

**発覚の経緯:** Phase 2 のMVPを実際にプレイしたところ、重傷になった冒険者が一度も回復せず、詰み状態のまま出撃させ続けられることが判明した。§2.3で負傷の全治週数（軽傷1〜2週／重傷3〜8週）をデータとして定義していたにもかかわらず、それを消化して治す処理がv1.0・v1.1のどちらにも存在していなかった。

- 負傷した週に、その負傷の全治週数を `InjuryWeeksRemaining` としてランダムに決定し保持する（軽傷1〜2週、重傷3〜8週の範囲で）。
- 毎週の決算処理で、負傷している全冒険者の `InjuryWeeksRemaining` を1減らす。
- 0に達したら `Injury = None` に戻し、`CurrentHP = MaxHP` として全快させる。
- **出撃制限:** `Injury == Severe` の間は編成画面で選択できないようにする（MVPのUIには未実装だったため、Phase 2の修正で追加）。
- 不可逆障害（Permanent）はこの処理の対象外（そもそも完治しない。仕様書 §2.3・§4.3参照）。

### 3.7 満期引退（v2.0改訂：26歳・8年稼働モデル）

- **26歳になった年度末（第48週決算）に満期引退**（`RetirementAge` = 26、
  `AgingSystem.ProcessWeeklyAging`）。18歳で加入した場合、年度末を8回迎えて
  26歳になるため、稼働期間はちょうど8年＝384週（`MaxActiveWeeks`）になる。
  この計算が成立する順序が重要：**先に加齢し、その結果が満期年齢に達していれば
  引退**という順序で処理する（逆にすると9年稼働になってしまう）。
- 加入から満期までの週数は `Adventurer.ActiveWeeks` に毎週記録される
  （UI表示・退職金の算定根拠に使う想定）。
- **早期引退（`AgingSystem.RetireVoluntarily`）：** プレイヤーは満期を待たず、
  任意のタイミングで現役冒険者を早期引退させ、顧問候補にすることもできる
  （→ MainDashboardの「引退させる」ボタン）。退職金支給等の処理は満期引退と共通。
- **退職金＝週給×12週（`SeveranceWeeks`）＋累積功績（`TotalContributionScore`）×
  係数（`SeveranceContributionCoefficient`）。** 危険な任務を多く引き受けた
  冒険者ほど手厚く送り出される。**累積功績の加算元は大迷宮の実績**（2026年9月、旧通常
  クエストの撤去に伴い再配線。`DungeonExpeditionSystem.AwardContribution`、→ BAL: dungeon.csv
  `Contribution*`）：
  - 道中進軍（潜行）：進んだ階層数×`ContributionPerTraversedFloor`（1階層につき+1）。
  - 階層ボス撃破：撃破したボスの階層×`ContributionPerBossFloor`（10Fボスなら+10、深いほど大きい）。
  - 採取：素材を持ち帰れた時に`ContributionPerGathering`（+2）。
  いずれも部隊の生存者（現役ロースターに残っている者）全員へ加算し、強制除籍者には加算しない。
  扉前での偵察・迷宮調査・撤退そのものでは加算されない。
- 退職金を払いきれない場合も引退自体は成立させる（冒険者を人質に取らない）が、
  「退職金を持たせて自立させる」アルベールの信念に背くため、マスターの機嫌が下がる
  （`SeveranceShortfallMoodPenalty`、−15。旧・名声低下、→ §8.1）。
- **装備の自動返還（2026年9月新設、→ §4.2.2「離脱時の自動回収」）：** 引退した冒険者が
  身につけていた全装備は、ロースターから外れる**直前に**ギルド保管庫（`GameState.Armory`）へ
  回収される（満期・早期のどちらも同じ）。装備したまま引退済み一覧へ移ると、その武具には
  二度と手が届かなくなるため。保管庫の在庫には入手経路として「○○（引退）から返還」が記録され、
  誰の遺したものかを後から辿れる。
- 引退した冒険者は現役ロースターから除外され、`RetiredAdventurers`（引退済み・
  顧問候補一覧）へ移る。§7の顧問制度（教官・参謀・スカウト）は既に本実装済みで、
  ここに保持された冒険者から任命できる（旧v1.1時点の「顧問制度は未実装のため
  効果を付与しない」という制約は解消済み）。
- 「引退勧告（肩たたき）」の受諾判定は任意項目のまま未実装（→ §11）。8年稼働
  モデルでは満期が明確な区切りとして機能するため、優先度は当初より下がっている。

## 4.0.2 パーティー編成（永続化、部隊編成パネル `PartyFormationPanel`）

- パーティーは編成時に保存される永続的な単位（最大4部隊、`SavedParties`）。名前を自由に付け替えられる。
- 1人は同時に1つのパーティーにしか所属できない。
- どのパーティーにも属さない冒険者は「未編成（待機中）」として扱われる。
- **部隊選択と出撃枠連動:** 開放出撃枠（`UnlockedSquadSlots`、初期1枠・森節目ボス撃破で拡張、→ §4.5.1）と連動し、開放枠内の部隊のみ選択・編集可能。未開放枠は「第X部隊 (未開放)」として選択が無効化（ロック）される。
- **出撃中ガード:** 選択中の部隊が出撃中（`IsDispatched` または `ActiveDungeonMissions` に所属）の場合、「【出撃中・編成変更不可】」バッジを表示し、メンバーの追加・解除・改名操作を完全にロックする。
- **編成メンバー4枠（スロット0〜3）:**
  - 各カードに隊長/スロット番号バッジ、職業に応じた【前衛】／【後衛】バッジ（後述）、ポートレート、氏名、職業、年齢、HPバー、「編成解除」ボタンをコンパクト（最小高さ148px）に配置。
  - 空き枠は「＋ 空き枠（下の候補一覧から配属）」と表示。
- **編成候補リスト（待機冒険者一覧）:**
  - 画面下部に十分なスクロール枠（最小高さ360px、垂直拡張）を確保し、常時4〜5行以上の候補者を一覧表示。
  - 各行に前後衛バッジ、氏名、職業、年齢、HP、現在状態（待機中／出撃中／軽傷／重傷／他部隊配属中／引退）を表示。
  - 待機中かつ空き枠がある場合のみ「配属 ＋」ボタンが活性化し、即時スロットへ配属される。
- **部隊総合力プレビュー（サマリーパネル）:**
  - **算出は`PartyFormationSystem.CalculateMetrics`に一元化する（2026年9月）。** UI側は式を持たず、
    任務解決時（`DungeonTraversalResolver`・`ScoutingResolver`）とまったく同じstatic式の結果を表示する。
    以前は編成パネルが隠密の式を独自に持っており、Core側を直してもUIが追随しない二重管理だった。
  - **走破力予測:** VIT・MND・部隊長LDR＋研究/参謀ボーナス（→ §4.5.3）。道中潜行の進軍ランク目安。
  - **隠密適性:** AGI・DEX・隊長LDR＋斥候/盗賊ボーナス −人数減衰・重装ペナルティ（→ §4.5.3）。
    迷宮調査の遭遇回避目安。カード下段に内訳（素点／専門職／人数倍率／重装）を小さく併記し、
    「何を直せば上がるのか」が編成中に分かるようにする。
  - **解析適性:** INT合計に基づくスコア（迷宮調査の解析効率目安）。
  - **部隊健全度:** メンバーの平均HP%バーと数値。
  - **相性警告:** メンバー間の相性（→ §5.3.1）を確認し、相性30未満（険悪）のペアがいる場合は警告表示するが編成自体は妨げない。
- **前衛/後衛の配置表示（v2.0追加改訂）:** 配置の手動切り替え操作は行わず職業固定（§4.2）を維持するが、UI上ではスロットカードおよび候補リスト内に【前衛】（水色）／【後衛】（薄紫）バッジを明瞭に可視化し、部隊の前後バランスを一目で把握できるようにした。

### 4.2 前衛/後衛の列システム（新規定義）

- 各冒険者は「配置（Placement）」＝前衛/後衛の属性を持つ。これはパーティの
  スロットではなく冒険者自身に紐づく永続的な状態で、クエストをまたいで
  保持される。
- 配置は職業から自動決定される（§2.1の適性表に基づく、v2.0改訂：7職業分に拡張）：
  - 前衛：重戦士（Warrior）・騎士（Knight）・斥候（Ranger）・盗賊（Thief）
  - 後衛：魔導士（Mage）・神官（Cleric）・学者（Scholar）
- 配置補正（個人CP計算式の「職業配置補正(職業, 配置)」）も7職業分を定義済み
  （→ BAL: combat.csv `PlacementCorrection_*`）。新3職も既存職と同じ考え方：
  騎士＝前衛1.2倍/後衛0.8倍（重戦士と同型）、学者＝前衛0.8倍/後衛1.2倍（魔導士と
  同型）、盗賊＝前衛/後衛とも1.0倍（斥候と同型）。同じ役割の職業間に戦闘格差が
  出ないようにしている。
- **配置の自動決定とUI可視化（2026年9月同期）：** 以前はパーティー編成画面に
  手動の配置切り替えボタンがあったが、「現状は職業でほぼ配置が固定され、
  選択の幅を生んでいない」という判断から手動切り替え操作は廃止した。
  ただし、部隊の前後衛構成をプレイヤーが直感的に把握できるよう、部隊編成パネルおよび
  候補一覧には【前衛】（水色）／【後衛】（薄紫）のカラーバッジを表示している。
  階層ボス討伐の部隊火力（→ §4.5.4）における内部の配置補正ロジックは
  自動決定された配置のまま従来どおり機能し続ける。
- 役割から外れた配置（例：魔導士を前衛に置く）は、個人CP計算式の職業配置補正で
  ペナルティが掛かる（→ BAL: 戦闘/配置補正）。ただし配置が職業で自動固定される
  ため、現状この分岐が実際に発生することはない。
- 個人CP計算式（既存）の「職業配置補正(職業, 配置)」は、この配置属性を
  参照する（→ BAL: 戦闘/配置補正）。

### 4.2.2 装備システム（新規）

- 装備枠：武器（Weapon）・防具（Armor）・アクセサリー1・
  アクセサリー2（Accessory1, Accessory2）の4枠。
- 効果：
  - 武器：個人CPへの固定加算（→ BAL: 装備/武器効果量）。
  - 防具：最大HP（VIT×2+50）への固定加算（→ BAL: 装備/防具効果量）。
  - アクセサリー：アイテムごとに「個人CP加算」または「最大HP加算」の
    いずれかを持つ（アイテムデータで指定）。
- 職業制限：各アイテムは装備可能な職業（JobClass）のリストを持つ
  （`Item.AllowedJobs`、空リスト＝制限なし）。制限に反する装備はできない。
  7職業化に伴い、次の武具は職業の役割に沿って複数職に対応させている
  （→ BAL: equipment.csv・`ItemCatalog`）：
  - 大剣（重量武器）：Warrior・Knight
  - 魔導士の杖（魔法職）：Mage・Scholar
  - 重装鎧：Warrior・Knight・Cleric
  - ローブ（後衛職）：Mage・Cleric・Scholar
  - 鉄の剣・革鎧・アクセサリー類は制限なし（全職業が装備可能）。
- 入手：次の2経路（素材・製作期間を伴う工房での製作はpost-MVP、→ §11）。
  1. **カタログからの即時購入**（`EquipmentSystem.TryPurchaseAndEquip`）：資金を払えば
     即座に購入・装備できる。代金は前払いで、返金はしない。
  2. **ギルド保管庫からの装着**（`EquipmentSystem.TryEquip`、2026年9月新設）：遺物の鑑定
     （→ §4.7）で出土した武具や、他の冒険者から外した武具の**現物**を装着する。

- **装備の「個体」とギルド保管庫（2026年9月改訂、→ §4.7）：**
  冒険者の装備枠が持つのはカタログIdの文字列ではなく**個体**（`Models.EquipmentItem`＝
  個体Guid・カタログId・表示名・入手週・入手経路）である。装備を外したときに
  「どの個体を保管庫へ戻すのか」を一意に決める必要があるため（同じ鉄の剣を2本持てる）。
  - **不変条件：** 1つの個体がギルド保管庫（`GameState.Armory`）と冒険者の装備枠の
    両方に同時に存在することはない。装着すれば保管庫から抜け、外せば保管庫へ戻る
    （＝個体が消えたり増えたりしない）。
  - 同じ枠に別の装備を着けた場合、押し出された旧装備は保管庫へ戻る（購入経路でも同じ。
    改訂前は上書きで消滅していた）。
  - 付け替え（AさんからBさんへ）は「外す → 保管庫 → Bさんへ装着」の2手で行う。
    保管庫を経由しない直接の受け渡しは用意しない（在庫の所在を一意に保つため）。

- **着脱の判定（`EquipmentSystem`）：** 以下のいずれかに該当すれば何もせず `false` を返す
  （`Try*`系の共通パターン）。
  - **出撃中**（`Adventurer.IsDispatched`）の冒険者は着脱不可（→ `CanChangeEquipment`）。
    出撃中の部隊の戦力が週次決算の直前に変わるのを防ぐ。UI側（`AdventurerPanel`の
    「装備変更」ボタン・`EquipmentPopup`の各ボタン）も同じ条件でDisabledにするが、
    可否の判定そのものはCore層で自己完結させる。
  - 職業制限違反（→ `Item.IsAllowedFor`。例：魔導士に大剣）。
  - 個体の装備枠が指定した枠と一致しない（武器枠に防具を入れる等）。
  - 個体がカタログから引けない（カタログから消えた武具の旧データ＝正体不明の物は着せない）。
  - 装着時：個体が保管庫に無い（他の冒険者が装備中など）。解除時：対象の枠が空。

- **離脱時の自動回収（`EquipmentSystem.UnequipAllToArmory`、2026年9月新設）：**
  冒険者がギルドを去るすべての経路で、身につけていた全装備を離脱の**直前に**保管庫へ回収する。
    ギルド備品として在庫へ戻る（→ 06タスクリスト「①離脱時の装備回収」）。

  | 離脱経路 | 実行箇所 | 在庫に記録される入手経路 |
  |---|---|---|
  | 26歳満期引退（→ §3.7） | `AgingSystem.Retire` | 「○○（引退）から返還」 |
  | 早期引退（プレイヤー操作、→ §7） | `AgingSystem.RetireVoluntarily` | 「○○（引退）から返還」 |
  | 決戦での強制除籍（→ §4.3.1） | `DungeonExpeditionSystem.ApplyForcedRetirements` | 「○○（除籍）から返還」 |
  | 契約交渉決裂による退団（→ §5.2） | `SatisfactionSystem.Terminate` | 「○○（退団）から返還」 |

  - 回収した個体には**回収した週**（`AcquiredAtWeek`）と上表の入手経路（`AcquiredFrom`）を
    書き込む。保管庫一覧（→ §4.7.4）で「第40週 ○○（除籍）から返還」と辿れるようにするため。
  - 通常の着脱（`TryEquip`/`TryUnequip`）と違い、**出撃中ガードを持たない**。決戦で強制除籍
    される冒険者は定義上まだ出撃中であり、そこで弾くと肝心の経路で装備を取りこぼすため。
  - 回収した装備の一覧は呼び出し側へ返す（早期引退は `RetireVoluntarily` の戻り値、強制除籍は
    `DungeonMissionResolution.RecoveredEquipment`）。UIはこれを週報・操作ログへ反映する。
    満期引退・退団は週次決算の内部で起きるため専用の戻り値を持たないが、その週に回収された
    個体は `AcquiredAtWeek` から辿れる。

- **最大HPの整合：** `Adventurer.MaxHP` は装備補正を含む計算プロパティのため、装備を外した
  瞬間に「現在HP＞最大HP」が起こり得る。着脱のたびに現在HPを最大HPでクランプする
  （最大HPが**上がった**場合は現在HPを据え置く＝装備で全回復してしまわないようにする）。

- **UI（`EquipmentPopup`、冒険者人事パネルの「装備変更」から開く）：**
  - 上段：所持金・現在HP/最大HP・装備補正の合計と、現在の装備4枠。各枠に「外す」ボタン
    （空き枠・出撃中はDisabled）。
  - 中段：**ギルド保管庫の在庫一覧**（装備枠・名称・効果量・入手週と入手経路）。職業制限に
    反するものは所持していること自体は見えるようグレーアウト（選択不可）にする。
  - 下段：カタログ購入一覧（従来どおり。職業制限違反はグレーアウト、資金不足はツールチップで明示）。
  - 着脱・購入はその場で即座に反映され、保管庫・冒険者ステータス・冒険者人事パネルの装備欄・
    「倉庫・遺物」画面の保管庫タブ（→ §4.7.4）がまとめて再描画される。
- **見た目との連動（未接続）：** 立ち絵システム（`AdventurerVisualData`）
  との連携を設計上は想定している（防具は`CostumeUpperId`・
  `CostumeLowerId`を同時切替、武器は`WeaponId`、アクセサリー1は
  `AccessoryId`に反映、アクセサリー2は見た目に反映しない）が、
  **`AdventurerVisualData`自体が本リポジトリのどこにも存在しないため、
  今回この連携は未実装。** `Item.VisualPartId`フィールドはデータとして
  保持しているのみで、実際の反映先が用意され次第、接続する
  （→ §11）。

### 4.2.3 クエスト種別ごとの統一点数計算式（2026年9月撤去）

### 4.3.1 強制除籍の記録（v2.0改訂：「戦死」表現の撤廃）

> **世界観上の扱い（→ 01_コンセプト.md）：** 本作の冒険者は「戦死」しない。
> HPが0に達しても、アルベールの秘薬によって必ず一命は取り留める。ただし、
> 危険な目に遭わせたことに激怒したマスターがギルド登録を即座に強制抹消するため、
> 二度と戻らない。**システム上の扱いは恒久的なロストであり、以前の「戦死」と
> 何一つ変わらない。** 変更したのはプレイヤーへの提示文言のみ（内部の識別子
> `FallenAdventurers` 等はセーブデータ互換のため据え置き）。強制除籍は現在、
> 大迷宮の階層ボス討伐（`DungeonResolver`、§4.5.4）でのみ発生する（旧通常クエストは撤去済み）。

- 強制除籍となった冒険者は、氏名・除籍された週番号・除籍時の年齢・職業を
  記録として保持する（内部呼称は据え置きで `FallenAdventurers`、顧問候補の
  引退済み一覧とは別枠）。
- 現役ロースター・パーティ編成・訓練場配置からは完全に除外する。
- §5.1「仲間ロストの余波（-30、同パーティ全員の満足度）」は、
  この強制除籍の判定と同時に実行する。
- **離脱時の装備回収（2026年9月新設、→ §4.2.2「離脱時の自動回収」）：** 記録リストへ移す
  **直前に**、その冒険者が身につけていた全装備をギルド保管庫（`GameState.Armory`）へ回収する。
  倒れた隊員を救い出すアルベールが、その武具も併せて持ち帰る扱い。保管庫の在庫には
  入手経路として「○○（除籍）から返還」が記録される
  （→ `DungeonMissionResolution.RecoveredEquipment`。週報ログでも
  「📦 アルベールは○○の武具を回収し、ギルド備品としてギルド保管庫へ返還した」と報告する）。

## 4.5 大迷宮（ダンジョン攻略システム、v2.0新規・5フィールド拡張／3大任務）

通常クエスト（§4.0〜§4.4）とは別枠の攻略対象。「調査任務で階層を進み、情報を集める →
判明したギミックへ対策を組んだ編成で討伐する」という2段構えを軸に、随時出撃できる
第3の任務「探索（採取）」（§4.5.5）が並走する。**無調査での突撃は未対策ペナルティに
より壊滅する**設計（→ §4.5.4）。

同時出撃枠（`GameState.UnlockedSquadSlots`）は出撃中の部隊の数で消費する
（`DungeonExpeditionSystem.CanDispatch`）。出撃操作自体は即座に解決せず、週次決算でまとめて解決する。
**2026年9月改訂（毎回1Fリセット・複数週潜行型）：** 道中調査で出撃した部隊は
帰還するまで複数週にわたって潜行し、その間ずっと出撃枠を1つ占有する（→ §4.5.3）。

### 4.5.1 5フィールド構造と開放条件（`DungeonField`）

- 大迷宮は単一のダンジョンではなく、**全5フィールド**で構成される
  （→ BAL: 構造値のためCSV化せず`Data.SampleData.CreateDefaultFields`にハードコード。
  §10.1の方針どおり）：

  | 攻略順（Order） | フィールドId | 名称 |
  |---|---|---|
  | 1 | forest | 翠緑の原生林 |
  | 2 | cave | 嘆きの鍾乳洞 |
  | 3 | ruins | 忘却の古代廃墟 |
  | 4 | canyon | 焦熱の峡谷 |
  | 5 | abyss | 深淵の特異点 |

- 各フィールドは**100階層**（`DungeonField.MaxFloor`）を持ち、**10階ごと**
  （`DungeonField.BossInterval`）に階層ボスを配置する（10・20・…・100Fの
  **1フィールド計10体、全5フィールドで計50体**）。配置間隔は構造値としての
  ハードコードをやめ、`dungeon.csv`の`BossIntervalFloors`へ外部化した
  （2026年9月改訂、→ BAL: dungeon.csv／`DungeonBalance.BossIntervalFloors`）。
  ボスのギミック種別は4種を周期的に循環させ、階層が深く・フィールドの
  攻略順が進むほどHP・危険度・報酬が滑らかに増える。
- **開放条件：** 初期状態で開放済みなのは第1フィールド（森）のみ。
  - フィールドOrder 1〜3（森・洞窟・廃墟）は、そのフィールドの**10Fボス撃破**で
    次順（Order+1）のフィールドが開放される（森10F撃破→洞窟、洞窟10F→廃墟、
    廃墟10F→峡谷）。
  - 第5フィールド（深淵）だけは通常の10F連鎖では開放されない。**Order 1〜4
    （森・洞窟・廃墟・峡谷）の全フィールドで20Fボスが撃破済み**になった時点で
    開放される（`DungeonExpeditionSystem.ApplyFieldProgression`）。
  - **出撃枠拡張（2026年9月新設、「古代エルフの多頭通信術式の復元」）:**
    森（Order=1）の節目ボス撃破のみが対象。**森10Fボス撃破で同時出撃枠2枠**、
    **森20Fボス撃破で3枠**まで拡張される（`DungeonExpeditionSystem.ApplyFieldProgression`）。
    既に到達済みの枠数を下回ることはない（Maxで引き上げるのみ）。旧来はギルド格付けE・D相当への
    引き上げも伴っていたが、格付けの廃止（2026年9月、→ §8.1）に伴い出撃枠のみになった。
  - 最終フィールド（深淵）の100Fボス撃破で `FinalQuestUnlocked` フラグを立てる
    （＝終盤コンテンツ解禁の合図、→ §8.2）。
- **撃破報酬（`FloorBoss.RewardGold`/`RewardMaterialId`/
  `RewardMaterialCount`、2026年9月改訂で素材ドロップを新設）：** 撃破成功時に
  `DungeonExpeditionSystem.ApplyFieldProgression`が`GameState.Gold`
  へ加算し、`RewardMaterialId`が設定されていれば`GameState.Materials`へも加算する。
  名声報酬（`RewardReputation`・`dungeon.csv` `BossBaseReputation`）は2026年9月に廃止し、
  撃破1体ごとのマスターの機嫌+20（週次決算で集計、→ §8.1）に置き換えた。
  ゴールドは段（フィールド内の何体目か＋攻略順による格上げ）を指数に
  `dungeon.csv`の係数で滑らかにスケールする（→ `BossBaseRewardGold`・
  `BossRewardGoldMultiplier`等）。
  - **森（forest）：** 全10体すべてが素材をドロップする。3種
    （月光草・霊樹の枝・変異胞子）を巡回させ、個数は段が進むほど緩やかに増える
    （3〜5個、→ §4.5.5候補Aの最初の実装分）。
  - **洞窟・廃墟・峡谷・深淵（2026年9月拡張）：** **節目ボス（10F・20Fのみ）**が、
    フィールド固有の希少素材を確定ドロップする（3〜5個）。他の階層のボスは
    素材ドロップを持たない。

    | フィールド | 10F/20Fボスの確定ドロップ素材 |
    |---|---|
    | 嘆きの鍾乳洞（cave） | 黒鉱石（`mat_cave_ore`） |
    | 忘却の古代廃墟（ruins） | ルーン石（`mat_ruins_rune`） |
    | 焦熱の峡谷（canyon） | 紅玉鉱石（`mat_canyon_gem`） |
    | 深淵の特異点（abyss） | 深淵の結晶（`mat_abyss_crystal`） |
- 各フィールドは**最高到達階層の記録**（`ReachedFloor`）を持ち、ボス撃破のたびに
  `max(現在値, 撃破階層+1)` で更新されるほか、道中進軍でより深く潜れた場合も更新される。
  **2026年9月改訂（毎回1Fリセット）以降、これは表示・素材抽選範囲（§4.5.5）用の記録であり、
  出撃の開始階層ではない**（部隊は毎回1階層から潜る、→ §4.5.3）。
- 攻略対象は各フィールドごとに「未撃破のうち最も浅い階層のボス」
  （`DungeonField.GetNextActiveBoss`）。全ボス撃破済みのフィールドは制覇済み
  （攻略対象なし。探索（採取）は制覇後も継続可能、→ §4.5.5）。

### 4.5.2 階層ボスと情報解析率（IntelTier）

- 各ボスは階層（`Floor`）・最大HP・複数の**ギミック**（`BossGimmick`、後述）を持つ。
- 各ボスは**情報解析率**（`IntelRate`、0.0〜1.0）を持ち、調査任務（§4.5.3）の成果で
  上昇する。解析率に応じて段階的に情報が開示される（`IntelTier`、→ BAL: scouting.csv）：

  | 解析率 | 段階（IntelTier） | 開示される情報 |
  |---|---|---|
  | 〜25%未満 | 未調査（Unknown） | 名前と階層のみ。ボス概要は「？？？」 |
  | 25%〜 | 基本情報（Basic） | 最大HPなど、おおよその規模が判明 |
  | 50%〜 | 危険情報（Hazards） | どのギミック（猛毒・重装甲など）を持つかが判明 |
  | 75%〜 | 対策情報（Countermeasures） | 各ギミックへの対策ロール・必要アイテムが判明 |
  | 100% | 完全解析（Complete） | 弱点看破。討伐時の与ダメージに+20%ボーナス（→ BAL: dungeon.csv `FullIntelDamageBonus`） |

- 情報公開の原則（§4.2.3）に従い、判定用の内部数値（要求値・Ratio・閾値）は
  UIに一切表示しない。開示されるのは「何が起きるか」という定性的な事実のみ。

### 4.5.3 潜行（Scouting）と迷宮調査（Survey）：毎回1Fリセット・複数週潜行とボスの調査

低リスク経路として設計する。**HP下限1で止まり、致死判定には一切接続しない**
（探索・護衛クエストと同じ考え方。調査で人を失うと「調べてから挑む」という
本システムの導線自体が破綻するため）。

**遠征の状態遷移（`ActiveDungeonMission.Status`＝`ExpeditionStatus`、2026年9月改訂）**

| 状態 | 意味 | 週次決算での処理 |
|---|---|---|
| Advancing | 道中進軍中 | 現在階層（`CurrentFloor`）から進軍する（下記「道中進軍」） |
| AwaitingBossDecision | 未撃破ボスの扉前で指令待ち | 扉前でボスを偵察し解析率を上げる（下記「扉前の偵察」。完全解析済みなら何もしない） |
| EngagingBoss | 討伐を指令済み | ボス討伐の決戦判定（§4.5.4）。勝敗にかかわらず決着後に帰還 |
| Retreating | 撤退中 | 帰還（UIの撤退は即時帰還のため、通常この状態は経由しない） |

- **出撃は必ず1階層から始まる**（`CurrentFloor=1`）。帰還（撤退・勝利・全滅）で
  出撃は解除され、次回もまた1階層から潜り直す（1Fリセットルール）。
- ボスの撃破状況（`IsDefeated`）と解析率（`IntelRate`）はフィールド側に永続するため、
  2回目以降は撃破済み・解析済みの区間を電撃的に抜けられる。
- **プレイヤー指令（`DungeonExpeditionSystem`）：**
  - `TryEngageBoss`（⚔️ボス討伐に挑む）：扉前で判断待ちの部隊にのみ出せる。携行ポーチの
    アイテムを積み込み代金を即時徴収し、EngagingBossへ。次週の決算で決戦判定。
  - `TryRetreat`（🏃撤退・帰還する）：出発済みで進軍中または判断待ちの部隊を即時帰還させる。
    道中の拾得物をギルドへ格納し、全員を待機中へ戻す（討伐は行わない）。
  - `TryCancel`（取り消し）：**出発前（まだ一度も週次決算を経ていない）の出撃のみ**。
    潜行を始めた部隊は撤退で呼び戻す。
- **帰還時の処理：** 出撃を解除して同時出撃枠を空け、生還者を待機中へ戻し、道中の
  拾得物（`CarriedGold`・`CarriedMaterials`）をギルドへ格納する。生還者が1人もいない
  （全滅）場合、拾得物も失われる。累計出撃回数は帰還時に数える（取り消しは数えない）。

**道中進軍（`DungeonTraversalResolver`）**

- 現在階層から、その階層以降で最初の未撃破ボスに向けて進む。一度倒したボス階層は
  素通りできる（＝再度足止めにならない）。
- **走破力（2026年9月改訂：VIT/MND化）** ＝ Σ(VIT×`Traversal_Weight_Vit` ＋
  MND×`Traversal_Weight_Mnd`) ＋ 部隊長LDR×`Traversal_Weight_Ldr`
  （＋TraversalBonus種別の研究ボーナス合算。軽量踏破靴・耐熱踏破法、→ §4.6
  ＋参謀のルート指導ボーナス、→ §7.2）vs 現在階層×係数
  （→ BAL: dungeon_traversal.csv。重みは VIT 1.0／MND 0.8／LDR 1.0）。
  - **測っているもの：** 悪路を踏み越える**体力（VIT）**と、長い潜行に耐える**気力（MND）**。
    隊列を崩さず歩かせ続ける**部隊長の指揮（LDR）**が乗る。
  - **AGI/DEXは走破力に一切効かない。** 旧モデルは隠密と同じ Σ(AGI+DEX) だったため、
    編成画面の「走破力予測」と「隠密適性」が**どんな編成でも必ず同じ数値**になっていた
    （→ §0.17）。素早いだけの部隊は隠れるのが上手いだけで、長い道中を踏破できるとは限らない。
- Ratioに応じて4区分（電撃／迅速／通常／苦戦）に分類し、区分ごとに定められた
  階層数を**移動予算**として進軍する。**走破力が不足していても必ず1階層は進む**
  （完全な足止めにはしない設計）。
- **調査度連動の電撃走破（2026年9月新設）：** 1階層進むごとに、その区間を担当する
  ボス（その階層より深い最初のボス。撃破済みも含む、`DungeonField.GetSegmentBoss`）の
  解析率から走破倍率 `IntelSpeedMultiplier = 1.0 ＋ 解析率 × IntelSpeedBonusPerIntel(2.0)`
  を求め、`1 ÷ 倍率` の予算を消費する（未調査1.0倍〜完全解析3.0倍＝同じ予算で3倍進む）。
  区間担当ボスが完全解析済みの階層では被ダメージが `FullIntelDamageMultiplier(0.3)` 倍
  （HP損耗70%軽減）になる。この軽減は**その区間の階層にだけ**効く（→ 下記「HP消費」の
  階層ごとの積み上げ）。floor→floor+1 の1歩は出発階層 floor の区間担当ボスが受け持つ
  （9→10Fは10Fボス、10→11Fは20Fボスの区間）。週報の走破速度は、歩いた各階層の区間倍率を
  階層数で重み付けした**実効平均**（`TraversalResult.IntelSpeedMultiplier`）を表示する。
- **ストッパー：** 未撃破ボスの階層を超えて進むことはない。ボス階層に達したら
  そこで進軍を止め（`TraversalResult.StopperTriggered`）、**自動では突入せず**
  AwaitingBossDecisionへ遷移する。週報に「【扉前到達】部隊は第○層ボスの扉前に到達。
  突入準備を整えて指令を待機中」と出力し、自動スキップを停止する（§1.3の第10条件）。
- **拾得物：** 1階層進むごとに `LootGoldPerFloor` G、`LootFloorsPerMaterial` 階層ごとに
  その階層で採れる素材（§4.5.5の素材定義）を1個拾い、部隊が持ち歩く（帰還時に格納）。
  素材の選択は乱数を使わない決定的な巡回。
- **HP消費（2026年9月改訂：未踏破の重損耗・階層ごとの個別損耗の合算積み上げ）：**
  各員について基礎損耗率を乱数で決める：**未踏破階層**（進軍前のフィールドの最高到達階層
  `ReachedFloor`より深い階層）用は重い消費率 **30〜50%**（→ BAL: dungeon.csv
  `UnexploredHpLossPctMin/Max`）、既踏階層用は進軍ランクごとの軽重（電撃が最も軽く、
  苦戦が最も重い、→ BAL: dungeon_traversal.csv `HpLossPct*`）。どちらも実際に歩いた種類の
  階層がある場合だけ引く。この基礎率を歩いた階層数で均等配分し、**1階層ごとに**
  「その階層の基礎率（未踏破か既踏か）÷歩いた階層数 × その階層の区間担当ボスによる
  被ダメージ倍率（完全解析なら0.3、それ以外1.0）」を求めて**合算**する：
  `実効損耗率 = Σ_階層 (基礎率_f × 被ダメ倍率_f) ÷ 歩いた階層数`。
  失うHPは `floor(最大HP × 実効損耗率 ÷ 100)`（浮動小数で計算し、途中の整数割り算で
  切り捨てない）。したがって未調査の未踏破区間は30〜50%をそのまま受け、完全解析済みの
  「安全ルート」なら9〜15%まで下がる。解析済み区間から未解析区間へまたいだ場合、
  解析済み区間の0.3倍は解析済みの階層ぶんにしか効かず、未解析区間の重損耗を薄めない
  （例：7〜10Fが完全解析・既踏、11〜13Fが未解析・未踏破で、電撃8%・未踏破50%なら
  (3×8×0.3 ＋ 3×50×1.0)÷6 ＝ 26.2%。旧来の「未踏破の基礎率×歩いた階層の平均倍率」
  （50%×0.65＝32.5%）は、0.3倍を未解析区間へ漏らす一方で既踏階層にも重損耗を課していた）。
  1階層も進めなかった場合は、進軍ランクの率×出発区間の被ダメージ倍率を受ける。
  区間ごとの内訳は `TraversalResult.Segments` に記録し、週報に開示する（→ §4.2.3 特記事項）。
  HPは下限1で止まり、道中損耗による死亡・負傷・強制除籍は発生しない。
  （走破倍率は進む階層数に掛かる＝完全解析で同じ予算のまま3倍の階層を進む。走破力スコアには
  掛けない：スコアに掛けると進軍ランクの上限（電撃・4階層/週）で頭打ちになるため。）
- 未撃破ボスが残っていないフィールドを最深部（100F）まで踏破した場合は、そのまま帰還する。

**ボスの調査（`ScoutingResolver`）：迷宮調査（Survey）と扉前の偵察**

ボスの解析率を上げる手段は2つあり、どちらも同じ判定（下記）で解決する：

- **迷宮調査（`DungeonMissionType.Survey`、2026年9月新設、「🔍 迷宮調査に出撃」）：**
  選択中フィールドの攻略対象ボスを、次週の決算で1回調査して帰還する**1週の独立任務**
  （`DungeonExpeditionSystem.TryDispatchSurvey`）。1階層から潜る潜行とは別で、扉前まで
  潜る必要はない。同時出撃枠を1つ使う。完全解析済み・撃破済みのボスには出撃できない。
  出発後に対象ボスが他部隊に倒されていた場合は、調査せずに帰還する。
- **扉前の偵察：** 潜行中に扉前で判断待ちのまま週を越した部隊が行う（待機中に他部隊が
  そのボスを倒した場合は、判断待ちを解いて先へ進軍する）。

判定は3つ：

1. **隠密（2026年9月改訂：潜伏精度の指標へ）：** 隠密適性 vs 階層×要求値
   （→ BAL: scouting.csv）。失敗すると見つかり、解析の成果が1段階下がる
   （大成功→成功→失敗）。HP消費には影響しない（HP消費は護衛判定だけで決まる）。

   - **基礎隠密** ＝ Σ(AGI×`Stealth_Weight_Agi` ＋ DEX×`Stealth_Weight_Dex`)
     ＋ 部隊長LDR×`Stealth_Weight_Ldr` ＋ **専門職ボーナス合計**
   - **実効隠密** ＝ max(0, ⌊基礎隠密 × **人数倍率**⌋ − **重装ペナルティ合計**)

   | 補正 | キー（scouting.csv） | 値 | 意味 |
   |---|---|---|---|
   | AGI・DEXの重み | `Stealth_Weight_Agi` / `Stealth_Weight_Dex` | 1.0 / 1.0 | 身のこなしと、足音を殺す手先の精度 |
   | 部隊長LDRの重み | `Stealth_Weight_Ldr` | 0.5 | パニック・事故の防止 |
   | 専門職ボーナス | `Stealth_Bonus_RangerThief` | 30 | **斥候（Ranger）・盗賊（Thief）1名につき加算** |
   | 人数倍率 | `Stealth_PartySize_Mult_1`〜`_4` | 1.10 / 1.00 / 0.85 / 0.70 | 大所帯ほど気配を消しにくい（単独潜入が最も隠れやすい） |
   | 重装ペナルティ | `Stealth_HeavyArmor_Penalty` | 30 | **重装者1名につき直接減算**（重装鎧の装備者、または重戦士・騎士） |

   - **順序を固定する：** 人数倍率は**乗算**、重装ペナルティは倍率適用**後**の**直接減算**。
     この順序でないと「大人数の重装部隊」で両者が二重に効き、極端な値になる。
   - 重装の判定は「重装鎧を装備している」または「職業が重戦士・騎士」のどちらかに該当すれば
     1名分（両方に該当しても二重取りはしない）。
   - 結果は0未満にならない（重装部隊は「隠密0」＝必ず見つかるところで止まる）。
   - **走破力（§4.5.3の道中進軍）とは別系統。** 隠密が測るのは「**誰が**（専門職）」
     「**何人で**（人数）」「**何を着て**（重装）」潜るかという潜伏の精度であり、
     走破力が測る体力・気力とは編成の最適解が異なる（→ §0.17）。
2. **解析・情報収集：** Σ(INT)×係数 vs 階層×要求値（＋IntelRateBonus種別の
   研究ボーナス合算。生体蛍光試薬・古代戦術録の解読、→ §4.6）。Ratioに応じて
   大成功／成功／失敗の3区分（閾値は探索・
   護衛と同じ1.5倍/1.0倍、§4.2.3）。解析率の基礎上昇量は大成功0.50・成功0.25・
   失敗でも断片情報として0.10。
3. **護衛（4段階、`GuardTier`、2026年9月新設）：** 部隊護衛力＝出撃メンバー全員の中で
   最大の max(STR, VIT, INT)（装備補正込み）。要求護衛値＝`BaseRequiredGuardPower`(35)×
   ボス階層÷10（10F＝35、20F＝70…）。護衛比率＝護衛力÷要求護衛値で4段階に分け、
   解析率の上昇量に倍率を掛け、各員のHP消費（最大HP×%）を決める（→ BAL: scouting.csv
   `GuardRatio_*`・`GuardEffect_*`）：

   | 護衛比率 | 段階 | 解析成果の倍率 | 各員のHP消費 | 週報の状況 |
   |---|---|---|---|---|
   | 1.4以上 | 余裕（Abundant） | ×1.25 | 0% | 護衛が残党を完封 |
   | 1.0〜1.4未満 | 十分（Sufficient） | ×1.0 | 8% | 護衛が残党を退ける |
   | 0.7〜1.0未満 | 充足（Marginal） | ×0.75 | 20% | 護衛の手が回らず被弾 |
   | 0.7未満 | 不足（Deficient） | ×0（成果なし） | 40% | 魔物の残党に強襲され調査隊が潰走 |

   HPは下限1で止まり、致死・負傷・強制除籍の判定には一切接続しない。

- 解析率の上昇量＝基礎上昇量×研究ボーナス×護衛倍率。解析率は上限1.0でクランプする。
- 解析率100%（完全解析済み）のボスの扉前では偵察を行わない（それ以上解析率が
  上がらず、部隊のHPを消費するだけのため）。

### 4.5.4 階層ボス討伐（Dungeon Expedition）

直接指揮UIは作らない。扉前に着いた部隊へ（対策次第で）携行品を積んで「挑む」を
指令すれば、次週の決算で完全自動で判定し構造化された結果を返す。2026年9月改訂以降、ギルドから直接ボス討伐へ出撃する経路はUIに無い
（Core の `TryDispatch(…, BossAssault)` は「扉前から即座に決戦へ臨む」扱いとして
テスト・互換用に残している）。

勝敗を分けるのは「事前にどれだけ調べ、どれだけ対策を積んだか」：

- **ボスのギミック（`BossGimmickType`）：** 猛毒（Poison）・重装甲（HeavyArmor）・
  飛行（Flying）・即死級攻撃（InstantKill）の4種。§4.2.3の環境ギミック
  （`EnvironmentTag`。クエストの「場」に付く属性で、対策達成度を3段階で緩和する
  連続的な仕組み）とは**別体系**。こちらは「対策ロール／対策ステータス合算／
  対策アイテム」の**いずれか1つを満たせば対策成立**という離散判定で、
  未対策なら被害が跳ね上がる（対策口を1つも持たないギミック定義は「対策不能」
  として常に未対策扱いになる＝ボス定義側の設定漏れを黙って握り潰さない）。
- **未対策ペナルティ：** 未対策1件につき危険度（`DangerLevel`）に比例して
  被ダメージ倍率が積み上がる（→ BAL: dungeon.csv
  `UncounteredDamageMultiplierPerDangerLevel`）。**即死級（InstantKill）を
  未対策で踏むとHPを全損する**＝無調査での突撃は壊滅する。
- **完全解析ボーナス：** 解析率100%（→ §4.5.2）で部隊火力（討伐の要求値との
  比較に使う値）に+20%の補正が乗る（`FullIntelDamageBonus`）。
- 討伐の成否は部隊火力（`DungeonPowerCalculator.PartyPower`＝各員の「実効ステータス×重み
  （→ BAL: dungeon.csv `BossPowerWeight_*`）＋装備の個人CPボーナス」×配置補正×HP比率の合計。
  2026年9月、旧クエストの討伐スコア式から同じ数値のまま移設。完全解析ボーナス適用後）とボスの要求火力（階層×係数、→ BAL: dungeon.csv
  `PartyPowerRequirementPerFloor`）の比較で決まる。**撃破（Victory）**か
  **撤退（Retreat）**の2択で、撤退時はボスのHPが回復し次回は仕切り直しになる。
- **HP下限0**（道中進軍・調査・採取はHP下限1）で、0に到達した
  冒険者は強制除籍（恒久ロスト、§4.3.1と同じ表現・扱い）になる。
  即死級ギミックを未対策で踏んだ場合は、乱数レンジを無視して固定でHP全損させる
  （対策の有無がそのまま生死を分ける）。
- **研究「魂魄安定の霊香」（`SurvivalThresholdBonus`、→ §4.6）が完了済みなら**、
  算出後のHP消費率（%）から完了分すべての合計EffectValueを%ポイントで差し引く
  （0未満にはしない）。即死級ギミック未対策時の全損（100%）にも適用されるため、
  事故を軽傷へ和らげる効果として働く。

#### パーティ携行アイテムポーチ（最大2枠、2026年9月新設）

対策口の3つ目「対策アイテム」（`BossGimmick.RequiredItemId`）をUIから実際に
編成できるようにする仕組み（→ `Party.ConsumableItemIds`、最大2枠・重複不可）。

- **対策アイテム4種（→ `Models.ConsumableCatalog`）。** カタログはこの4種が全件で、
  ギミック4種と1対1に対応する（`ConsumableItem.TargetGimmick`。旧・環境ギミックの相殺
  アイテムと効果アイテムは 2026年9月に撤去済み、→ §0.13）：

  | ギミック | アイテム | 価格 |
  |---|---|---|
  | 猛毒（Poison） | 解毒薬（`Antidote`） | 15G |
  | 重装甲（HeavyArmor） | 溶解液（`AcidFlask`、2026年9月新設） | 25G |
  | 飛行（Flying） | 捕縛網（`Net`、2026年9月新設） | 20G |
  | 即死級攻撃（InstantKill） | 身代わりの護符（`Charm`） | 20G |

- **指令時の費用徴収（2026年9月改訂）：** 扉前の部隊へ「挑む」を指令した時点で
  携行アイテムを積み込み、合計代金を`GameState.Gold`から即座に引き落とす
  （`DungeonExpeditionSystem.TryEngageBoss`→`CalculateConsumableCost`）。
  所持金が足りなければ指令自体が失敗し、部隊は判断待ちのまま残る。
- **返金：** 出発前の討伐出撃を取り消した場合（`TryCancel`）と、討伐に向かった
  ボスが既に他部隊に倒されていて決戦が行われなかった場合は、代金を全額返金する
  （判定が行われていないため何も失わない、という既存方針をゴールドにも適用）。
- **解決時の消費：** 討伐が解決すると、携行アイテムは勝敗・生死に関わらず
  すべて消費される（`DungeonResolver.Resolve`が`Party.ConsumableItemIds`を
  クリアする「使い切り」の扱い）。

### 4.5.5 探索（採取）任務（Gathering、v2.0内追加：第3の任務）

特定のボスではなく**フィールドそのもの**を対象にする低リスク経路
（`GatheringResolver`）。調査・道中進軍（隠密・解析、§4.5.3）と並び、
**HP下限1で止まり、致死判定には一切接続しない**。

- **常時出撃可能：** ボスの解析状況・到達階層に関わらず、フィールドが
  開放されてさえいれば出撃できる。フィールドを完全制覇（全10体撃破）した後も
  素材採取だけは継続できる。
- **採取スコア** ＝ (Σ(AGI×係数＋DEX×係数) ＋ 部隊長LDR×係数 ＋ 盗賊・斥候ボーナス)
  × 部隊の平均HP比率（→ BAL: gathering.csv）。調査・道中進軍と違い、消耗（HP比率）が
  スコアに直接効く＝弱った部隊は採取の効率も落ちる。
  **盗賊・斥候ボーナス（2026年9月新設）：** 部隊にThief（盗賊）・Ranger（斥候）が
  1名いるごとに、`GatheringBalance.ThiefRangerScoreBonus`をスコアへ加算する
  （地形の見極め・目利きに長けた職業という位置づけ）。
- **獲得素材：** `Max(1, 選ばれた素材のBaseYield ＋ 採取スコア÷係数 ＋ 到達階層÷係数)`
  個の、フィールド固有の素材を1種類獲得する（＋研究「特殊保存嚢」ボーナス、→ §4.6）。
  対象素材の抽選は**フィールドの到達階層(`ReachedFloor`)が素材のMinFloor以上**の
  ものだけが対象になり、その中から等確率で1種を選ぶ（→ `Balance.MaterialBalance`、下表）。
- **換金ゴールド：** 採取スコア×係数の少量のゴールドも同時に得る。
- HP消費は区分の区別なく一律（→ BAL: gathering.csv）。

## 4.6 アルベールの研究室（素材投資システム、v2.0内追加）

探索（採取、§4.5.5）で集めた素材と、通常のゴールドを投じて、恒久的な
インフラバフを獲得するシステム（`Systems.ResearchSystem`）。

- **二軸経済：** ゴールド（副官管轄：給与・雇用・退職金・施設投資）と
  素材（アルベール管轄：研究投資）を分離する。ゴールドは稼ぐほど増え続ける
  一方、素材は探索（採取）に出撃しなければ増えない専用資源として扱う。
- **研究プロジェクト（`ResearchDefinition`、→ BAL: research.csv。2026年9月改訂で
  レシピを新素材IDへ全面差し替え）：** 各プロジェクトは必要素材（複数種・個数）・
  必要ゴールド・効果種別・効果量を持つ。実行すると即座に完了し（乱数・週送りを
  介さない）、恒久的に効果が有効になる（`GameState.CompletedResearchIds`、
  同じ研究は一度しか実行できない）。

  | 研究 | 必要素材 | 必要ゴールド | 効果種別 | 効果 |
  |---|---|---|---|---|
  | 薬草湿布の調合（`res_herb_poultice`） | 月光草×5 | 200G | HpRecoveryBonus | 静養（§3.5）時のHP回復量に+15% |
  | 生体蛍光試薬（`res_scout_reagent`） | 変異胞子×3・霊樹の枝×3 | 300G | IntelRateBonus | ボス調査時の解析率獲得量に+25% |
  | 特殊保存嚢（`res_gathering_bag`） | 霊樹の枝×5 | 250G | GatheringYieldBonus | 探索（採取）の獲得個数に+1個（→ §4.5.5） |
  | 軽量踏破靴（`res_light_tread`） | 霊樹の枝×3・月光草×3 | 300G | TraversalBonus | 道中進軍の走破力スコアに+15加算（→ §4.5.3道中進軍） |
  | 硬化軟膏の調合（`res_cave_ointment`、2026年9月新設） | 発光苔×5・黒鉱石×2 | 500G | HpRecoveryBonus | 静養時のHP回復量にさらに+15%（薬草湿布の調合と合算） |
  | 古代戦術録の解読（`res_ruins_tactics`、2026年9月新設） | 遺物の欠片×6・ルーン石×3 | 800G | IntelRateBonus | ボス調査時の解析率獲得量にさらに+25%（生体蛍光試薬と合算） |
  | 耐熱踏破法（`res_canyon_tread`、2026年9月新設） | 火山灰×8・紅玉鉱石×4 | 1200G | TraversalBonus | 道中進軍の走破力スコアにさらに+20加算（軽量踏破靴と合算） |
  | 魂魄安定の霊香（`res_abyss_preservation`、2026年9月新設） | 虚空の粉塵×10・深淵の結晶×5 | 2000G | SurvivalThresholdBonus | ボス討伐のHP消費率から-5%ポイント（→ §4.5.4） |
  | 潤い美肌液の調合（`res_beauty_lotion`、2026年9月新設・§0.21） | 月光草×5・霊樹の枝×3 | 100G | SideBusinessGoldBonus | アルベールの内職の基本売上+150G（→ §8.1） |
  | 滋養強壮アンプル（`res_energy_tonic`、同上） | 発光苔×5・黒鉱石×3 | 200G | SideBusinessGoldBonus | 内職の基本売上+250G |
  | 古代香料の王都外販（`res_trade_route`、同上） | 遺物の欠片×6・ルーン石×3 | 300G | SideBusinessGoldBonus | 内職の基本売上+400G |
  | 不老長生薬の密売（`res_vitality_elixir`、同上） | 火山灰×8・紅玉鉱石×4 | 500G | SideBusinessGoldBonus | 内職の基本売上+600G |

  > **EffectValueの意味は種別ごとに統一されている**：HpRecoveryBonus・IntelRateBonus・
  > GatheringYieldBonus・TraversalBonus・SurvivalThresholdBonusのいずれも「既存の値に
  > 足し込む加算率／加算量」として扱う（IntelRateBonusは2026年9月改訂で、直接倍率
  > (×1.25)から(1+EffectValue)倍の加算率方式へ統一した）。
  >
  > **同種研究の合算（2026年9月改訂）：** 同じ効果種別の研究が複数完了している場合、
  > 各Resolver（RestRecoverySystem・ScoutingResolver・DungeonTraversalResolver・
  > GatheringResolver・DungeonResolver）は`Balance.ResearchBalance.GetTotalEffectValue`
  > で完了済み研究のEffectValueを効果種別ごとに合算して適用する（例：薬草湿布の調合＋
  > 硬化軟膏の調合が両方完了していれば、HP回復ボーナスは+15%+15%＝+30%になる）。
  > 以前は研究Idを1つだけ固定でチェックしていたため、同種の研究が複数存在すると
  > 2つ目以降が反映されない不具合があった。
  >
  > **内職強化研究（`SideBusinessGoldBonus`、2026年9月新設・§0.21）：** 採取素材を「固定収入」へ
  > 投資する系統。EffectValue（G）を内職売上の初期基本額200Gへそのまま加算し、その合計に
  > マスターの機嫌の売上倍率を掛ける（→ §8.1、`EconomySystem.ProcessWeeklySideJobIncome`）。
  > 4段階とも加算で重複でき、全完了で基本額1600G（200+150+250+400+600）になる。

- **研究実行の判定（`ResearchSystem.CanStartResearch` / `CompleteResearch`）：**
  必要素材・必要ゴールドの両方を満たし、かつ未完了の研究のみ実行できる。
  実行すると素材・ゴールドが減算され、`CompletedResearchIds` に登録される。
  既存セーブとの互換性は、`CompletedResearchIds`（`HashSet<string>`）が
  未定義のセーブでは空集合として補完されることで担保する（新規追加フィールド
  につき、§10.1のCSV欠損時例外とは別枠。JSONデシリアライズのデフォルト値補完）。

## 4.7 未鑑定遺物と鑑定システム（レリック、v2.0内追加）

大迷宮から「**中身の分からない古代の遺物**」を持ち帰り、アルベールに鑑定費用を払って
中身を確定させるシステム（`Systems.AppraisalSystem`）。素材投資（§4.6）が
「計画的に貯めて使う」経路なのに対し、こちらは「掘って開けて一喜一憂する」ハクスラ的な
短周期の報酬ループを担う。

### 4.7.1 データモデルと希少度

- **希少度（`ItemRarity`、4段階）：** `Common`（銅）／`Rare`（銀）／`Epic`（金）／
  `Legendary`（虹）。鑑定費用・鑑定結果の比率・換金額・獲得個数・武具の抽選プールは
  すべて希少度で決まる（→ BAL: relic.csv、`Balance.RelicBalance`）。

  | 希少度 | 鑑定費用 | 武具率 | 素材率 | 換金率 | 換金額 | 素材個数 |
  |---|---|---|---|---|---|---|
  | 銅（Common） | 100G | 30% | 50% | 20% | 60〜160G | 1〜3個 |
  | 銀（Rare） | 250G | 40% | 40% | 20% | 180〜420G | 3〜6個 |
  | 金（Epic） | 500G | 50% | 30% | 20% | 420〜900G | 6〜10個 |
  | 虹（Legendary） | 1200G | 60% | 25% | 15% | 1100〜2600G | 10〜18個 |

  > 銅は鑑定費用（100G）に対して換金額が下回ることもある＝**必ず儲かる訳ではない**。
  > 深く潜って良い遺物を持ち帰るほど期待値が上がる、という設計。

- **未鑑定遺物（`Models.UnidentifiedItem`）：** 仮称（「？？？ 苔むした封印箱」等、
  希少度ごとの名前プール → `Models.RelicNames`）・希少度・**出土地**（`OriginFieldId`）・
  **出土階層**（`OriginFloor`）・鑑定費用を持つ。中身の情報は一切持たず、
  鑑定を実行した瞬間に抽選される。在庫は `GameState.UnidentifiedItems`。
- **鑑定結果（`Models.AppraisalResult`）：** 種別（`Equipment`／`Material`／`Gold`）と、
  種別に応じた中身（武具の現物・素材Idと個数・獲得ゴールド）、およびアルベールの
  鑑定コメント（`FlavorText`）を持つ結果DTO。
- **ギルド保管庫（`GameState.Armory`、`Models.EquipmentItem`）：** 鑑定で出土した武具の
  「個体」を積む在庫。既存の `Item`（→ §4.2.2）はカタログ定義であり同じ武具を2本持つ状態を
  表現できないため、カタログIdを指す個体として `EquipmentItem`（個体Guid・カタログId・
  表示名・入手週・入手経路）を新設した。冒険者側は従来どおりカタログIdの文字列のみを
  持つ（→ `Adventurer.EquippedWeaponId`）ため、保管庫は「在庫」専用で装備状態は表現しない。

### 4.7.2 ドロップ（出土）

希少度は共通のロールで決まる：**1〜100の乱数 ＋ 出土階層÷10 ＋ 任務ボーナス**を
閾値（銀60／金85／虹100）と比べる（→ `RelicBalance.RollRarity`）。深く潜るほど
良い物が出る、という単調な設計に揃えてある。

- **探索（採取）任務（→ §4.5.5、`GatheringResolver`）：** 確率ドロップ。
  ドロップ確率＝**基礎5%** ＋ 採取スコア（DEX/AGI/隊長LDR由来）÷40 ＋ 到達階層÷20 を
  **上限15%** でクランプする。任務ボーナスは無し（＝浅い階層では実質すべて銅）。
  週報ログに「【遺物発見】未鑑定の古代遺物を持ち帰った！」を出力する。
- **階層ボス討伐（→ §4.5.4、`DungeonExpeditionSystem`）：** **撃破成功時の確定ドロップ**。
  希少度ロールに **+25** のボーナスが乗り、さらに**最低保証は銀（Rare）**。
  撤退・全滅では出ない。撃破報酬（ゴールド・確定素材）とは別枠で加算される。
- 出土した遺物は、素材・拾得ゴールドと同じく**週次決算で `GameState.UnidentifiedItems` へ
  積まれる**（各Resolverは結果DTOに記録するだけでGameStateを書き換えない、という既存方針に従う）。

### 4.7.3 鑑定（`AppraisalSystem`）

- `CanAppraise(state, itemId)`：対象が在庫に存在し、かつ `state.Gold >= AppraisalCost` か。
- `Appraise(state, itemId)`：鑑定費用を引き落とし、在庫から取り除き、中身を抽選して
  ギルド資産へ反映し、`AppraisalResult` を返す。対象が無い・資金不足なら**何もせず null**
  （`Try*` 系と同じ流儀。1Gも引かれず在庫も減らない）。研究（§4.6）と同じく
  **週送りを介さない即時処理**。
- 中身の抽選：
  - **武具** → 希少度ごとの抽選プール（`EquipmentPool*`、ItemCatalogのId列）から1点。
    `state.Armory` へ格納する。
  - **素材** → **遺物の出土地・出土階層**で抽選対象になる素材（→ `MaterialBalance.
    GetEligibleMaterials`、materials.csv が正本）から1種。個数は希少度の幅から。
    `state.AddMaterial` で加算する。
  - **換金** → 希少度の幅から1つ引いて `state.Gold` へ加算（表示名は「古代硬貨」）。
  - 出土地に素材定義が1件も無い場合（未定義のフィールドId等）は、遺物が無に帰さないよう
    **換金へ振り替える**（防御的フォールバック）。
- **セーブ互換性：** `UnidentifiedItems`・`Armory` はいずれも新規追加フィールドのため、
  これらを持たない旧セーブでは JSON デシリアライズのデフォルト値（空リスト）で
  自然に補完される（→ §12）。

### 4.7.4 UI（InventoryPanel、中央ペイン「倉庫・遺物」タブ）

ナビゲーションバーの `[ 📦 倉庫・遺物 ]`（`%NavWarehouseBtn`）から開く。他の内政画面と同様、
開いている間は作戦週報（右ペイン）を非表示にして全幅（約1900px）で表示する（→ §9）。
3つのタブで構成する：

1. **`[ 📦 未鑑定遺物 ]`（2ペイン構成）**
   - 左ペイン：所持している未鑑定遺物の一覧（希少度の色分け・仮称・出土地と階層・鑑定費用。
     資金不足の行は「（資金不足）」を併記）。上部に所持金と希少度ごとの内訳を表示する。
   - 右ペイン：選択した遺物の詳細（希少度・出土地・鑑定費用・**中身の見込み**＝武具/素材/換金の
     比率と、素材・換金だった場合の幅）、アルベールのコメント欄、
     `[ 🔬 アルベールに鑑定させる（○○G） ]` ボタン。
   - **資金不足時はボタンをDisabled化**し、文言を「🔬 鑑定費用が足りない（○○G 必要）」に変える。
   - 鑑定実行時は、コメント欄に獲得アイテム名とアルベールの台詞を演出表示し、
     一覧・所持金・ヘッダーの素材サマリーをまとめて再描画する（週報ログにも記録する）。
2. **`[ 🌿 採取素材一覧 ]`**：全5フィールドの素材を、フィールドごとに在庫数・採取可能階層・

## 4.8 売却（在庫の換金、v2.0内追加）

ギルド保管庫の余剰武具（→ §4.2.2）と採取素材（→ §4.5.5）を、資金（Gold）へ換える経路。
遺物の鑑定（§4.7）と離脱時の装備回収（§4.2.2）によって在庫が一方的に増え続けるため、
「使わない物を捌いて次の投資に回す」出口としてこれを用意する。UIは
「倉庫・遺物」画面（→ §4.7.4）の素材タブ・保管庫タブに組み込む。

### 4.8.1 素材の売却（`EconomySystem.TrySellMaterial`）

- 単価は素材ごとに `materials.csv` の **`SellPrice` 列**で定義する（2026年9月追加、
  → `MaterialBalance.GetSellPrice`）。深いフィールドの素材ほど高い
  （月光草8G／霊樹の枝12G／変異胞子25G／発光苔10G／黒鉱石30G／遺物の欠片12G／
  ルーン石35G／火山灰14G／紅玉鉱石45G／虚空の粉塵20G／深淵の結晶70G）。
- `TrySellMaterial(state, materialId, count, out totalGold)`：`count`個を在庫から減らし、
  `SellPrice × count` を所持金へ加算する。以下は**在庫・所持金を一切動かさず** false：
  `count` が0以下／在庫が無い・足りない／`materials.csv` に定義が無い素材Id。
- 在庫がちょうど0になった素材は辞書からキーごと取り除く（「未所持の素材はキー自体が
  存在しない」という `GameState.Materials` の不変条件に合わせる）。
- 研究（→ §4.6）で使う素材を売り払うか貯めておくかが、素材経済のトレードオフになる。
  素材タブは各素材の**用途（必要とする研究名と個数）**を併記し、売る前に判断できるようにする。

### 4.8.2 武具の売却（`EquipmentSystem.TrySellEquipments`）

売却額は個体の出自で2系統に分かれる（→ `EquipmentSystem.GetSellPrice`）：

| 個体の種別 | 判別 | 売却額 |
|---|---|---|
| カタログ品（無銘） | `EquipmentItem.Rarity` が null | カタログ**定価の50%**（端数切り捨て、→ BAL: equipment.csv） |
| 鑑定で出土した個体 | `Rarity` あり（→ §4.7） | 希少度ごとの基準額（銅50G／銀125G／金250G／虹600G、→ BAL: relic.csv `SellPrice*`） |

- カタログ品は買い直せるので目減りする。鑑定品は定価と無関係に希少度だけで決まる
  （「掘り出し物」としての価値）。カタログから引けない個体（カタログから消えた武具の
  旧データ）は0G＝売っても1Gにならない。
- `TrySellEquipments(state, itemIds, out totalGold)`：個体Idの並びを受け取り、**全か無か**で
  判定する（一部だけ売れて残りが失敗する半端な状態を作らない）。以下は false：
  指定が空／同じ個体Idの重複／保管庫に無い個体Idが含まれている。
- **「装備中の武具は売れない」は保管庫の在庫判定で自然に担保される**（装備中の個体は保管庫から
  抜けている、という§4.2.2の不変条件）。念のため現役・引退・除籍の全ロースターの装備枠とも
  突き合わせて二重に弾く。
- **武具の解体（素材への還元）は実装しない。** 古代の武具を打ち直して素材に戻す技術は
  この世界のギルドには無い、という整理（売るか、使うか、抱えるかの3択に絞る）。

### 4.8.3 UI（→ §4.7.4 倉庫・遺物画面）

- **素材タブ：** 各素材行に単価（○G/個）を表示し、`[ 💰 1個売却 ]` `[ 💰 全売却（N個） ]`、
  数量指定スピンボックス（初期値 `Math.Min(10, 在庫数)`、範囲 1〜在庫数）＋
  `[ 💰 指定数売却 ]` を置く。在庫0の素材は操作部をすべて無効化する。
- **保管庫タブ：** 誤売却の事故を防ぐため、在庫を2カテゴリに分けて表示する。
  - **🔧 汎用武具（まとめ売り可）：** カタログ品（無銘）と銅・銀の鑑定品。
    **同じカタログId・同じ希少度**ごとにまとめ（例「鉄の剣［無銘］×3」）、素材と同じ
    1個／全数／数量指定の操作部を置く。希少度も鍵に含めるのは、同じ鉄の剣でも
    カタログ品と鑑定品では単価の系統が違い、群の中で単価が一様でなくなるため。
  - **💎 希少武具（1点ずつ）：** 金・虹の鑑定品。**グルーピングせず1行ずつ独立表示**し、
    `[ 💰 売却（○○G） ]` の1個売却ボタンのみを置く（まとめ売り・数量指定は用意しない）。
- 売却するとその場で在庫・所持金・ヘッダーの素材サマリーが再描画され、週報ログにも
  「💰 ○○ ×N を売却し、○○ G を得た。」が記録される。

## 5. クラブ運営・人事マネジメント

### 5.1 満足度（Satisfaction）変動ロジック

毎週日曜の決算時に増減（各係数 → BAL: 満足度）。

- 出場機会：**全盛期（23〜26歳）** が「4週連続で遠征なし」なら毎週 -5
  （対象年齢は → BAL: satisfaction.csv `OpportunityPenaltyMinAge`／`MaxAge`。
  年齢帯の3区分化に合わせた整合は → §0.12。22歳以下は育成猶予として対象外）
- 賃金妥当性：実力ランクに対し週給が適正値の80%未満なら毎週 -8
- 人間関係：相性「険悪」（→ §5.3.1）のメンバーと同パーティ出撃で -10
  （v1.4改訂で接続済み）
- 勝利・功績（2026年9月、大迷宮の任務成果へ再配線。`SatisfactionSystem.ApplyExpeditionSatisfaction`、
  → BAL: satisfaction.csv `Satisfaction_*`）：任務の週次解決時に、部隊の生存者（現役ロースターに残り、
  HPが1以上の者）へ適用する。強制除籍者には適用しない。満足度は0〜100にクランプする。

  | 任務成果 | 変動 |
  |---|---|
  | 階層ボス撃破 | +10 |
  | ボス戦で撤退・敗退 | -5 |
  | 迷宮調査：護衛「余裕」／「十分」／「充足」／「不足」（潰走） | +2／+1／0／-5 |
  | 道中進軍で1階層以上進み生還した週 | +1 |
  | 採取で素材を持ち帰れた時（取れなければ変動なし） | +1 |

  扉前での偵察（指令待ちのまま週を越した場合）は対象外。ボス戦で強制除籍者が出た場合、生存者には
  下記「仲間ロストの余波（-30）」と撃破／撤退の変動が加算で重なる。旧通常クエストの
  「Bランク以上のクエスト達成で+10」（`VictoryBonus`）は、この表の「階層ボス撃破」に置き換えた。
- 仲間ロストの余波：同パーティの死亡で一律 -30（v1.2改訂で接続済み。→ §4.3.1）
  ＋確率でトラウマ特性付与（v1.4改訂で接続済み。→ §5.3.1・§5.3.2）
- 自然回復：酒場 Lv により毎週 +（→ §6）

### 5.2 契約交渉と退団

- 満足度20未満でインボックスに「昇給要求」または「移籍検討」警告。
- 2週以内に昇給（週給 1.5〜2.0倍提示）またはボーナスを行わなければ自発的に契約解除・他都市へ移籍（消滅）。

### 5.3 相性・特性システム

### 5.3.1 相性（Compatibility）

- 冒険者2人1組ごとに相性値（0〜100）を持つ。初回に同じパーティへ
  編成された時点で初期値50（中立）から開始する。
- 変動（→ BAL: 相性、`compatibility_advisor.csv`）：
  - **大迷宮の任務達成による上昇（2026年9月再配線・§0.22、`CompatibilitySystem.ApplyExpeditionOutcome`）：**
    同じ部隊で任務を達成して生還した時、**生還者同士の全ペア**の相性を加算する（上限100）。
    強制除籍でロースターを離れた者とのペアは対象外。

    | 任務 | 達成の条件 | 上昇量 |
    |---|---|---|
    | 階層ボス討伐（BossAssault） | ボスを撃破 | **+3**（`ExpeditionGain_BossVictory`） |
    | 道中潜行（Scouting） | その週に1階層以上進軍 | **+1**（`ExpeditionGain_Traversal`） |
    | 迷宮調査（Survey） | 護衛判定「不足」（潰走）以外で帰還 | **+1**（`ExpeditionGain_Survey`） |
    | 探索採取（Gathering） | 素材を1個以上持ち帰る | **+1**（`ExpeditionGain_Gathering`） |

    達成できなかった場合（撤退・潰走・進軍なし・素材なし）は上昇も下降もしない。扉前での偵察は対象外。
    週報の各任務ログに `【部隊の結束】共闘により隊員間の相性値が向上 (+N)` を出す。
  - 同パーティのメンバーが強制除籍（戦死扱い、→ §4.5.4）された場合、居合わせた生存者同士の相性は
    大きく下降（トラウマ的な体験として扱う、`DeathWitnessLoss`）。
  - 旧来の「クエスト達成で上昇／苦戦敗退・戦線崩壊で下降」（`AchievementGain`・`FailureLoss`）は、
    旧クエストの撤去で呼び出し元を失い、相性が下がる一方になっていたため廃止した（→ §0.22）。
- 相性値が **30未満** で「険悪」と判定し、§5.1の満足度ペナルティ
  （相性険悪のペアと同パーティ出撃で毎週-10）が発動する。
- 「容姿秀麗」特性（§5.3.2）を持つ者が関与するペアは、**上昇量のみ**
  倍率がかかる（下降量には影響しない）。

### 5.3.2 特性（Trait）カタログ（v1.3時点）

| 特性 | 種別 | 付与条件 | 効果 |
|---|---|---|---|
| 古傷 | 後天的 | 致死判定の不可逆障害域（§4.3） | STR/VIT/AGI/DEX割合低下 |
| トラウマ | 後天的 | 戦死現場に居合わせた生存者に確率付与 | MND割合低下 |
| 豪胆 | 先天的 | 採用時に低確率付与 | SurvivalThresholdに固定ボーナス |
| 注意深い | 先天的 | 採用時に低確率付与 | 索敵フェーズのDEX寄与+10% |
| 容姿秀麗 | 先天的 | 採用時に低確率付与 | 関与する相性ペアの上昇量に倍率 |
| 田舎育ち | 先天的 | 採用時に低確率付与 | 採取任務の採取スコアに個人ボーナス（+20%） |
| 知識人 | 先天的 | 採用時に低確率付与 | 単独効果は最小限。豪胆とのペアで護衛に負のシナジー |

- **田舎育ち**（2026年9月再設計・§0.22）：探索採取（→ §4.5.5）の採取スコアに個人ボーナスを加算する。
  保有者本人の採取寄与（AGI×係数＋DEX×係数）の **+20%**（`trait.csv` `CountryBredGatheringBonusRate`、
  `TraitEffectType.GatheringScoreBonus`）を採取スコアへ上乗せし、HP比率はその後に掛ける
  （→ `GatheringResolver.CalculateRuralBonus`）。出撃前プレビューに `部隊採取力: {score} pt (基礎: {base} + 田舎育ち: +{bonus}pt)`、
  週報の【探索採取】に「うち田舎育ちボーナス+N」を開示する。旧効果（探索クエストのスコア加算）は
  旧クエストの撤去で参照先を失っていた。特性Id（`CountryBred`）はセーブ互換のため据え置く。
- **知識人**：単独での効果は最小限。「豪胆」とのペアで護衛クエストに
  負のシナジーを持つ（→ §4.2.3）。

各種確率・効果量は → BAL: 特性 に集約。「頑強」「師匠肌」等は
post-MVP（→ §11）。

## 6. 施設・インフラ拡張（9施設 Lv0〜5 または Lv1〜5）

- **Lv0の施設は、該当する訓練枠・顧問スロットが存在しない（0扱い）。**
  Lv1に到達して初めて、既存ルール（訓練枠1名等）が適用される。

旧「訓練場・道場（単一施設）」は、戦士訓練所・教会・魔法研究所・
斥候所の4つの専門施設に分割された（v1.3改訂）。各施設は独立した
訓練枠（Lv0で0名・Lv1で1名、Lv上昇で開放）を持つ。経路2（訓練場配置
による成長、§3.1〜3.4）の対象ステータスは、配置先施設が扱う
ステータスに限定される。

各 Lv の効果・**改築費**は → BAL: 施設。
（v1.0 の Lv1/3/5 の効果値を土台に、Lv2/4 の中間値と全 Lv の費用を BAL 側で補完する。）

### 6.1 建設（Lvアップ）の仕組み（新規定義）

- Lvアップは即時ではなく、**着工→N週間の工事期間→完成**という時間経過を
  要する（Nは施設・対象Lvごとに → BAL: 施設/工事期間）。
- 改築費は着工時に前払い（着工時点で資金から差し引く）。
- **同時着工は1件のみ。** 他の施設（9施設全体）が工事中の間、新たな着工は
  できない（単一の建設キュー）。
- 工事中も、現在のLv（着工前のLv）の効果はそのまま維持される。
- 完成した週の決算処理でLvが+1され、新しいLvの効果が即座に適用される。

## 7. 引退とセカンドキャリア（顧問制度）

- **引退の経路：** 26歳での満期引退（§3.7）に加え、プレイヤーが
  任意のタイミングで満期前の現役冒険者を早期引退させることもできる。
  どちらの場合も退職金（週給×12週＋累積功績×係数）を一括支給する（→ §3.7）。
- 引退した冒険者は「顧問候補」として保持され、以下のいずれかの
  役職に任意で任命できる（任命しなくてもよい）。

### 7.1 教官（Trainer）

- 戦士訓練所・教会・魔法研究所・斥候所、各施設に1名まで配置できる
  （計4名まで）。配置はプレイヤーの手動操作。
- 効果：配置先施設の対象ステータス（1つまたは2つの平均）の
  **引退時の実効ステータス**に比例して、その施設で訓練中の者への成長ボーナス
  （成長ロール確率または成長量への加算、→ BAL: 顧問/教官伝授）が
  発生する。「得意ステータスの一致判定」は行わない
  （施設の対象ステータスにおける実効値の高さがそのままボーナス量になる）。

### 7.2 作戦参謀（Advisor）

- 作戦資料室に1名まで配置できる。
- 効果：**引退時の実効ステータス7能力（STR・VIT・AGI・DEX・INT・MND・LDR）の平均**に比例した支援ボーナスを大迷宮攻略の2大局面に付与する（2026年9月再配線、→ BAL: compatibility_advisor.csv）：
  1. **迷宮調査（作戦分析ボーナス）：** `ScoutingResolver` におけるボス解析率の上昇量に、7能力平均×`Advisor_SurveyIntelBonusCoeff`（0.002、平均50で+10%）を加算（研究ボーナスの `IntelRateBonus` と合算され、基礎解析率×(1＋研究ボーナス＋参謀解析ボーナス)×護衛倍率 となる）。
  2. **道中潜行（ルート指導ボーナス）：** `DungeonTraversalResolver` における部隊走破力スコアに、7能力平均×`Advisor_TraversalPowerBonusCoeff`（0.2、平均50で+10pt）を直接加算（研究ボーナスと並列して加算される）。出撃前の `PartyFormationPanel` や `DungeonPanel` のプレビューにもリアルタイムに反映される。
  - 週報ログにも支援した参謀の名前とボーナス効果（解析支援・進軍支援）が表示される。未任命の場合はボーナス0。

### 7.3 スカウト（Scout Master）

- **冒険者支援室に1名まで配置できる。** 冒険者支援室がLv0（未建設）の
  間は配置できない。
- 効果：引退時の実効ステータスのLDR・DEX平均に比例したボーナスを、新人応募率に
  加算する（既存どおり。能力値そのものへの補正ではない）。既存の
  「総合PA75以上の新人応募率+25%」はスカウト未配置時の基礎値として
  維持し、配置時はここに個人ボーナスが上乗せされる。

### 7.4 保有枠との関係（既存決定を維持）

- 顧問は宿舎の保有枠（現役枠）を占有しない。顧問は各施設の専用スロット
  （教官枠・参謀枠・スカウト枠）にのみ入る。

## 8. 勝敗判定条件

### 8.1 マスターの機嫌（`MasterMood`、2026年9月改訂：名声・ギルド格付けを廃止）

> **2026年9月改訂（→ §0.20）：** 旧来の **名声（Reputation）**・**ギルド格付け（G〜S、
> `GuildRankSystem`／`guild_rank.csv`・`guild_rank_params.csv`）**・**公的な月次助成金
> （`SubsidySystem`）** は、世俗的な評判で動く仕組みが世界観（ギルドはマスター・アルベールの
> 私設組織で、プレイヤーはその副官）に合わないため**すべて廃止**した。代わりに
> 「マスターの機嫌」と「アルベールの市販薬・内職売上」を置く。

- ギルドは **マスターの機嫌（`GameState.MasterMood`）** 整数（**0〜100**、初期値 **50**）を持つ。
  常に 0〜100 にクランプする（→ `MasterMoodSystem.Adjust`、BAL: `master_mood.csv`）。
- **上昇要因（大迷宮での成果、週次決算で集計）：**
  - 階層ボス撃破：**+20**（1体ごと、`BossDefeatMoodGain`）
  - 道中潜行での新階層開拓：進軍した**未踏破階層数 × +2**（`PioneerMoodPerFloor`、
    → `TraversalResult.UnexploredFloorsAdvanced`）
  - 迷宮調査：護衛判定「余裕」「十分」で帰還時 **+3**（`SurveySuccessMoodGain`）。
    「充足」は増減なし（解析は進むため成果には数える）。潰走（「不足」）は **−3**（`SurveyRoutedMoodLoss`）
  - 探索採取：素材を1個以上獲得して帰還時 **+2**（`GatheringMoodGain`）
  - 未鑑定遺物の鑑定完了：**1個につき +1**（`AppraisalMoodGain`。週次決算を待たず即時。
    大迷宮での成果には数えない＝退屈減衰は防がない）
  - 扉前待機中の偵察：増減なし（護衛判定が「不足」でなければ成果には数える）
- **低下要因：** 退屈減衰（→ §8.1.1）、満期引退で退職金を払いきれなかった場合 **−15**
  （旧・名声低下の置き換え、`economy.csv` `SeveranceShortfallMoodPenalty`）、
  強制除籍へのアルベールの激怒 **除籍1名につき−20**（→ §8.1.1、2026年9月新設・§0.21）。
- **機嫌の段階と内職売上倍率（`MasterMoodSystem.GetTier`）：**

  | 機嫌 | 段階 | 内職売上倍率 |
  |---|---|---|
  | 80〜100 | 上機嫌（Cheerful） | ×1.5 |
  | 50〜79 | 平常（Normal） | ×1.0 |
  | 20〜49 | 不機嫌（Grumpy） | ×0.5 |
  | 1〜19 | 危機（Crisis） | ×0.0 |
  | 0 | — | 副官解雇（→ §8.3） |

- **アルベールの市販薬・内職売上（`EconomySystem.ProcessWeeklySideJobIncome`、旧・月次助成金）:**
  4週に1回（`SideJobIntervalWeeks`）、**(初期基本額 200G ＋ 内職強化研究の加算) × 決算時点の機嫌の
  売上倍率**を入金する（初期基本額は `SideJobBaseAmount`。旧・格付けGの助成金を流用。研究の加算は
  `SideBusinessGoldBonus` の合計、→ §4.6、2026年9月新設・§0.21）。週次決算では機嫌の変動を先に
  済ませてから売上を計算する（→ `WeekProcessingSystem.ProcessWeek`）。
- **表示（→ §4.2.3 特記事項）：** ヘッダーに `マスターの機嫌: {機嫌}/100 ［{段階} 内職×{倍率}］`。
  週報に `【マスターの機嫌】現在: {機嫌}/100 (今週の変動: {±N} / {理由の内訳})［{段階}］` と、その末尾に
  段階ごとのアルベールの一言（→ §8.1.1）、
  `【アルベールの内職】市販薬売上: +{入金}G (基本 {基本額}G［初期200+研究{加算}］ × 機嫌倍率 {倍率}［{段階}］)` を出す
  （例：`+525G (基本 350G［初期200+研究150］ × 機嫌倍率 1.5［上機嫌］)`）。

### 8.1.1 退屈減衰（2026年9月改訂：旧・名声の自然減衰）

- 当週に大迷宮での成果（新階層開拓・有効な調査・採取成功・ボス撃破、→ §8.1）が
  **1件もなかった**場合（全員待機、または調査の潰走・全滅・撤退のみ）、
  `WeeksSinceLastGuildActivity`（最終活動成果からの経過週数）を +1 し、
  マスターの機嫌を **−5**（`BoredomMoodDecay`）減衰させる。週報に
  「大迷宮での成果がなく、アルベールは退屈して機嫌を損ねている (機嫌 -5)」と明記する。
- 成果が1件でもあった週は `WeeksSinceLastGuildActivity` を 0 にリセットする。
- 旧来の名声の自然減衰は「現ランク相当のクエスト達成」でしかリセットできず、旧クエストの
  撤去以降は毎週無条件に減衰していた（リセット不能）。本改訂でリセット条件を大迷宮での成果へ
  付け替えた。旧キー `WeeksSinceLastRankAppropriateQuest` は `WeeksSinceLastGuildActivity` へ
  改名し、旧セーブの値は引き継ぐ（→ §12）。
- **研究連動の内職売上（2026年9月新設・§0.21）：** 採取素材を内職強化研究（→ §4.6、
  `SideBusinessGoldBonus`）へ投じると、内職売上の基本額が恒久的に上がる（+150／+250／+400／+600G、
  全完了で1600G）。機嫌の売上倍率は研究で上がった基本額にも掛かるため、機嫌を保つほど研究投資の
  見返りが大きくなる（危機×0.0では研究済みでも入金0）。
- **現場除籍への激怒（2026年9月新設・§0.21）：** ボス討伐等で隊員がHP0となり、アルベールの不死薬で
  一命は取り留めたものの現場から永久離脱（強制除籍、→ §4.5.4）した場合、**除籍1名につき機嫌−20**
  （`master_mood.csv` `ForcedRetirementMoodLoss`、下限0）。ボス戦の解決の時点で即座に反映し
  （→ `MasterMoodSystem.ApplyForcedRetirementFury`）、週報の決戦ログに
  `【アルベールの激怒】「うちの子に何て無茶をさせたの！ あなた、自分が何をしたか分かっているの!?」 (機嫌 -20)`
  を出す。週次の機嫌内訳（【マスターの機嫌】）にも「アルベールの激怒（除籍N名×20）」として載る。
  これで機嫌が0に達すれば、その週の決算で副官解雇（→ §8.3）になる。激怒は成果には数えない
  （撃破と同時に除籍者が出た場合、撃破の+20と激怒の−20は両方適用される）。
- **段階ごとのアルベールの一言（2026年9月新設・§0.21、`MasterMoodSystem.GetAlbertLine`）：**
  週報の【マスターの機嫌】行の末尾に付ける。

  | 段階 | 一言 |
  |---|---|
  | 上機嫌（80〜100） | 「ふふ、いいデータが届いたわ。今夜は気分がいいから調合も捗るわね」 |
  | 平常（50〜79） | 「順調ね。次も期待しているわよ、副官」 |
  | 不機嫌（20〜49） | 「……はあ。退屈ね。薬の注文なんて放っておいて頂戴、気分じゃないの」 |
  | 危機（1〜19） | 「ねえ副官、あなた本当に私の役に立っているのかしら？ 次はないと思いなさい」 |

### 8.2 勝利条件（未定・構想段階）

- **勝利条件は現時点で未定。** 「20年でSランク到達」「第960ターン到達」
  という当初案はいずれも撤回した（→ §1.2）。**期限による勝敗判定は
  無い。**
- **想定している方向性：** 最終討伐クエスト（魔王戦、仮称）のクリアを
  勝利条件とする。通常のクエスト（§4.0）とは別枠の、一度きりの特別な
  クエストとして構想している（出現条件・難易度・専用の解決ロジック等、
  詳細は未設計）。
- **最終討伐解禁フラグ（`FinalQuestUnlocked`、v1.10改訂で新設）：**
  「最終討伐クエストの依頼が持ち込まれるようになった」ことを示すフラグ。
  **最終フィールド（深淵）の100Fボスを撃破した時点**で立ち、以後は取り消されない
  （→ `DungeonExpeditionSystem.ApplyFieldProgression`）。旧来の「ギルド格付けが初めて
  Aランク以上に到達した時点」の経路は、格付けの廃止（2026年9月、→ §8.1・§0.20）に伴い撤去した。
  **最終討伐クエスト自体の中身（出現条件・難易度・専用ロジック）は今回実装しない。**
- 詳細設計は、ゲーム全体のバランス・ゲーム性（Phase 3全体の実装・
  実機プレイを経た上での調整方針）が固まってから行う。
- **現時点では勝利判定を一切実装しない。**

### 8.3 敗北条件（成立した週の終了時に即時敗北）

- **副官解雇（2026年9月新設、`DefeatReason.DismissedByMaster`）:** 週次決算の時点で
  マスターの機嫌（§8.1）が **0** に達していれば、猶予なく即時敗北
  （退屈減衰・潰走・退職金不足のいずれで0になっても同じ）。破産と同じ週に成立した場合は
  副官解雇を優先する（→ `DefeatSystem`）。
- **破産:** 週次決算で所持金マイナスが **4週連続**で解消されない
  （4週間の猶予あり）。
- ~~**治安崩壊:** 脅威度が100%に到達した週の決算時点で、猶予なく即時敗北
  （破産のような連続週数のカウントは行わない）。~~
  **→ 2026年9月改訂で撤廃。** 敗北条件を経営破綻（資金ショート）のみへ
  純化した。`DefeatReason.SecurityCollapse` 自体は列挙子として削除して
  いない：この理由で既に敗北していた旧セーブをロードした際、ParseEnumが
  未知の値で例外を投げないようにするため（→ §12のセーブ互換性方針）。
  新規にこの理由で敗北が確定することはもう無い（→ `DefeatSystem`）。
- **期限（960ターン到達等）による敗北は無い**（→ §1.2）。敗北条件は
  上記の副官解雇と経営破綻（破産）の2つ。

#### 確定済みの世界観連動仕様（実装済み）

以下は構想ではなく、既にコードへ反映済みの確定仕様である。

**1. 女性限定ギルド（構造的に保証）**

コンセプト上の「女性限定」を、設定値ではなく**型の構造**で保証している。

- `Models.Gender` は `Female` のみを持つ（`Male` は削除済み）。
- `NameGenerator` から男性名プール（旧 `WesternMaleNames` / `EasternMaleNames`）と
  性別の抽選（旧 `RollGenderAndCulture`）を撤去し、抽選対象は文化圏のみ（`RollCulture`）。
- バランス値 `MaleGenderChancePercent` は `recruitment.csv` から削除済み。

> 経緯：当初は `MaleGenderChancePercent = 0`（出現率0%）で女性限定を表現していたが、
> それでは**CSVの値を書き換えるだけで男性が復活してしまう**状態だった。
> 「今後も男性冒険者が登場する予定は無い」という決定を受け、復活の余地そのものを
> 構造から取り除いた。この改訂により、既存のセーブデータとの互換性は失われている
> （性別の列挙値が変わったため。互換維持は不要との判断）。

**2. 8年稼働・26歳満期引退モデル（衰微の廃止）**

アルベールの信念（「危険な冒険者は若く美しい全盛期のうちに引退させ、十分な退職金を
持たせて安全に自立させるべき」→ 01_コンセプト.md）をシステム化したもの。

- **加齢による能力低下（衰微）は一切発生しない。** 旧モデルの円熟期・限界期の
  フィジカル衰微と、対応するバランス値（`MatureDecline*` / `LimitDecline*`）は削除した。
- **加入は18歳固定**（`MinCandidateAge` = `MaxCandidateAge` = 18）。
  年齢による能力差別化が無くなったため `YoungestAgePaBonus` は 0 とした。
- **26歳になった年度末で満期引退**（`RetirementAge` = 26）。18歳加入なら稼働期間は
  ちょうど8年＝384週（`MaxActiveWeeks`）になる。時間の刻みは従来どおり**週単位**を維持する。
- 稼働週数は `Adventurer.ActiveWeeks`、累積功績は `Adventurer.TotalContributionScore` に記録する。
- **退職金＝週給×12週＋累積功績×係数**（`SeveranceContributionCoefficient`）。
  支払いきれない場合も引退自体は成立させるが、マスターの機嫌が低下する
  （`SeveranceShortfallMoodPenalty`、−15。旧・名声低下、→ §8.1）。

**3. 冒険者は「戦死」しない（表現の統一）**

HPが0に達した冒険者は、アルベールの秘薬によって必ず一命を取り留める。ただし危険な目に
遭わせたことに激怒したマスターがギルド登録を強制抹消するため、二度と戻らない。

- **システム上の扱いは恒久的なロストであり、従来と変わらない**（現役ロースターから外れる）。
  変更したのはプレイヤーへの提示文言のみで、内部の識別子（`FallenAdventurers` 等）は据え置く。
- 現在、強制除籍は階層ボス（`DungeonResolver` の `ForceRetiredAdventurerIds`）でのみ発生する
  （旧通常クエストの致死判定は2026年9月に撤去）。

**4. 職業体系の7職拡張**

既存4職（Warrior/Ranger/Mage/Cleric）に、Knight（騎士）・Thief（盗賊）・
Scholar（学者）を追加した。詳細は §2.1・§4.2・§4.2.2。

- 成長重み（`growth_job_weights.csv`）は全7職業で合計9に統一。
- 配置（前衛/後衛）と配置補正倍率は新3職も既存職と同じ考え方で設定
  （騎士＝重戦士型、学者＝魔導士型、盗賊＝斥候型）。
- 装備制限（大剣・魔導士の杖・重装鎧・ローブ）を7職業対応に拡張。
- 学者はギミック解析役として大迷宮システム（下記5）と特に強く結び付く
  （ボスギミックの対策口の1つとして頻出、→ `Data.SampleData.CreateFloorBosses`）。

**5. 大迷宮（ダンジョン攻略システム）**

詳細は新設した §4.5（Core層のエンジン）・§9（UI）を参照。既存の通常クエスト
（討伐/探索/護衛）とは別枠の攻略対象として、全5フィールド（各100階層・
**10階ごとに階層ボス計10体、全5フィールドで計50体、2026年9月改訂**）・
情報解析率（IntelTier）・走破力による道中進軍・調査任務（低リスク・
致死判定なし）・ギミック対策付きのボス討伐（未対策は壊滅リスク）・
探索（採取、第3の任務）を実装した。中央ペインに専用タブ（`DungeonPanel.cs`）と
フィールドセレクターを追加している。

**6. アルベールの研究室（素材投資システム）**

詳細は新設した §4.6（Core層のエンジン）・§9（UI）を参照。探索（採取）で
集めた素材とゴールドを投じて、恒久的なインフラバフ（HP回復・解析率・
採取数・走破力）を獲得する二軸経済を実装した。中央ペインに専用タブ
（`ResearchPanel.cs`）を追加している。**素材は`materials.csv`（→ Balance.
MaterialBalance）でCSV管理し、研究レシピは`research.csv`で管理する
（2026年9月改訂、→ §0.4・§4.5.5・§4.6）。**

#### ギルドマスター連動システム構想（将来拡張 / post-MVP）
アルベールのキャラクター性（長命・マッドサイエンティスト・百合趣味）を軸とした、世代交代・育成・経済・演出の深化メカニクス。

1. **【魂魄定着（こんぱくていちゃく）の儀】（顧問制度の不可逆・全盛期固定モデル）**
   - **全盛期スナップショット**: 冒険者が引退・ピークに達した際の最高ステータス・スキルを記録。
   - **施設スロットへのバインド**: 現行の9施設（戦士訓練所・魔法研究所・作戦資料室等）の専用枠に魂を定着させ、永続バフを付与する。施設内には「全盛期の幻影」として常駐する。
   - **不可逆な交代（完全消滅・成仏）**: スロット数は限定的。次世代の魂を新たに定着させるには既存の魂を外す必要があり、外された魂は光となって完全消滅（永久ロスト）する。
   - ※実装時留意: 現行の `AdvisorSystem`（何度でも配置転換可能・消滅なし）からの改修・移行ルールを別途設計すること。

2. **【魂魄融和（こんぱくゆうわ）の秘薬】（女性同士の配合・継承）**
   - **秘薬と誕生**: 相性が最大値に達した女性冒険者ペアに秘薬を処方し、2人の素質・遺伝情報を掛け合わせた子供（新米冒険者）を誕生させる。
   - **培養による高速成長**: エルフの培養技術により短期間で18歳（即戦力、→ §2.4の加入年齢に統一）まで促成成長させる。
   - **百合相性（ニックス）と触媒**: アルベールの琴線に触れる属性・職種ペアほど「感情の爆発力」が高まり、能力限界突破児が生まれやすくなる。採取素材の投入で遺伝安定性・ボーナス値を底上げ可能。

3. **【観測日誌（アルベールズ・ノート）】（関係性可視化と創発ログ）**
   - **関係性タグ**: 同一部隊出撃や同室滞在により、冒険者間に「背中を預ける戦友」「憧れの先輩後輩」等のタグが付与される。
   - **戦闘ログへの割り込み**: 特別な関係にあるペアが出撃時、完全自動の戦闘解決ログ中に確率で特殊連携アクション（庇い・詠唱補助等）が演出として割り込む。

4. **【研究室への素材投資】（二軸経済インフラ）**
   - **ゴールドと素材の分離**: 維持費・装備用の「ゴールド」とは別に、採取任務で得た薬草・魔石・モンスター素材をアルベールへ納品して研究レベルを上げる。
   - **インフラバフ**: 秘薬の純度向上（初期能力上限UP）、医務室設備強化（負傷日数短縮）、試作薬レシピの閃きなど。
   - **基礎版はv2.0内で実装済み（→ §4.6。2026年9月改訂で素材・研究レシピをCSV化
     ＝候補Aとして確定、→ §0.4）**：4種の恒久バフ（HP回復・解析率・採取数・走破力）を
     即時実行のシンプルな研究として実装した。上記の「初期能力上限UP」「研究レベル」
     といったより深いインフラ育成要素は引き続きpost-MVPの構想として残る。

5. **【試作薬（ドーピング）の投与】（出撃前のハイリスク・ハイリターン）**
   - ボス戦等において、部隊に副作用付きの未認可薬を投与可能（例：筋力+100%だが帰還後に医務室送り確定、敏捷+50%だが知力激減でスキル使用不可など）。

6. **【ギルドマスター後方支援】（間接介入トリガー）**
   - 緊急退避の煙幕（即時帰還・負傷無効化・報酬破棄）や常備回復薬の投入。
   - ※実装時留意: `GuildManager.Core` は戦闘を一括全自動解決するアーキテクチャであるため、リアルタイム介入ではなく「出撃前の携行品・保険設定」または「UI再生時のイベントフック」としてCore層の純粋性を損なわない形で設計すること。

## 12. セーブ/ロード（新規）

- 保存形式：JSON。
- 保存タイミング：毎週の決算後に自動保存＋プレイヤーの任意操作による
  手動保存。
- セーブスロット：単一（1つのみ、常に上書き）。複数スロットは
  post-MVP（→ §11）。
- ロード失敗時（破損ファイル・バージョン不一致）は新規ゲームの
  みを提示し、既存セーブを保護する（プレイヤーが新規ゲームを
  選ぶまで上書きしない）。
- セーブフォーマットにはバージョン番号を持たせる。現時点では
  マイグレーション処理は未実装（バージョン不一致は単純にロード
  失敗として扱う）。将来的な仕様変更に備え、この番号は仕様変更の
  たびに更新することを検討する。
- 保存対象は、ギルドのスカラー値（週番号・所持金・マスターの機嫌・
  破産カウンタ・敗北理由・最終活動成果からの経過週数）、冒険者
  （現役・引退済み顧問候補・戦死者の3リスト全体）、相性、訓練施設への
  配置、施設Lv・建設キュー、顧問（教官・参謀・スカウト）の割り当て、
  受注可能クエスト一覧、派遣中（複数週）クエストの全て、永続パーティー
  編成（→ §4.0.2、v1.9改訂で追加）、大迷宮の5フィールド状態（開放状況・
  最高到達階層・各ボスの撃破状況とIntelRate、→ §4.5）、素材インベントリ
  （`GameState.Materials`、→ §4.5.5）、完了済み研究Id一覧
  （`GameState.CompletedResearchIds`、→ §4.6、v2.0内追加）、未鑑定遺物の在庫
  （`GameState.UnidentifiedItems`）とギルド保管庫の装備在庫（`GameState.Armory`、
  → §4.7、v2.0内追加）。装備カタログは
  静的コード定義のため保存対象外（保管庫の在庫・冒険者が装備している個体は、いずれも
  `EquipmentItem`＝個体Guid・カタログId・表示名・入手週・入手経路のみを保存する）。
- 冒険者の装備枠の保存形式（→ §4.2.2、2026年9月改訂）：`EquippedWeapon` ほか4枠に
  個体（`EquipmentItem`）をそのまま書き出す。派生値であるカタログId
  （`EquippedWeaponId` 等）は二重管理を避けるため書き出さない。改訂前のセーブが持つ
  旧キー（`"EquippedWeaponId":"IronSword"`）は、`Adventurer` のセット専用プロパティ
  （`LegacyEquippedWeaponId` ほか）がカタログ定義から個体を復元する。カタログから
  消えたIdは未装備として復元し、ロード自体は失敗させない。
  大迷宮フィールド拡張・素材・研究・遺物の4項目はいずれも新規追加フィールドのため、
  それらを持たない旧セーブでもロード自体は失敗しない：素材（`Materials`）・
  完了済み研究Id（`CompletedResearchIds`）・未鑑定遺物（`UnidentifiedItems`）・
  ギルド保管庫（`Armory`）は未定義キーがJSONデシリアライズの
  デフォルト値（空辞書／空集合／空リスト）で自然に補完される一方、大迷宮フィールド
  （`DungeonFields`）は単一ダンジョン時代の旧セーブだと空リストのまま復元される
  ため、`MainDashboard`側に明示的なフォールバック
  （`DungeonFields.Count == 0` なら `SampleData.CreateDefaultFields()` で補う）
  を置いている。
